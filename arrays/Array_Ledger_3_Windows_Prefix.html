Windows & Prefix Sums

These problems all maintain a window or a prefix-sum table over a subarray, counting or maximizing under constraints that arise from element identity (distinct values) or arithmetic (target sum, divisibility). The two techniques — sliding window and prefix sums — are distinguished by whether the constraint is monotone in window size.

Recognition rules

The judgment calls that separate these problems from each other. Every rule must be demonstrated by at least two entries on this page.

1

Monotonicity dictates the tool. A sliding window works if adding an element always makes a valid state strictly worse (or closer to invalid). If negative values or arbitrary divisibility exist, monotonicity breaks, so Subarray Sums II and Subarray Divisibility must use prefix sums instead.

2

CSES anti-hash tests mean unordered_map on plain integer keys will TLE. Playlist, Distinct Subarrays, Distinct Values Subarrays II, and Subarray Sums II all rely on std::map (or sorting where possible) to prevent worst-case hash collisions.

3

Counting all valid subarrays starting at tail is exactly head - tail + 1. Distinct Subarrays and Distinct Values Subarrays II accumulate this value at every outer step, whereas Playlist simply takes the max of this length.

4

Negative prefix sums require modulo fixing. Subarray Divisibility forces the use of (pre[i] % n + n) % n to map negative remainders back to positive ones. Normal sum constraints just lookup pre[i] - x.

5

Tracking the exact number of distinct elements in a map requires strict cleanups. In Distinct Values Subarrays II, when freq[v[t]] hits 0, it must be erased so freq.size() stays accurate. Playlist does not need this because it only checks freq[x] == 0.

1 · Duplicate-free window

Maintaining a two-pointer window where elements are distinct or bounded by a distinct count. The constraint is monotone in window size, allowing a greedy slide.

Playlist

O(n log n)
The ask
Find the longest contiguous subarray with all distinct elements.
Key observations
  1. Extending the window with a duplicate makes it invalid. This is monotonic, so two pointers work.
  2. Keep extending head as long as freq[a[head+1]] == 0.
  3. Record the maximum length head - tail + 1 at each valid state.
  4. When invalid, increment tail and decrement its frequency to make room.
Brute force → why it dies
naiveCheck all (i, j) pairs and use a set to verify distinctness.
costO(n³) or O(n²) with a running set.
dies atn = 2·10⁵
thereforeTwo-pointer sliding window with a frequency map.
Diagram
Implementation

Using std::map dodges CSES anti-hash tests.

arrays/Playlist.cppverbatim
// Problem: Playlist
// Link: CSES 1141
// Pattern: two-pointer window (tail/head), freq map keeps window duplicate-free
// Time: O(n log n)  Space: O(n)
//
// map (not unordered_map) to sidestep CSES's anti-hash test on plain int keys.
//
// Longest contiguous subsequence with no repeated song id.
//
// Example:
//     1 2 1 3 2 7 4 2 -> 5   (window: 1 3 2 7 4)

#include <iostream>
#include <vector>
#include <map>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<int> a(n);
    for (auto& x : a) cin >> x;

    map<int, int> freq;
    int tail = 0, head = -1;
    long long ans = 0;

    while (tail < n) {
        while (head + 1 < n && freq[a[head + 1]] == 0) {
            head++;
            freq[a[head]]++;
        }
        ans = max(ans, (long long)(head - tail + 1));

        if (tail > head) {
            tail++;
            head = tail - 1;
        } else {
            freq[a[tail]]--;
            tail++;
        }
    }

    cout << ans << '\n';
    return 0;
}
GotchaDo not use unordered_map, as malicious inputs will cause O(n²) hash collisions.
Recognize"longest contiguous subarray with distinct elements" → distinct-element window.

Distinct Subarrays

O(n log n)
The ask
Count the total number of subarrays where every element is distinct.
Key observations
  1. The same distinct-element window from Playlist is used.
  2. For any valid window spanning [tail, head], every subarray starting exactly at tail and ending anywhere up to head is also distinct.
  3. There are head - tail + 1 such subarrays starting at tail. Accumulating this directly counts all valid subarrays exactly once without combinatorial formulas.
Brute force → why it dies
naiveEnumerate all subarrays and check each for distinctness.
costO(n³)
dies atn = 2·10⁵
thereforeAccumulate window lengths during a two-pointer scan.
Diagram
Implementation

The core difference is ans += head - tail + 1.

// Problem: Distinct Subarrays (count)
// Link: CSES 2428
// Pattern: same duplicate-free window as Playlist, but accumulate
// head-tail+1 (subarrays starting at tail) every outer step instead of
// tracking the max
// Time: O(n log n)  Space: O(n)
//
// Count subarrays where every element is distinct.
//
// Example:
//     1 2 1 3 -> 8

#include <iostream>
#include <vector>
#include <map>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<int> a(n);
    for (auto& v : a) cin >> v;

    map<int, int> freq;
    int tail = 0, head = -1;
    long long ans = 0;

    while (tail < n) {
        while (head + 1 < n && freq[a[head + 1]] == 0) {
            head++;
            freq[a[head]]++;
        }
        ans += head - tail + 1;

        if (tail > head) {
            tail++;
            head = tail - 1;
        } else {
            freq[a[tail]]--;
            tail++;
        }
    }

    cout << ans << '\n';
    return 0;
}
GotchaCount only subarrays starting at tail. Using a combinatorics formula leads to double-counting overlap regions.
Recognize"count total subarrays with distinct elements" → accumulate length of duplicate-free window.

Distinct Values Subarrays II

O(n log n)
The ask
Count the number of subarrays that have at most k distinct values.
Key observations
  1. Extending a window can only increase or maintain the number of distinct elements, which is monotonic.
  2. We can safely absorb v[h+1] if freq.size() < k OR if it's already in the window.
  3. To rely on freq.size(), keys with a zero count must be erased, not just decremented.
Brute force → why it dies
naiveEnumerate subarrays and count distinct elements using a set.
costO(n²)
dies atn = 2·10⁵
thereforeWindow accumulation with exact freq size tracking.
Diagram
Implementation

Note the strict freq.erase(v[t]) when count hits zero.

2 · Prefix + map

When constraints involve negative numbers or divisibility, monotonicity breaks down (the sum can go up and down). Two pointers die. Prefix sums mapped by frequency solve this by tracking what was seen.

Subarray Sums II

O(n log n)
The ask
Count the number of subarrays having sum exactly x. Elements can be negative.
Key observations
  1. Negative numbers mean the sum goes down. Two pointers cannot reliably expand/contract.
  2. A subarray v[l..r] summing to x means pre[r] - pre[l-1] = x.
  3. Rearranging gives pre[l-1] = pre[r] - x. We just look up how many times we've seen this target prefix.
Brute force → why it dies
naiveEnumerate all pairs and sum them.
costO(n²)
dies atn = 2·10⁵
thereforeSingle pass with a prefix frequency map.
Diagram
Implementation

Keep pre[0] = 0 to naturally handle prefixes starting at the first element.

Subarray Divisibility

O(n)
The ask
Count the number of subarrays whose sum is divisible by n.
Key observations
  1. pre[r] - pre[l-1] ≡ 0 (mod n) reduces to pre[r] ≡ pre[l-1] (mod n).
  2. Two prefixes with the same remainder modulo n form a divisible subarray.
  3. Negative numbers cause negative remainders in C++. Fix with (pre[i] % n + n) % n.
Brute force → why it dies
naiveEnumerate all pairs.
costO(n²)
dies atn = 2·10⁵
thereforePrefix modulo frequency map.
Diagram
Implementation

Since remainders are exactly 0..n-1, a direct vector<ll> freq(n) provides O(n) lookup without maps.

3 · Positive-only window

When elements are strictly positive, the sum is monotonically increasing with length, allowing us to safely slide a two-pointer window.

Subarray Sums I

O(n)
The ask
Count the number of subarrays having sum exactly x. Elements are strictly POSITIVE.
Key observations
  1. Because elements are positive, extending the window strictly increases the sum. Monotonicity holds.
  2. We extend while sum + v[h+1] ≤ x.
  3. If the sum hits x exactly, it is counted.
Brute force → why it dies
naiveEnumerate pairs.
costO(n²)
dies atn = 2·10⁵
thereforeTwo-pointer window.
Diagram
Implementation

The O(n) two-pointer is lighter than a prefix map since it requires no hash lookups.

#include <bits/stdc++.h>

#define ll long long 
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353
#define INF 1e18
#define mp make_pair
#define PI acos(-1) 
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
void solve() 
{
    ll n ; 
    cin >> n ;
    ll x ; 
    cin >> x ;
    vector < ll > v(n) ;
    for (ll i = 0 ; i < n ; i++)
    {
        cin >> v[i] ;
    }
    ll  t = 0 , h = -1 , sum = 0 , ans = 0 ;
    while(t < n)
    {
        while(h + 1 < n && sum + v[h + 1] <= x)
        {
            h++ ;
            sum += v[h] ;
        }
        if(sum == x)
        {
            ans++ ;
        }
        if (  t > h )
        {
            h = t - 1 ;
            t++ ; 
        }
        else
        {
            sum -= v[t] ;
            t++ ;
        }
    }
    cout << ans << endl ;
    
   






}
