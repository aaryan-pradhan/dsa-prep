Recognition rules

The judgment calls that separate these problems from each other.

1

n ≤ 20 and the question is "best over all subsets" → recurse take/skip, no DP needed: Apple Division. n ≤ 8 and the question is "count the valid placements" → recurse one row at a time: Chessboard and Queens.

2

"Print all … in alphabetical order" → sort, then next_permutation. It skips duplicates for free, so no set: Creating Strings.

3

Output length is 2ⁿ or 2ⁿ−1 → the answer is a recursion on the output, not a search: Gray Code, Tower of Hanoi. Build the list for n−1, then glue.

4

"Print YES/NO, and an example if YES", n up to 10⁹ or t up to 10⁵ → there is a closed-form feasibility test. Find it first, construct second: Coin Piles, Raab Game I.

5

Rearrange characters under a symmetry constraint → count characters, check the parity condition, emit greedily: Palindrome Reorder.

1 · Exhaustive recursion

The constraint is tiny on purpose. Enumerate every choice, score the leaf, keep the best or the count. The only design question is what to carry down the recursion and what to recompute at the bottom.

Apple Division

O(2ⁿ·n)
The ask
Split n weights into two groups with the smallest possible difference of sums.
minT ⊆ {1…n} |S − 2·∑i∈T pᵢ|, where S = ∑ pᵢ
Key observations
  1. Choosing group 1 fixes group 2. So the search space is subsets, not ordered pairs — 2ⁿ, and each split is generated twice (T and its complement), which costs nothing.
  2. n ≤ 20 ⇒ 2²⁰ ≈ 10⁶ leaves. Free.
  3. Sums reach 20 · 10⁹ = 2·10¹⁰ ⇒ ll, not int.
  4. The bitmask is only a carrier. This same recursion works with two running sums passed down; the mask version just re-reads them at the leaf.
Brute force → why it dies
naiveEnumerate all 2ⁿ subsets — which is what this is.
costO(2ⁿ·n) here, because the leaf re-sums the mask.
dies atnothing. n ≤ 20 → 2·10⁷ operations.
thereforeAccept the extra factor n. Carrying two running sums would give O(2ⁿ), and is the version to write if n were 30.
Implementation

rec takes index i and the mask of everything chosen so far. Both branches are unconditional; the work happens only at i == n. ans starts at INF.

Chessboard and Queens

O(8! · 8)
The ask
Count placements of 8 non-attacking queens on an 8×8 board where some squares are forbidden.
#{c₀…c₇ : cᵢ free, cᵢ ≠ cⱼ, |cᵢ − cⱼ| ≠ |i − j|}
Key observations
  1. Exactly one queen per row. That is forced, not a choice: 8 queens, 8 rows, no two in a row. So the recursion is over rows, and only the column is picked.
  2. Because rows are filled top-down, only squares above the current row can conflict. check looks up the column and the two upward diagonals and nothing else.
  3. A reserved square blocks placement but not attacks. So it is a test on v[row][col] only — it never appears in check.
  4. Marking reserved squares as 2 and queens as 1 keeps the two meanings in one grid, and check compares against 1.
Brute force → why it dies
naiveChoose 8 of the 64 squares, test each combination.
costC(64,8) ≈ 4·10⁹ combinations, each checked in 8².
dies atthe 1 s limit, by three orders of magnitude.
thereforeOne queen per row prunes it to at most 8⁸ = 1.6·10⁷ paths, and conflicts cut that to well under 8!.
Diagram
Implementation

rec(row) returns the count for rows row..7 instead of mutating a global, so the base case is a plain return 1. Place, recurse, unplace.

Creating Strings

O(n!·n)
The ask
Print every distinct rearrangement of a string, in alphabetical order, preceded by the count.
sorted set of all permutations of s, |set| = n! / ∏c cnt[c]!
Key observations
  1. next_permutation walks permutations in lexicographic order and skips duplicates automatically. It returns false once the sequence is the last (descending) one.
  2. Therefore the string must be sorted first, so the walk starts at the smallest arrangement and covers all of them.
  3. A do … while, not a while: the sorted string itself is the first answer and must be emitted before any call.
  4. The count is required before the strings, so they have to be buffered in a vector rather than printed as they are produced.
Brute force → why it dies
naiveRecurse over positions, insert every produced string into a set<string> to deduplicate.
costO(n! · n log(n!)) plus the memory of all n! strings, duplicates included.
dies atit survives n ≤ 8 (8! = 40320) — but it is strictly more code.
thereforeUse the stdlib walk: sorted order and deduplication both come free.
Implementation

Four lines of logic. The vector exists only because the count has to be printed first.

2 · Recursive construction

The output itself is defined by a recurrence. Solve for n−1, then describe the n case as two copies of it with something glued between or in front. No search, no pruning — every step of the answer is forced.

Gray Code

O(n·2ⁿ)
The ask
List all 2ⁿ bit strings of length n so that consecutive strings differ in exactly one bit.
hamming(gᵢ, gᵢ₊₁) = 1 for all i
Key observations
  1. Take a valid list for n−1. Prefix every entry with 0; then prefix the same list reversed with 1.
  2. Inside each half the prefix is constant, so neighbours still differ in one bit — the n−1 property carries over.
  3. At the seam the two entries are the last of the first half and the last of the second half's source, i.e. the same (n−1)-string. They differ only in the prefix. That is why the second half is reversed.
  4. Base case {"0", "1"} is n = 1, so the loop starts at i = 2.
Brute force → why it dies
naiveBacktrack over the 2ⁿ codes, at each step trying every unused string at Hamming distance 1.
costexponential with backtracking, and needs a visited set of size 2ⁿ.
dies atn ≤ 16 → 65536 codes; the search is survivable but pointless.
thereforeThe reflect-and-prefix recurrence produces the list directly, with no search at all.
Diagram
Implementation

Iterative rather than recursive: v holds the (i−1)-bit list and is rebuilt into temp each round. The second loop runs downwards, which is the reflection.

Tower of Hanoi

O(2ⁿ)
The ask
Print the shortest move sequence that transfers n disks from stack 1 to stack 3, never placing a larger disk on a smaller one.
k = 2ⁿ − 1 moves, each printed as "from to"
Key observations
  1. The bottom disk can only move once the other n−1 are all on the spare stack. That single fact forces the whole recurrence.
  2. So: move n−1 from → aux (using to as spare), move disk n from → to, move n−1 aux → to (using from as spare).
  3. The roles of the three stacks rotate at each call. Getting the argument order right in the two recursive calls is the problem.
  4. T(n) = 2T(n−1) + 1 = 2ⁿ − 1, and that is optimal, so no minimisation is needed — just print.
Brute force → why it dies
naiveBFS over board states to find the shortest path to the goal.
cost3ⁿ states → 4·10⁷ at n = 16, each with a stack-configuration key.
dies atmemory, well before time.
thereforeThe optimum is known in closed form; emit it directly in O(2ⁿ), which is the output size.
Diagram
Implementation

Moves are collected into a global vector<pll> because the count must be printed before them. Parameter order is (nod, from, aux, to).

3 · Constructive answers

A feasibility question with a witness attached. The constraints rule out search entirely, so the work is finding the exact condition, then writing down one example that meets it. If the condition is right, the construction is usually three lines.

Coin Piles

O(1)
The ask
Two piles of a and b coins. Each move removes (1,2) or (2,1). Can both piles reach zero?
∃ x,y ≥ 0 : x + 2y = a and 2x + y = b
Key observations
  1. Every move removes exactly 3 coins in total ⇒ (a + b) % 3 == 0 is necessary.
  2. Solving the system gives x = (2b − a)/3 and y = (2a − b)/3. Both must be ≥ 0, which is exactly 2·min(a,b) ≥ max(a,b).
  3. Given divisibility by 3, that inequality is also sufficient — the two conditions together are the full answer.
  4. a = b = 0 passes both and is correct (zero moves).
Brute force → why it dies
naiveSearch over the number of each move type, or BFS the state (a, b).
costO(a) per test at best, O(a·b) for BFS.
dies ata,b ≤ 10⁹ with t ≤ 10⁵ → 10¹⁴.
thereforeSolve the 2×2 system once, on paper. Both conditions are O(1).
Implementation

One if. The whole derivation lives in the condition.

Raab Game I

O(n)
The ask
Both players hold cards 1…n and play them in some order. Given n, a, b, produce two orderings where player 1 wins exactly a rounds and player 2 exactly b.
#{i : pᵢ > qᵢ} = a, #{i : qᵢ > pᵢ} = b, ties elsewhere
Key observations
  1. a + b ≤ n, because each round produces at most one point.
  2. If exactly one of a, b is zero it is impossible: some card of the winner must beat something, and the multiset is identical on both sides, so a total win-shutout forces all ties, i.e. a = b = 0.
  3. Otherwise construct directly: leave n − a − b rounds as ties (same card both sides), and arrange the rest as a cyclic shift.
  4. The construction pairs i ↔ a+i for the first b rounds (player 2 wins) and b+i ↔ i for the next a rounds (player 1 wins). Every card 1…n appears exactly once on each side.
Brute force → why it dies
naiveTry permutations of player 2's hand against player 1's identity ordering.
costO(n!).
dies atn ≤ 100, t ≤ 1000. Instantly.
thereforeProve the two impossibility rules, then emit one witness in O(n).
Diagram
Implementation

One pass over i = 1…n choosing which of the three regions i falls in. The inline comments record the index arithmetic for each region.

void solve() 
{
    ll n ; 
    ll a , b ;
    cin >> n >> a >> b ;
    if(a + b > n)
    {
        pn ;
        return ;
    }
    if(a == 0 && b > 0)
    {
        pn ;
        return ;
    }
    if(b == 0 && a > 0)
    {
        pn ;
        return ;
    }
    vector < ll > v1 , v2 ;
    for(ll i = 1 ; i <= n ; i++)
    {
        if(i <= b)
        {
            v2.push_back(a + i ) ; 
            v1.push_back(i)  ;

            // b - 1 + 1 
            // 1 , a + 1 
            // 2 , a + 2
            // ..
            // b , a + b

            v1.push_back(i) ;

            // a + b - b - 1 + 1 
            // b + 1 , 1
            // b + 2 , 2
            // .. 
            // b + a , a
        }
        else
        {
            v1.push_back(i) ; 
            v2.push_back(i) ; 
            
        }
    }
    py ;

    {
        cout << x << " " ; 
    }
    cout << endl ;
    for(auto& x : v2)
    {
        cout << x << " " ;
    }
    cout << endl ;
   

}

Palindrome Reorder

O(n + 26)
The ask
Rearrange the letters of a string into any palindrome, or report that none exists.
possible ⇔ #{c : cnt[c] odd} ≤ 1
Key observations
  1. A palindrome pairs position i with n−1−i. Every character except a possible middle one appears an even number of times.
  2. So the whole feasibility test is: at most one letter has an odd count.
  3. Construction: put the odd letter (if any) in the middle, then for each letter push half its pairs to the front and half to the back. A deque makes that literal.
  4. Only the 26 counts matter — the original order is irrelevant.
Brute force → why it dies
naiveGenerate permutations and test each for the palindrome property.
costO(n!·n).
dies atn ≤ 10⁶. Hopeless past n = 10.
thereforeCount the 26 letters, check one parity condition, emit greedily in O(n).
Implementation

The deque is built outward-in: the odd letter is seeded first, then each pair is pushed to both ends at once, so the result is symmetric by construction.

arrays/Palindrome_Reorder.cppverbatim
// orz
#include <bits/stdc++.h>

#define ll long long 
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353
#define INF 1e18
#define mp make_pair
#define PI acos(-1) 
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
void solve() 
{

   string s ; 
   cin >> s ;
   ll n = s.size() ;
   vector < ll > v(26, 0) ;
   for(ll i = 0 ; i < n ; i++)
   {
        v[s[i] - 'A']++ ;
   }
   ll odd = 0 , index = -1  ; 
   for(ll i = 0 ; i < 26 ; i++)
   {
        if(v[i] % 2 == 1)
        {
            odd++ ;
            index = i ;
        }
   }
   if(odd > 1)
   {
        cout << "NO SOLUTION" << endl ;
        return ;
   }
   deque < char > dq ;
   if(index != -1)
   {
        dq.push_back('A' + index) ;
   }
   v[index]-- ;
   for(ll i = 0 ; i < 26 ; i++)
   {
        while(v[i] > 0)
        {
            dq.push_front('A' + i) ;
            dq.push_back('A' + i) ;
            v[i] -= 2 ;
        }
   }
   for(auto& x : dq)
   {
        cout << x ;
   }
   cout << endl ;

}

{

    ios_base::sync_with_stdio(false);
    cin.tie(0);
    cout.tie(0);
 
    solve() ; 
}
Gotchav[index]-- runs even when index == -1 — on a string with no odd letter that writes to v[-1]. It happens to be harmless on this input (a vector index one before the data), but it is out-of-bounds and should be inside the if.
Recognize"rearrange into a palindrome" → count characters, test odd-count ≤ 1, build from both ends.
