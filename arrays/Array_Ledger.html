Recognition rules

The cross-cutting judgment calls that separate one family from another — grounded in the actual problems above, not generic textbook advice.

01

This repo standardizes on the segment tree over Fenwick/BIT for point-update + range-query problems — one structure covers everything a BIT does plus arbitrary range merges. Dynamic Range Sum Queries, Dynamic Range Minimum Queries, and Josephus Queries all reuse the identical build/update/query scaffold, swapping only merge and the identity value. A static, sum-only array doesn't need the tree at all — Static Range Sum Queries collapses to O(1) prefix sums, since sum has a clean inverse (subtraction). Static Range Minimum Queries still needs the tree's query (no update) because min has no inverse — you can't "un-min" a removed element the way you can subtract it back out of a sum.

02

A container needs to be multiset, not set, whenever the values it holds are logically distinct entities that can legitimately collide — Tower of Cubes' pile-top values (two towers can share a top height) and Traffic Lights' gap lengths (two gaps can share a length). Corollary from Traffic Lights: erase the *one* instance that changed via s.erase(s.find(x)), never s.erase(x) — the value form deletes every matching entry, not just the one that broke.

03

unordered_set/unordered_map on plain integer keys is CSES-unsafe — an anti-hash test forces every key into one bucket, degrading every op to O(n). Distinct Values switched to sort + adjacent-run scan after TLEing; Playlist and Distinct Subarrays use map instead of unordered_map for the same reason. Default to sort or an ordered container on judge-facing code with int/ll keys.

04

Similarly-named problems can hide completely different data shapes: Distinct Subarrays (contiguous — two-pointer window) vs. Distinct Subsequences (order/contiguity irrelevant — per-value combinatorics, Π(freq+1)) look nearly identical by title but need unrelated techniques. Check "does this need to be contiguous?" before reaching for a sliding window.

05

A +1/−1 event sweep answers "max concurrently active" (Restaurant Customers); a sort-and-merge sweep over the same kind of interval list answers "total distinct coverage" (Union of Painted Bricks) — same input shape, different aggregate needs a different sweep. In the concurrency version the running total is always 0 at the end, so the answer must be captured mid-sweep (best = max(best, running)), never read off the final state.

06

Nested Ranges Check and Nested Ranges Count reuse the identical sort-by-left-ascending/right-descending + running-max/min-of-r two-pass sweep, differing only in whether the inner test sets a boolean flag or increments a counter. Recognize the sort-then-track-extreme-so-far shape once and both "does X contain something" and "how many things does X contain" fall out of the same scaffold.

07

When the answer only depends on the sign of a running total, not its magnitude, a greedy prefix-drop loop replaces recomputation from scratch: Reducing Dishes' ans -= total; total -= a[start] works because the popped element's own value cancels out of the delta entirely. Missing Coin Sum's x > R+1 check is the same shape in reverse — one failed comparison ends the loop with no backtracking needed.

08

A position array (pos[value] = index) turns "does value v come before/after v+1 in the array" into an O(1) lookup instead of a scan. Collecting Numbers builds it once; Collecting Numbers II maintains it under swaps by touching only the ≤4 edges that could possibly flip ({u, u+1, v, v+1}, deduped via std::set) — subtract each edge's old status before the swap, add back the new status after, never recompute the whole count per update.

build(id,l,r)recursively fills leaves from arr[], internal nodes via merge of children — O(n)
update(id,l,r,pos,val)point-set (not add) at pos, re-merge on the way back up — O(log n)
query(id,l,r,lq,rq)range query; returns the identity node on no-overlap, the stored node on full containment, else merges both halves — O(log n)

1 · Single-pass running-state tricks

O(n), no auxiliary structure — a single scalar (or two) carried forward across one left-to-right pass. The entire difficulty is picking exactly which running value to track and how to seed it.

Maximum Subarray Sum

O(n)

Maximum sum of a contiguous, nonempty subarray (Kadane's).

state
cur = best sum of a subarray ending here
recurrence
cur = max(x[i], cur + x[i])
base
cur = best = x[0]
long long cur = x[0], best = x[0];
for (int i = 1; i < n; i++) {
  cur = max(x[i], cur + x[i]);
  best = max(best, cur);
}
Gotchaseed both cur and best with x[0], not 0 — the subarray must be nonempty, so an all-negative array must return its least-negative single element, not 0. best is tracked separately from cur since the optimal subarray need not end at the last index.
Recognize"max sum of a contiguous subarray" → extend-or-restart running sum, Kadane's.

Maximum Difference

O(n)

Pick i < j maximizing arr[j] − arr[i].

state
minSoFar = min of everything strictly before j
recurrence
ans = max(ans, arr[j] − minSoFar)
base
minSoFar=arr[0], ans=arr[1]−arr[0], loop from i=1
int minSoFar = arr[0], maxDiff = arr[1] - arr[0];
for (int i = 1; i < (int)arr.size(); i++) {
  maxDiff = max(maxDiff, arr[i] - minSoFar);
  minSoFar = min(minSoFar, arr[i]);
}
Gotchanot "global max − global min" — that ignores i<j ([5,1] gives global 5−1=4 but the only valid pair is 1−5=−4). Loop must start at i=1 with minSoFar=arr[0] already seeded — starting at i=0 lets index 0 pair with itself, inflating the answer to 0 on a strictly decreasing array.
Recognize"best pair with an ordering constraint (i<j)" → running extremum of the prefix, not a global extremum.

Increasing Array

O(n)

Only move: increase any element by 1. Minimum total moves to make the array non-decreasing.

state
prev = running floor (post-adjustment)
recurrence
x<prev: cost+=prev−x; else prev=x
base
prev=0, cost=0
long long prev = 0, cost = 0;
for (int i = 0; i < n; i++) {
  long long x; cin >> x;
  if (x < prev) cost += prev - x;
  else prev = x;
}
Gotchacompare against the running prev (after bumps already applied), never the original array's previous value — a bumped element raises the floor for everything after it. Accumulate cost in long long: n up to 2×10⁵ with per-step diffs up to ~10⁵ can overflow int.
Recognize"only-increase moves to enforce non-decreasing" → running floor, pay the shortfall, never lower the floor.

2 · Sort + two-pointer greedy matching

Sort once, then sweep with a pointer from each side (or each array) instead of checking every element against every other. The extreme element is always resolved at each step, which is what keeps this O(n) after the sort.

Ferris Wheel

O(n log n)

Gondola holds 1 or 2, weight cap x per gondola — minimum gondolas for n children.

state
i=lightest unmatched, j=heaviest unmatched
recurrence
p[i]+p[j]≤x: pair, i++; always j−−, count++
base
i=0, j=n−1, count=0
sort(p.begin(), p.end());
int i = 0, j = n - 1, count = 0;
while (i <= j) {
  if (p[i] + p[j] <= x) i++;
  j--; count++;
}
Gotchaj always decrements and count always increments once per step regardless of whether a pair formed — the current heaviest is always resolved this step, either paired or sent alone. i==j (one child left) still resolves correctly with no special-casing.
Recognize"minimize pair/group count under a per-pair capacity" → sort, converge two pointers from both ends.

Apartments

O(n log n+m log m)

n applicants each want size in [ai−k, ai+k], m apartments of fixed size — maximize distinct matches.

state
i over sorted applicants, j over sorted apartments
recurrence
b[j]<a[i]−k: j++; b[j]>a[i]+k: i++; else match, i++,j++
sort(a.begin(),a.end()); sort(b.begin(),b.end());
int i=0,j=0,count=0;
while (i<n && j<m) {
  if (b[j] < a[i]-k) j++;
  else if (b[j] > a[i]+k) i++;
  else { count++; i++; j++; }
}
Gotchaa binary-search-per-applicant check ("does some apartment fit?") isn't sufficient — apartments can't be reused, so a matched one must be consumed. The two discard branches rely on both arrays being sorted ascending: an apartment too small for the current applicant is too small for every later (larger) applicant too.
Recognize"match two groups under a per-pair tolerance, each side used at most once" → sort both, one pointer per side, three-way branch.

3 · Sort + single-pass greedy

Sort once, then a single forward pass with a running scalar (median, achievable range, prefix total) decides the answer directly — no second pointer needed, unlike family 2.

Stick Lengths

O(n log n)

Minimum total cost (|new−old| per stick) to make all sticks equal length.

state
target = median after sorting
recurrence
cost = ∑|pi − median|
sort(p.begin(), p.end());
long long median = p[n / 2];
long long cost = 0;
for (int i = 0; i < n; i++) cost += abs(p[i] - median);
Gotcha∑|pi−m| is minimized at the median, provable by pairing smallest with largest post-sort — each pair forces m into a shrinking interval whose intersection is the median. p[n/2] works for both parities (any point in the tie range gives the same cost when n is even), so no averaging needed.
Recognize"minimize sum of absolute deviations to a single target" → the target is the median, not the mean.

Missing Coin Sum

O(n log n)

Smallest positive sum not formable as a subset sum of the given coins.

invariant
every sum in [0,R] is achievable so far
recurrence
x≤R+1: R+=x; else stop, answer=R+1
sort(x.begin(), x.end());
long long r = 0;
for (int i = 0; i < n; i++) {
  if (x[i] > r + 1) break;
  r += x[i];
}
cout << r + 1;
Gotchax==R+1 still extends the range (closes the gap exactly) — the break condition is strict >. The first coin that fails proves R+1 unreachable forever: every later coin is sorted larger and only widens the gap, so stop immediately rather than scanning the rest.
Recognize"smallest unreachable subset sum" → sort ascending, greedily extend a contiguous achievable-sum range.

Reducing Dishes

O(n log n)

Pick a subset + cooking order; k-th cooked dish scores k×satisfaction[i]. Maximize total.

state
ans=∑(i+1)a[i], T=∑a[i] over sorted array
recurrence
while T<0: ans−=T; T−=a[start]; start++
sort(a.begin(), a.end());
long long ans=0, total=0;
for (int i=0;i<n;i++){ ans+=(long long)(i+1)*a[i]; total+=a[i]; }
int start=0;
while (start<n && total<0) { ans-=total; total-=a[start]; start++; }
Gotchafull inclusion isn't always optimal ([-2,0,-2,3]: including everything gives 6, dropping one −2 gives 7). Popping the smallest changes the answer by exactly −T — the popped value's own magnitude cancels out entirely, so the decision to pop depends only on the sign of T, never on which value is popped.
Recognize"assign increasing weights to a chosen subset, any element droppable" → sort ascending, pop the front while the running total is negative.

4 · Parity-based construction

Split the array by parity of value or position; each half is either free to sort independently or forms two independently-safe output runs.

Beautiful Permutation

O(n)

Print a permutation of 1..n with no two adjacent elements differing by exactly 1, or "NO SOLUTION".

construction
all evens ascending, then all odds ascending
impossible
n==2 or n==3 only
if (n == 2 || n == 3) { cout << "NO SOLUTION\n"; return 0; }
for (int i = 2; i <= n; i += 2) cout << i << ' ';
for (int i = 1; i <= n; i += 2) cout << i << ' ';
Gotchan==1 is trivially fine despite looking like a small-n edge case (no adjacent pair exists to violate anything) — only n==2 and n==3 are truly impossible, verified by exhausting every arrangement by hand. Within each half, consecutive printed values differ by 2 (never 1); at the even→odd boundary the gap (largest even to 1) stays safely >1 once n≥4.
Recognize"permutation avoiding adjacent difference of exactly 1" → split by parity, each half internally safe, check the boundary once.

Parity Constrained Sort

O(n log n)

Only same-parity elements may be swapped. Output the array closest to non-decreasing achievable under that constraint.

invariant
positions' parity class is fixed; values within a class are freely permutable
recurrence
bucket by a[i]%2, sort each bucket, re-check parity to re-merge
sort(evens.begin(), evens.end());
sort(odds.begin(), odds.end());
int ei = 0, oi = 0;
for (int i = 0; i < n; i++)
  a[i] = (a[i] % 2 == 0) ? evens[ei++] : odds[oi++];
Gotchathe second pass re-evaluates a[i]%2 on the array being overwritten in place — it still reads correctly because the parity of the value about to be placed there matches the parity of the value being replaced (same bucket), so a stored-position/index approach is unnecessary overhead, not a correctness requirement.
Recognize"swaps restricted to elements sharing a predicate" → positions per predicate class are fixed, sort within each class, cross-class inversions are unavoidable and ignorable.

5 · Position-array incremental invariant

A break/round count derived from pos[value] comparisons, first computed once, then maintained under localized updates by touching only the handful of entries that could possibly change.

Collecting Numbers

O(n)

Repeatedly sweep left-to-right collecting 1..n in increasing order, as far as contiguity allows each round — count rounds.

state
pos[v] = index of value v in the array
recurrence
rounds = 1 + ∑i=2..n[pos[i]<pos[i−1]]
vector<int> pos(n + 1);
for (int i = 1; i <= n; i++) { int x; cin>>x; pos[x] = i; }
int rounds = 1;
for (int i = 2; i <= n; i++)
  if (pos[i] < pos[i - 1]) rounds++;
Gotchavalues i−1 and i are collectible in the same round iff pos[i−1] < pos[i] — i appears strictly later in the array. It's a break check on value order via position, not a check on array order directly.
Recognize"count sweep rounds to collect values in increasing order" → build pos[], count breaks where pos[i]<pos[i−1].

Collecting Numbers II

O((n+m) log n)

Same rounds formula, but m swaps of array positions are applied one at a time — report rounds after each.

state
breaks maintained incrementally, not recomputed
recurrence
edges={u,u+1,v,v+1}: subtract old, swap pos[], add new
set<int> edges;
for (int w : {u, v}) {
  if (w >= 2) edges.insert(w);
  if (w + 1 <= n) edges.insert(w + 1);
}
for (int k : edges) breaks -= isBad(k);
swap(pos[u], pos[v]); swap(x[a], x[b]);
for (int k : edges) breaks += isBad(k);
Gotchaa, b in a query are array positions, not values — the values that actually move are u=x[a], v=x[b], and only pos[u], pos[v] change. Exactly ≤4 edges can flip (deduped via std::set since u,v close in value can overlap); must subtract old status before the swap and add new status after — recomputing "after" without first undoing "before" double-counts.
Recognize"maintain a derived count under localized updates" → identify the small fixed-size neighborhood of conditions a changed value can affect, update just those.

6 · Duplicate-free window (two-pointer)

Same tail/head mechanics and freq map in both problems — the only difference is whether the outer loop tracks a max or accumulates a sum, which is exactly rule 04's warning made concrete.

Playlist

O(n log n)

Longest contiguous subsequence with no repeated element.

state
[tail,head] window, freq map of window contents
recurrence
ans = max(ans, head−tail+1)
while (head+1 < n && freq[a[head+1]]==0) { head++; freq[a[head]]++; }
ans = max(ans, (long long)(head - tail + 1));
if (tail > head) { tail++; head = tail-1; }
else { freq[a[tail]]--; tail++; }
Gotchamap, not unordered_map — CSES's anti-hash test targets plain-int unordered containers (see rule 03). The shrink step (freq[a[tail]]--; tail++) is what makes room for the next repeat once head can't extend further.
Recognize"longest contiguous run with no repeats" → two-pointer window, track a running max, not a sum.

Distinct Subarrays

O(n log n)

Count subarrays where every element is distinct.

state
identical window mechanics to Playlist
recurrence
ans += head−tail+1 (every outer step)
while (head+1 < n && freq[a[head+1]]==0) { head++; freq[a[head]]++; }
ans += head - tail + 1;
if (tail > head) { tail++; head = tail-1; }
else { freq[a[tail]]--; tail++; }
Gotchathe only change from Playlist is ans += ... instead of ans = max(ans, ...) — this counts every valid subarray starting at the current tail (right endpoint anywhere from tail to the maximal head), and summing over every tail value (each visited exactly once) covers every valid subarray exactly once. Don't reach for a combinatorial nC2 formula here — it's a fixed-one-endpoint count, not a choose-k problem.
Recognize"count (not find longest) contiguous no-repeat subarrays" → same window, accumulate instead of max.

7 · Per-value frequency counting

Position/contiguity is irrelevant here — both problems reduce to a per-distinct-value count, computed once with no window at all. Deliberately paired with family 6 by rule 04's naming trap.

Distinct Values

O(n log n)

Count distinct values in a list of n integers.

technique
sort, count runs of adjacent-unequal values
sort(x.begin(), x.end());
int distinct = n > 0 ? 1 : 0;
for (int i = 1; i < n; i++)
  if (x[i] != x[i - 1]) distinct++;
Gotchafirst attempt used unordered_set and TLE'd on CSES's final (anti-hash) test case — see rule 03. Sort + adjacent-scan is immune to adversarial input at the same O(n log n).
Recognize"count distinct elements, judge-facing" → sort + run-count, not a hash set.

Distinct Subsequences

O(n log n)

Count subsequences (order/contiguity irrelevant) where every element is distinct, mod 1e9+7.

state
freq[v] = occurrence count of value v
recurrence
ans = Π(freq[v]+1) − 1 (mod p)
ll ans = 1;
for (auto& [val, f] : freq) ans = mmul(ans, f + 1);
ans = mcorr(msub(ans, 1));
Gotchaa value's real option set per subsequence is f+1 (exclude, or include exactly one of its f occurrences) — never 2^f, which would treat occurrences as independent bits and allow more than one "on" at once, an invalid state for a distinct subsequence. The final −1 removes the all-excluded (empty) subsequence that the product otherwise counts.
Recognize"count subsequences with all-distinct elements, non-contiguous" → per-value (f+1) option counting, independent across values — not a window technique (contrast Distinct Subarrays).

8 · Interval sweep & containment

All four sort a list of intervals first, then sweep once tracking a running extremum (concurrency count, merged block, or max/min endpoint seen). The same input shape answers four different questions depending on which extremum is tracked.

Restaurant Customers

O(n log n)

n (arrival, leaving) intervals — find the max number simultaneously present.

technique
split into ±1 timestamped events, sort, sweep
recurrence
running += delta; best = max(best, running)
events.push_back({a, 1});
events.push_back({b, -1});
sort(events.begin(), events.end());
int running = 0, best = 0;
for (auto& [time, delta] : events) {
  running += delta;
  best = max(best, running);
}
Gotchathe running total is always 0 at the very end — the answer must be captured mid-sweep via a separate best, never read off the final state. Arrival/leaving times are guaranteed distinct here, so no tie-break is needed between a same-instant arrival and departure.
Recognize"max number of intervals simultaneously active" → ±1 event sweep, not raw interval comparison.

Union of Painted Bricks

O(n log n)

N intervals paint ranges of up-to-1e9 bricks (repaint is a no-op) — count total distinct bricks painted.

state
open block (curL, curR)
recurrence
l≤curR: extend curR; else flush & restart
sort(seg.begin(), seg.end());
long long total=0, curL=seg[0].first, curR=seg[0].second;
for (int i=1;i<n;i++) {
  if (seg[i].first <= curR) curR = max(curR, seg[i].second);
  else { total += curR-curL+1; curL=seg[i].first; curR=seg[i].second; }
}
total += curR - curL + 1;
Gotchathe last open block never gets a "next" segment to trigger its flush — must flush it explicitly once, again, after the loop ends. Coordinates up to ~1e9 with N up to ~1e5 push the total to ~1e14 — long long throughout, not int.
Recognize"size of the union of intervals, coordinates too large to mark individually" → sort by left endpoint, merge overlapping/touching blocks.

Nested Ranges Check

O(n log n)

For each range, does it contain some other range, and is it contained by some other range? Print two 0/1 lines.

sort key
l ascending, tie-break r descending
recurrence
contains: r≤maxSoFar; contained: symmetric pass on minSoFar
sort(v.begin(), v.end(), [](auto a, auto b){
  if (a.fr.fr != b.fr.fr) return a.fr.fr < b.fr.fr;
  return a.fr.sc > b.fr.sc;   // ties: wider range (larger r) first
});
ll maxr = -1;
for (auto& e : v) {           // forward pass: "contains someone"
  if (e.r <= maxr) ans1[e.idx] = 1;
  maxr = max(maxr, e.r);
}
Gotchathe tie-break (equal l, larger r first) is load-bearing — without it, two ranges sharing a left endpoint could be compared in the wrong order and a containment relationship missed. Two separate passes are needed: forward with a running max of r (finds "contains another"), backward with a running min of r (finds "contained by another") — one sweep can't answer both directions.
Recognize"range containment, both directions, judge-facing" → sort by l asc/r desc, two running-extremum passes, not O(n²) pairwise comparison.

Nested Ranges Count

O(n log n)

Same as Nested Ranges Check, but count how many ranges each one contains/is contained by, not just whether any exist.

sort key
identical to Nested Ranges Check
recurrence
ans1[idx]++ (not =1) on r≤maxSoFar
ll maxr = -1;
vector<ll> ans1(n, 0);
for (auto& e : v) {
  if (e.r <= maxr) ans1[e.idx]++;   // count, not flag
  maxr = max(maxr, e.r);
}
Gotchathe running max/min sweep by itself only certifies "contained by the current widest-so-far," it does not by construction equal "count of all ranges containing this one" for free — this works here specifically because of the sort order (l ascending, r descending on ties) making every previously-seen wider range a valid container candidate simultaneously. Swap the counter increment for a boolean set and it's exactly Nested Ranges Check — same scaffold, different accumulation (rule 06).
Recognize"nested-range check, but count instead of yes/no" → same sort + sweep as Nested Ranges Check, increment instead of flag.

9 · Ordered-set greedy maintenance

A multiset stands in for a data structure that would otherwise need manual shifting — both problems process one event at a time and use predecessor/successor-style lookups to update a small local neighborhood.

Tower of Cubes

O(n log n)

Each cube starts a new tower or stacks on an existing tower whose current top is strictly larger. Minimize tower count.

state
tops = multiset of each tower's current top
recurrence
upper_bound(c): erase it, insert c; else insert c (new tower)
multiset<int> tops;
for (int i = 0; i < n; i++) {
  int c; cin >> c;
  auto it = tops.upper_bound(c);
  if (it != tops.end()) tops.erase(it);
  tops.insert(c);
}
cout << tops.size();
Gotchamultiset, not set — two towers can legitimately share the same top value. upper_bound (strict) is required, not lower_bound: a top equal to c can't accept it, the rule needs strictly greater. Placing the cube on the tightest-fitting tower (smallest valid top) preserves taller towers for future smaller cubes — the greedy correctness hinge.
Recognize"minimum piles/towers, each pile must stay monotonic, process in given order" → patience-sorting-style multiset of pile tops, tightest-fit placement.

Traffic Lights

O(n log n)

Street [0,x], lights added one at a time at distinct positions — print the longest gap with no light after each addition.

state
positions=set (with 0,x sentinels), gaps=multiset of lengths
recurrence
split gap(lo,hi) at p into (p−lo) and (hi−p)
auto it = positions.upper_bound(p);
long long hi = *it;
if (it != positions.begin()) it--;
long long lo = *it;
gaps.erase(gaps.find(hi - lo));
gaps.insert(p - lo); gaps.insert(hi - p);
positions.insert(p);
cout << *gaps.rbegin() << ' ';
Gotchamust erase the destroyed gap by iterator, gaps.erase(gaps.find(hi-lo)), never by value gaps.erase(hi-lo) — the value form deletes every gap of that length, not just the one that broke (rule 02). Seed positions with sentinels 0 and x up front so the very first inserted light never needs boundary special-casing.
Recognize"insert points one at a time, report the longest empty gap after each" → set for predecessor/successor, multiset for O(1) max gap.

10 · Range query data structures

From plain prefix sums (no updates, invertible aggregate) up to a full segment tree doing point-update, range-min, and order-statistics descent — the same build/query scaffold reused four times with one line changed each time (rule 01).

Static Range Sum Queries

O(n+q)

Array never changes; answer q range-sum queries.

state
prefix[i] = sum of first i elements (1-indexed)
recurrence
answer(a,b) = prefix[b] − prefix[a−1]
vector<long long> prefix(n + 1, 0);
for (int i = 1; i <= n; i++) { cin>>x; prefix[i]=prefix[i-1]+x; }
cout << prefix[b] - prefix[a - 1];
Gotchano segment tree needed at all — sum has an inverse (subtraction), so a static sum-only array collapses straight to O(1)-per-query prefix sums (rule 01). prefix[0]=0 as the base case handles a==1 queries for free, no special-casing.
Recognize"static array, range sum" → prefix sums, don't reach for a segment tree.

Static Range Minimum Queries

O((n+q) log n)

Array never changes; answer q range-minimum queries.

state
segment tree, node.mn, no update()
merge
res.mn = min(a.mn, b.mn); identity = +∞
node merge(node a, node b) { node r; r.mn = min(a.mn, b.mn); return r; }
// query(): no-overlap returns node() i.e. identity +INF
// full containment returns t[id] directly; else merges both halves
Gotchamin has no inverse the way sum does — you can't "un-min" a value back out, so even with zero updates this still needs the segment tree's query (build once, no update calls at all). The identity for a min-merge must be +∞, not 0 — a 0 identity would corrupt every real min.
Recognize"static array, range min (not sum)" → segment tree still required, but drop update() entirely since the array never changes.

Dynamic Range Sum Queries

O((n+q) log n)

Array supports point updates (set position k to u) interleaved with range-sum queries.

state
segment tree, node.sum, full build+update+query
merge
res.sum = a.sum + b.sum; identity = 0
void update(ll id, ll l, ll r, ll pos, ll val) {
  if (pos < l || pos > r) return;
  if (l == r) { t[id].sum = val; return; }
  ll mid = (l+r)/2;
  update(2*id,l,mid,pos,val); update(2*id+1,mid+1,r,pos,val);
  t[id] = merge(t[2*id], t[2*id+1]);
}
Gotchaupdate sets a position's value, it doesn't add to it — the CSES statement's "set position k to u" maps directly to a leaf overwrite, not a delta application. Direct application of the standing templates/segment_tree.cpp scaffold with zero adaptation beyond wiring the two query types.
Recognize"point updates interleaved with range sum queries" → standard segment tree, sum merge, identity 0.

Josephus Queries

O(n log n)

n children in a circle, repeatedly skip k and remove the next child — print the removal order (n up to 2×10⁵, k up to 10⁵).

state
segment tree over a 1/0-alive array, node.sum=alive count
recurrence
nextRank=(idx+k)%rem+1; removed=findKth(nextRank)
ll findKth(ll id, ll l, ll r, ll k) {
  if (l == r) return l;
  ll mid = (l + r) / 2;
  if (t[2*id].sum >= k) return findKth(2*id, l, mid, k);
  return findKth(2*id+1, mid+1, r, k - t[2*id].sum);
}
Gotchadirect circular-list simulation is O(n) worst case per removal (k can exceed n, forcing a full lap+) — O(n²) total, too slow; findKth makes each removal O(log n) with one path down and no backtracking. The tracked state is the survivor rank, not position: idx = rank "just after" the last removal, rem = survivor count; after removing, idx = nextRank−1, rem−− since everyone past the removed rank shifts down by one.
Recognize"repeatedly remove by rank/position, need the next target fast" (Josephus-style, or any find-the-k-th-remaining need) → segment tree over an alive/dead array, findKth order-statistics descent.
