Increasing Array

O(n)
The ask
Given a[0..n−1], the only legal move is to raise one element by 1. Find the least number of moves that makes the array non-decreasing.
minimise ∑ (bᵢ − aᵢ) subject to bᵢ ≥ aᵢ and bᵢ ≥ bᵢ₋₁
Key observations
  1. You may only raise, never lower — so bᵢ ≥ aᵢ is forced and the answer is a sum of non-negative shortfalls.
  2. Raising bᵢ above max(aᵢ, bᵢ₋₁) never helps: it costs more now and only raises the floor for later elements. So bᵢ = max(aᵢ, bᵢ₋₁) is optimal.
  3. That makes the choice at each index independent of everything after it — one left-to-right pass, no lookahead, no DP.
  4. The comparison is against the adjusted previous value, not the original aᵢ₋₁. A bump propagates.
Brute force → why it dies
naiveSearch over target arrays b, or re-scan the prefix at each index to find the running maximum.
cost O(n²) for the re-scan; unbounded for the search.
dies at n ≤ 2·10⁵ → 4·10¹⁰ operations. Also ∑(prev − x) reaches ~2·10¹⁴, past int.
therefore Carry the running maximum in a single scalar. No structure needed at all — O(n) time, O(1) space, accumulator in long long.
Diagram
Implementation

prev is the floor and is only ever assigned in the else branch — when a shortfall is paid the element becomes prev conceptually, so leaving prev alone is exactly right. Reading and processing in the same loop keeps space at O(1): the array is never stored.

arrays/Increasing_Array.cppverbatim
// Problem: Increasing Array
// Link: CSES 1094
// Pattern: single-pass greedy — track running previous (post-adjustment), pay the shortfall
// Time: O(n)  Space: O(1)
//
// Only allowed move: increase any element by 1. Minimum total moves to make
// the array non-decreasing.
//
// Example:
//     3 2 5 1 7 -> 5

#include <iostream>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    long long prev = 0, cost = 0;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        if (x < prev) cost += prev - x;
        else prev = x;
    }

    cout << cost << '\n';
    return 0;
}
GotchaCompare against the running prev, not a[i-1]. A bump raises the floor for everything after it, and the two differ the moment two dips occur in a row. cost must be long long.
Recognize"one-directional edit only, minimum total change to make a sequence monotone" → single-pass running floor, pay the shortfall.
