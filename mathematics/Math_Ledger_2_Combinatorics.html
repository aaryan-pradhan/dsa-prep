Combinatorics & Prime Counting

Counting problems whose answer is one formula. Either it is a binomial coefficient mod p — which means precomputed factorials and their inverses — or a short recurrence, or a sum over prime factors. The whole difficulty is naming the formula; the code after that is four lines.

Recognition rules

The judgment calls that separate these problems from each other.

1

Answer is "count the arrangements, mod 10⁹+7" → the same fact / invfact block every time. Write it once, then the problem is one ncr call: Binomial Coefficients, Creating Strings II, Distributing Apples.

2

"Distribute m identical things into n distinct boxes" → stars and bars, C(m+n−1, n−1). Size MAXN for m + n, not for n: Distributing Apples.

3

No closed form but the n case reduces to n−1 and n−2 by a case split on one element → write the recurrence and iterate it: Christmas Party.

4

"Count pairs with gcd = 1" or any condition over divisors → count pairs sharing a divisor d for every d, then inclusion–exclusion by ω(d): Counting Coprime Pairs.

5

n up to 10¹² but t small → sieve to √n once, then trial-divide each query by the sieved primes: Next Prime. A sieve to n itself is not an option.

1 · Factorials mod p

Everything here runs on one precomputed block: fact[i], and invfact[i] built backwards from a single modular inverse of fact[MAXN-1], using invfact[i] = invfact[i+1] · (i+1). One mpow, not MAXN of them. After that ncr is three multiplications.

Binomial Coefficients

O(MAX + t)
The ask
Answer t queries of C(a, b) modulo 10⁹+7.
C(n,r) = n! · (r!)⁻¹ · ((n−r)!)⁻¹ (mod p)
Key observations
  1. p = 10⁹+7 is prime, so by Fermat a⁻¹ ≡ a^(p−2). That is what minv is.
  2. Computing an inverse per query is O(log p) each; computing MAXN of them is 10⁶ · 30 = 3·10⁷ multiplications. Instead invert only fact[MAXN-1] and walk down: invfact[i] = invfact[i+1] · (i+1), because (i!)⁻¹ = ((i+1)!)⁻¹ · (i+1).
  3. Guard r > n and r < 0 inside ncr, or invfact[n-r] indexes out of bounds.
  4. fill() runs once in main, not per test.
Brute force → why it dies
naivePascal's triangle up to n, or a fresh mpow inverse per query.
costO(n²) memory for the triangle; O(t log p) for per-query inverses.
dies atn ≤ 10⁶ → the triangle is 10¹² cells.
thereforeTwo arrays of size MAXN, built in O(MAXN) with exactly one mpow.
Diagram
Implementation

This is the reusable block — madd/msub/mmul/mpow/minv/mdiv, then fact, invfact, ncr. The problem itself is the last two lines of solve().

{
    return (a + b) % MOD ;
}
ll msub(ll a , ll b)
{
    return (a - b + MOD) % MOD ;
}
ll mmul(ll a , ll b)
{
    return (a * b) % MOD ;
}
ll mpow(ll a , ll b)
{
    ll res = 1 ;
    while(b)
    {
        if(b & 1)
        {
            res = mmul(res , a) ;
        }
        a = mmul(a , a) ;
        b >>= 1 ;
    }
    return res ;
}
ll minv(ll a)
{
    return mpow(a , MOD - 2) ;
}
ll mdiv(ll a , ll b)
{
    return mmul(a , minv(b)) ;
}

void fill()
{
    fact[0] = 1 ;
    for(ll i = 1 ; i < MAXN ; i++)
    {
        fact[i] = mmul(fact[i - 1] , i) ;
    }
    invfact[MAXN - 1] = minv(fact[MAXN - 1]) ;
    for(ll i = MAXN - 2 ; i >= 0 ; i--)
    {
        invfact[i] = mmul(invfact[i + 1] , (i + 1)) ;
    }

}

{
    if(r > n || r < 0)
    {
        return 0 ;
    }
    return mmul(fact[n] , mmul(invfact[r] , invfact[n - r])) ;
}

{

    cin >> a >> b ;
    cout << ncr(a , b) << endl ;
    
   

}

Creating Strings II

O(MAX + n)
The ask
Count the distinct rearrangements of a string, modulo 10⁹+7.
n! / ∏c = a…z cnt[c]!
Key observations
  1. n! counts all orderings; swapping two copies of the same letter gives the same string, so divide by cnt[c]! for each letter.
  2. Division mod p is multiplication by the inverse — and invfact already holds every factorial inverse needed, so no mdiv call is required at all.
  3. invfact[0] = 1, so letters that do not occur contribute nothing and need no special case.
  4. Same problem as Creating Strings, one constraint bump: n ≤ 10⁶ makes listing them impossible, so only the count is asked for.
Brute force → why it dies
naiveGenerate the permutations and count them, as in Creating Strings.
costO(n!).
dies atn ≤ 10⁶. The answer does not fit in memory, let alone time.
thereforeThe multinomial coefficient, evaluated with precomputed factorials.
Implementation

Count into b[26], fold the 26 inverse factorials, then multiply by fact[n] at the end.

Distributing Apples

O(MAX)
The ask
Count the ways to give m identical apples to n distinct children, modulo 10⁹+7.
#{(x₁…xₙ) ∈ ℕⁿ : ∑ xᵢ = m} = C(m + n − 1, n − 1)
Key observations
  1. Write the m apples in a row as stars, and place n−1 bars among them to cut the row into n groups. Every arrangement is one distribution.
  2. Total symbols = m + (n−1). Choosing where the bars go is C(m+n−1, n−1).
  3. Children may get zero, which is exactly why bars are allowed to be adjacent — no extra constraint.
  4. MAXN must cover m + n − 1, so with n, m ≤ 10⁶ it is 2·10⁶, not 10⁶.
Brute force → why it dies
naiveDP over (child, apples left): dp[i][j] = ∑k≤j dp[i-1][j-k].
costO(n·m) even with prefix sums.
dies atn,m ≤ 10⁶ → 10¹².
thereforeThe closed form. One ncr, O(1) after precomputation.
Diagram
Implementation

st and br name the stars and bars explicitly, so the ncr(tot, br) line reads as the identity rather than as index arithmetic.

2 · Counting recurrences

No closed form is available, but a case split on one element expresses the n case in terms of smaller ones. Derive the recurrence, then iterate it bottom-up.

Christmas Party

O(n)
The ask
Count permutations of n items with no fixed point (derangements), modulo 10⁹+7.
D(n) = #{π ∈ Sₙ : π(i) ≠ i for all i}
Key observations
  1. Child i's gift goes to some child j ≠ i. There are (i−1) choices of j.
  2. Split on what j receives. If j gets i's gift, the two are paired off and the rest is D(i−2). If j is forbidden from i's gift, the remaining i−1 children form a derangement-shaped problem: D(i−1).
  3. Hence D(i) = (i−1)·(D(i−1) + D(i−2)), with D(1) = 0 and D(2) = 1.
  4. n ≤ 10⁶ makes recursion a stack overflow; iterate upwards.
Brute force → why it dies
naiveEnumerate permutations and reject those with a fixed point — or recurse on the formula without memoising.
costO(n!) for enumeration; the plain recursion is O(φⁿ) from the double call.
dies atn ≤ 10⁶. Even the recursion blows the stack.
thereforeOne upward loop over a dp array, O(n).
Implementation

The commented-out rec at the top is the derivation the loop was built from; it is kept as written. The two base cases are handled with continue inside the loop rather than before it.

3 · Prime-factor counting

The answer is a sum indexed by primes or by divisors. A sieve up to the value bound — not up to n — is the shared setup; what differs is what is summed over it.

Trailing Zeros

O(log₅ n)
The ask
How many trailing zeros does n! have?
v₅(n!) = ∑i≥1 ⌊n / 5ⁱ⌋
Key observations
  1. A trailing zero is a factor of 10 = 2·5. Factors of 2 are far more common than factors of 5, so the count of 5s is the binding one.
  2. ⌊n/5⌋ numbers up to n are divisible by 5; ⌊n/25⌋ of them contribute a second 5; and so on. Summing the floors counts each multiplicity exactly once.
  3. The loop is over powers of 5, so it runs at most log₅(10⁹) ≈ 13 times.
  4. No factorial is ever computed. n! at n = 10⁹ has no representation.
Brute force → why it dies
naiveCompute n! and strip zeros, or loop i = 1…n dividing out 5s.
costn! is astronomically large; the per-i loop is O(n log n).
dies atn ≤ 10⁹.
thereforeLegendre's formula: 13 divisions.
Implementation

Three lines. i *= 5 with i <= n ends the loop naturally once the power exceeds n.

Next Prime

O(X log log X + t·g·π(√n))
The ask
For each of t queries, print the smallest prime strictly greater than n, with n up to 10¹².
min {q > n : q prime}
Key observations
  1. A sieve to 10¹² is impossible. A sieve to 10⁶ is 1 MB of bool and gives every prime up to √(10¹²) — enough to test any n by trial division.
  2. Two regimes: if n is inside the sieved range, the answer is already in the prime list — upper_bound. Otherwise test candidates one at a time.
  3. Candidates skip evens: start at n+1 or n+2 so the start is odd, then step by 2.
  4. Trial division stops at x*x > ans. Prime gaps near 10¹² are ~300, so t = 20 queries cost at most a few thousand primality tests.
Brute force → why it dies
naiveSieve up to n, or trial-divide each candidate by every integer ≤ √n.
cost10¹² memory for the sieve; O(√n) = 10⁶ divisions per candidate otherwise.
dies atthe sieve dies on memory immediately; trial division by all integers is ~80× slower than by primes only.
thereforeSieve to √(max n) once, reuse the prime list for every query.
Implementation

sieve() marks composites; main then collects the primes into a vector before reading t. The n < 1000100 branch answers from the list directly.

Counting Coprime Pairs

O(X log X)
The ask
Count pairs i < j with gcd(xᵢ, xⱼ) = 1.
∑d squarefree (−1)ω(d) · C(cnt[d], 2), cnt[d] = #{i : d | xᵢ}
Key observations
  1. Counting coprime pairs directly is hard; counting pairs that share a divisor d is easy — C(cnt[d], 2).
  2. Those overlap, so inclusion–exclusion over the prime divisors: add for an even number of distinct primes, subtract for an odd number. That sign is the Möbius function.
  3. Only squarefree d contribute. Replacing each xᵢ by its radical (the product of its distinct primes) via reduce makes every surviving d automatically squarefree, so no explicit μ table is needed — nopd(d) counts the distinct primes and decides the sign.
  4. cnt[d] for all d comes from the harmonic sum for d: for j = d, 2d, …: dp[d] += freq[j] — X log X, not X².
  5. spf (smallest prime factor) from a linearish sieve makes reduce and nopd O(log x) each.
Brute force → why it dies
naiveAll pairs, __gcd on each.
costO(n² log X).
dies atn ≤ 10⁵ → 5·10⁹ gcd calls.
thereforeCount by divisor and fix the overcounting with Möbius signs: O(X log X) over the value range, independent of n.
Diagram
Implementation

reduce maps each input to its radical, freq counts radicals, dp[d] is the divisor-multiple sum, and the final loop applies the signs.

            for(ll j = i ; j < MAX ; j += i)
            {
                if(spf[j] == 0)
                {
                    spf[j] = i ;
                }
            }
        }
    }
}
ll reduce(ll a)
{
    ll ans = 1 ; 
    while(a > 1)
    {
        ll p = spf[a] ; 
        ans *= p ; 
        while(a % p == 0)
        {
            a /= p ; 
        }
    }
    return ans ;
}
ll nopd(ll a)
{
    ll cnt = 0 ; 
    while(a > 1)
    {
        ll p = spf[a] ; 
        cnt++ ; 
        while(a % p == 0)
        {
            a /= p ; 
        }
    }
    return cnt ;
}

void solve() 
{
    
   ll n ; 
   cin >> n ;
   vector < ll > v(n) ;
   ll maxi = 0 ;
   for(ll i = 0 ; i < n ; i++)
   {
        ll x ; 
        cin >> x ; 
        v[i] = reduce(x) ;
        maxi = max(maxi , v[i]) ;
   }
   vector < ll > freq(maxi + 1 , 0) ;
   for(ll i = 0 ; i < n ; i++)
   {
        freq[v[i]]++ ; 
   }
   vector < ll > dp(maxi + 1 , 0) ;
   for(ll d = 1 ; d <= maxi ; d++)
   {
        for(ll j = d ; j <= maxi ; j += d)
        {
            dp[d] += freq[j] ;   
        }
   }
   
    

   ll ans = 0 ; 
   for(ll d = 1 ; d <= maxi ; d++)
   {
        ll cnt = dp[d] ; 
        ll pairs = (cnt * (cnt - 1)) / 2 ; 
        if(pairs == 0)
        {
            continue ; 
        }
        if(nopd(d) % 2 == 0)
        {
            ans += pairs ;
        }
        else
        {
            ans -= pairs ;
        }
        
   }
   cout << ans << endl ;

}
