Recognition rules

The cross-cutting judgment calls that separate one family from another — these are the actual bugs the problems above were built to catch.

01

sum outer, choice inner counts permutations (order matters — Dice Combinations, Coin Combinations I). choice outer, sum inner counts combinations (order doesn't matter — Coin Combinations II). Same recurrence, opposite loop nesting, opposite answer.

02

An index/item dimension is only load-bearing when supply is limited (0/1 knapsack: Book Shop, Money Sums, Two Sets II, Coin Combinations II). It collapses into one loop over all choices per state when every choice is legal at every state regardless of history (unbounded reuse: Minimizing Coins, Coin Combinations I, Dice Combinations).

03

A "whose turn / which phase" flag doesn't always need its own DP dimension — if it's a deterministic function of another state value already being tracked, derive it instead of storing it. Removal Game gets turn = (n − segment length) % 2 for free from (l, r) alone.

04

Roll the array down to 2 rows (i&1) whenever only the final scalar answer is needed. Keep the full table when you must reconstruct an actual sequence afterward — LCS keeps it to walk the path back; Edit Distance, Book Shop, Array Description and Coin Combinations II all roll because none of them print a reconstruction.

05

An O(n²) DP that scans every earlier index for a valid predecessor often drops to O(n log n) by replacing that scan with a binary search — over a monotonic proxy array (LIS's tails[]) or a precomputed transition target (Projects' next[i]). Recognize the O(n²) shape, then jump straight to the search-based transition.

06

n ≤ ~20 in the constraints is the signal for bitmask DP over 2ⁿ subset states (Elevator Rides). Nothing else in this set has a constraint range that supports an exponential state space — don't reach for a mask when n is in the thousands.

07

Division under a prime modulus is never / — it's multiply by the modular inverse (Fermat: a−1 = aMOD−2 mod MOD). Two Sets II divides a count by 2 this way; any future combinatorics-mod-prime problem needs the same move.

madd(a,b)(a + b) % MOD
mmul(a,b)(a * b) % MOD
msub(a,b)(a − b + MOD) % MOD — guards against a negative left side
mpow(a,b)fast exponentiation, O(log b), the base every other helper is built on
minv(a)mpow(a, MOD−2) — only valid when MOD is prime (it is: 1e9+7)
mdiv(a,b)mmul(a, minv(b)) — the only correct way to "divide" under a modulus

1 · 1D sequential DP

One index, state built from a sum or min over a small set of prior states. The set of valid "moves" out of each state is either fixed (dice faces, coin values) or regenerated per-state (digits of the current number, the neighbor window around a value).

Dice Combinations

O(6n)

Count the ordered sequences of dice rolls (each 1–6) that sum to exactly n — 1+2 and 2+1 count separately.

state
dp[i] = ways to reach sum i
recurrence
dp[i] = ∑ dp[i−k], k=1..6, i−k≥0
base
dp[0] = 1
vector<ll> dp(n+1, 0); dp[0] = 1;
for (int i = 1; i <= n; i++)
  for (int k = 1; k <= 6; k++)
    if (i - k >= 0)
      dp[i] = madd(dp[i], dp[i-k]);
Gotchadp[0]=1, not 0 — it's the "empty roll sequence" identity, and seeding it this way means dp[1..6] fall out of the same loop with zero special-casing.
Recognize"count ordered sequences summing to a target, moves from a small fixed set" → sum-over-window 1D DP.

Minimizing Coins

O(n·x)

Fewest coins (unlimited supply of each denomination) that sum to exactly x; print −1 if impossible.

state
dp[left] = min coins to make left
recurrence
dp[left] = minc≤left dp[left−c] + 1
base
dp[0]=0, else INF
vector<int> dp(x+1, INF); dp[0] = 0;
for (int left = 1; left <= x; left++)
  for (int c : coins)
    if (c <= left && dp[left-c] != INF)
      dp[left] = min(dp[left], dp[left-c] + 1);
Gotchaguard dp[left−c]==INF before adding 1, or an infeasible sub-result silently poisons a real candidate. The coin-index dimension collapses away entirely — see rule 02.
Recognize"unlimited supply, minimize count of picks" → unbounded-knapsack 1D DP, no index dimension.

Coin Combinations I

O(n·x)

Count ordered ways (permutations) to build sum x from reusable coin values — 2+5+2 and 5+2+2 count separately.

state
dp[sum] = ordered ways to reach sum
recurrence
dp[sum] = ∑c dp[sum−c]
base
dp[0] = 1
vector<ll> dp(x+1, 0); dp[0] = 1;
for (int sum = 1; sum <= x; sum++)   // sum OUTER
  for (int c : coins)                // coin INNER
    if (sum - c >= 0)
      dp[sum] = madd(dp[sum], dp[sum-c]);
Gotchasame shape as Dice Combinations, arbitrary coin set instead of 1–6. The sum-outer / coin-inner nesting is what makes it count permutations — see rule 01.
Recognize"order matters + unlimited reuse" → sum-outer loop.

Coin Combinations II

O(n·x)

Count unordered ways (combinations) to build sum x from reusable coin values — {2,2,5} counted once regardless of order.

state
dp[i][left] = ways using coins[i..n−1]
recurrence
dp[i][left] = dp[i+1][left] + dp[i][left−ci]
collapsed 1D
for coin: for sum↑: dp[sum]+=dp[sum−c]
vector<ll> dp(x+1, 0); dp[0] = 1;
for (int c : coins)          // coin OUTER
  for (int sum = c; sum <= x; sum++)  // sum INNER, ascending
    dp[sum] = madd(dp[sum], dp[sum-c]);
Gotchathe coin-outer / sum-inner nesting (opposite of Coin Combinations I) is the entire trick — identical recurrence, flipped loop order turns permutation-counting into combination-counting. See rule 01.
Recognize"order doesn't matter, unlimited reuse" → coin-outer loop.

Removing Digits

O(n log n)

Minimum steps to reduce n to 0, where each step subtracts one nonzero digit currently present in the number.

state
dp[i] = min steps to reduce i to 0
recurrence
dp[i] = min over nonzero digit d of i: dp[i−d]+1
base
dp[0] = 0
vector<ll> dp(n+1, INF); dp[0] = 0;
for (ll i = 1; i <= n; i++) {
  ll t = i;
  while (t > 0) {
    ll d = t % 10;
    if (d) dp[i] = min(dp[i], dp[i-d] + 1);
    t /= 10;
  }
}
Gotchathe "coin set" here is state-dependent — only the digits currently present in i, re-extracted every state via i%10 / i/=10 — not a fixed global set like Minimizing Coins, but the same min-over-choices recurrence shape.
Recognize"the next legal move depends on the current number itself" → per-state generated choice set, still a min-over-choices 1D DP.

Array Description

O(n·m)

Count ways to fill in the unknown (0) entries of an array of size n, values in [1,m], so that any two adjacent values differ by at most 1.

state
dp[i][prev] = ways to fill i..n−1 given pos i−1 = prev
recurrence
fixed: dp[i][prev]=dp[i+1][arr[i]] if |arr[i]−prev|≤1
unknown: dp[i][prev]=∑j=prev−1..prev+1 dp[i+1][j]
base
dp[n][prev] = 1 ∀ prev
for (ll i = n; i >= 0; i--)
  for (ll prev = 1; prev <= m; prev++) {
    if (i == n) { dp[i&1][prev] = 1; continue; }
    if (arr[i] != 0) {
      dp[i&1][prev] = abs(arr[i]-prev)<=1
        ? dp[(i+1)&1][arr[i]] : 0;
    } else {
      ll ans = 0;
      for (ll j = prev-1; j <= prev+1; j++)
        if (j >= 1 && j <= m)
          ans = madd(ans, dp[(i+1)&1][j]);
      dp[i&1][prev] = ans;
    }
  }
Gotchathe answer read-out branches on whether position 0 is itself fixed: direct lookup dp[0][arr[0]], or sum dp[0][j] over all j if it's unknown — there is no single prev to plug in for a free starting cell.
Recognize"adjacency-constrained fill-in-the-blanks counting" → windowed-sum 1D DP over the previous value.

2 · 0/1 knapsack family

Each item usable at most once, so unlike family 1 the index dimension cannot collapse away — the meaning of "used it already" has to survive into the next state.

Book Shop

O(n·x)

n books, each with a price and a page count, budget x, each book buyable at most once — maximize total pages.

state
dp[left] = max pages with budget left remaining
recurrence
dp[i][left] = max(dp[i+1][left], dp[i+1][left−hi]+si)
base
dp[n][*] = 0
for (int i = n; i >= 0; i--)
  for (int left = 0; left <= x; left++) {
    if (i == n) { dp[i%2][left] = 0; continue; }
    ll ans = dp[(i+1)%2][left];               // skip book i
    if (left - h[i] >= 0)
      ans = max(ans, dp[(i+1)%2][left-h[i]] + s[i]);  // take it
    dp[i%2][left] = ans;
  }
Gotchatextbook 0/1 knapsack — the index dimension is load-bearing here (each book once), contrast with Minimizing Coins where the identical-looking loop collapsed to 1D. See rule 02.
Recognize"each item usable once, capacity budget, maximize value" → 0/1 knapsack.

Money Sums

O(n·Σx)

n coins (each used at most once) — list every distinct sum achievable by some subset.

state
dp[i][s] = can coins[i..n−1] reach sum s?
recurrence
dp[i][s] = dp[i+1][s] || (s≥xi && dp[i+1][s−xi])
base
dp[n][0]=true, dp[n][s>0]=false
for (int i = n; i >= 0; i--)
  for (int s = 0; s <= maxSum; s++) {
    if (s == 0) dp[i][s] = true;
    else if (i == n) dp[i][s] = false;
    else {
      bool ans = dp[i+1][s];
      if (s >= x[i]) ans = ans || dp[i+1][s-x[i]];
      dp[i][s] = ans;
    }
  }
Gotchathe sum axis is sized off the problem's own worst case (n·max value = 100·1000 = 100000), hardcoded from the constraints rather than computed from the actual coin sum at runtime — know the bound before you size the array.
Recognize"0/1 subset reachability, list every achievable total" → boolean knapsack.

Two Sets II

O(n·total/2)

Count the ways to split {1,…,n} into two sets of equal sum.

state
dp[i][sum] = # subsets of {1..i} summing to sum
recurrence
dp[i][sum] = dp[i−1][sum−i] + dp[i−1][sum]
answer
total odd → 0; else mdiv(dp[n][total/2], 2)
ll total = n*(n+1)/2;
if (total % 2) { cout << 0; return; }
ll target = total / 2;
vector<vector<ll>> dp(n+1, vector<ll>(target+1, 0));
for (int i = 0; i <= n; i++)
  for (int s = 0; s <= target; s++) {
    if (s == 0) dp[i][s] = 1;
    else if (i == 0) dp[i][s] = 0;
    else {
      ll take = (s-i>=0) ? dp[i-1][s-i] : 0;
      dp[i][s] = madd(take, dp[i-1][s]);
    }
  }
cout << mdiv(dp[n][target], 2);
Gotchathe final /2 is a modular division — via mdiv / Fermat's inverse, not integer division — needed because each valid partition gets counted twice (once as a subset, once as its complement). See rule 07.
Recognize"count subset-sum ways" + "split into two equal halves" → subset-sum DP, halve by symmetry at the end.

3 · Grid-path DP

Two indices, moves restricted to right/down. Direction of the fill (from the destination backward, here) matters more than in most families because both problems define state as "the best result reachable from this cell onward."

Grid Paths I

O(n²)

Count paths from the top-left to the bottom-right of an n×n grid (right/down moves only), avoiding trap cells.

state
dp[i][j] = # paths from (i,j) to the bottom-right
recurrence
dp[i][j] = 0 if trap; 1 if destination; else dp[i+1][j]+dp[i][j+1]
for (int i = n-1; i >= 0; i--)
  for (int j = n-1; j >= 0; j--) {
    if (grid[i][j] == '*') dp[i][j] = 0;
    else if (i==n-1 && j==n-1) dp[i][j] = 1;
    else {
      ll down = (i+1<n) ? dp[i+1][j] : 0;
      ll right = (j+1<n) ? dp[i][j+1] : 0;
      dp[i][j] = madd(down, right);
    }
  }
Recognize"grid path counting with obstacles" → fill from the destination cell backward, sum the two forward neighbors.

Minimal Grid Path

O(n³)*

Print the lexicographically smallest string readable along a top-left to bottom-right path (right/down moves only).

state
dp[i][j] = lexicographically smallest string reaching (i,j)
recurrence
dp[i][j] = min(dp[i−1][j], dp[i][j−1]) + grid[i][j]
string lexi(string a, string b) {
  if (a=="") return b; if (b=="") return a;
  return a < b ? a : b;
}
// dp[i][j] = lexi(dp[i-1][j], dp[i][j-1]) + grid[i][j]
Gotchamaterializing a full string per cell is O(n) length × O(n²) cells × O(n) comparison ≈ O(n³) time/space — correct to reason with, but will not survive n=3000 as written. A judge-passing version compares candidates one character at a time and keeps only the winning predecessor per cell instead of building every string. Know this before coding it live under a strict limit.
Recognize"lexicographically minimal path" and a purely greedy per-step choice doesn't work (a locally smaller next character can still lose on a later tie) → DP comparing whole candidate strings.

4 · Sequence-matching DP

Two-pointer-shaped state over one or two sequences. Whether the full table survives to the end depends entirely on whether you need to reconstruct an actual sequence afterward — rule 04.

Longest Common Subsequence

O(n·m)

Length of the longest common subsequence of two arrays, plus one example of it.

state
dp[i][j] = LCS length of a[0..i−1], b[0..j−1]
recurrence
match: dp[i][j]=1+dp[i−1][j−1]
else: dp[i][j]=max(dp[i−1][j], dp[i][j−1])
// reconstruct by walking back from (n,m):
void print(int i, int j) {
  if (!i || !j) return;
  if (a[i-1]==b[j-1]) {
    print(i-1,j-1); cout << a[i-1] << ' ';
  } else if (dp[i-1][j] > dp[i][j-1]) print(i-1,j);
  else print(i,j-1);
}
Gotchathe full O(n·m) table has to be kept, not rolled — reconstruction walks the whole table backward. Contrast Edit Distance directly below, which only needs the final number and rolls to 2 rows.
Recognize"two sequences, longest common subsequence, need to print one" → full 2D table, no rolling.

Edit Distance

O(n·m)

Minimum insert/delete/replace operations to turn string s into string t.

state
dp[i][j] = edit distance of s[0..i−1], t[0..j−1]
recurrence
match: dp[i][j]=dp[i−1][j−1]
else: 1+min(dp[i][j−1], dp[i−1][j], dp[i−1][j−1])
base
dp[0][j]=j, dp[i][0]=i
for (int i = 0; i <= n; i++)
  for (int j = 0; j <= m; j++) {
    if (!i) { dp[i&1][j] = j; continue; }
    if (!j) { dp[i&1][j] = i; continue; }
    if (s[i-1]==t[j-1]) dp[i&1][j] = dp[(i-1)&1][j-1];
    else dp[i&1][j] = 1 + min({dp[i&1][j-1],
                                  dp[(i-1)&1][j],
                                  dp[(i-1)&1][j-1]});
  }
Gotchaonly the final number is needed here (no reconstruction), so the 2-row rolling array on i&1 is safe — unlike LCS above, which needs the full table.
Recognize"min edit operations between two strings" → classic 3-way min recurrence, rollable.

Increasing Subsequence

O(n log n)

Length of the longest strictly increasing subsequence of an array (n up to 2×10⁵ — too large for the naive O(n²) DP).

naive state (infeasible)
dp[i] = LIS length ending at i, O(n²)
actual technique
tails[k] = smallest tail value of an increasing run of length k+1
vector<ll> tails;
for (int i = 0; i < n; i++) {
  auto it = lower_bound(tails.begin(), tails.end(), a[i]);
  if (it == tails.end()) tails.push_back(a[i]);
  else *it = a[i];
}
cout << tails.size();
Gotchatails is a greedy proxy, not an actual valid subsequence at the end — only its length is meaningful. Strictly increasing → lower_bound; swap to upper_bound for the non-decreasing variant.
Recognize"n too large for O(n²) LIS DP" → collapse to greedy + binary search over tails. See rule 05.

5 · Interval & game DP

State indexed by a shrinking range [l,r]. Fill order has to respect that dp[l][r] depends only on strictly smaller ranges.

Removal Game

O(n²)

Two players alternate removing from either end of a list, each maximizing their own score — find the first player's best achievable score under optimal play from both.

state
dp[l][r] = FIRST player's score over x[l..r]
turn (derived, not stored)
turn = (n − (r−l+1)) % 2
recurrence
turn=0: max(dp[l+1][r]+x[l], dp[l][r−1]+x[r])
turn=1: min(dp[l+1][r], dp[l][r−1])
for (int l = n-1; l >= 0; l--)
  for (int r = l; r < n; r++) {
    ll turn = (n - (r-l+1)) % 2;
    if (l == r) { dp[l][r] = turn==0 ? x[l] : 0; continue; }
    if (turn == 0)
      dp[l][r] = max(dp[l+1][r]+x[l], dp[l][r-1]+x[r]);
    else
      dp[l][r] = min(dp[l+1][r], dp[l][r-1]);
  }
Gotchaturn is derived from segment-length parity instead of carried as a 3rd dimension — rule 03. On the opponent's turn x[l]/x[r] is not added, because dp only tracks the first player's share; the opponent picks whichever end leaves the least for the first player. The more commonly taught formulation instead tracks a score advantage: dp[l][r]=max(x[l]−dp[l+1][r], x[r]−dp[l][r−1]), answer = (total+dp[0][n−1])/2 — be ready to produce either live.
Recognize"two optimal players alternate taking from either end" → interval DP over [l,r], turn from remaining length.

Rectangle Cutting

O(a²b+ab²)

Cut an a×b rectangle down to unit squares, one straight integer-sided cut per move — minimum number of moves.

state
dp[i][j] = min cuts for an i×j rectangle
recurrence
dp[i][j] = 0 if i=j, else
mink<i(1+dp[k][j]+dp[i−k][j]),
mink<j(1+dp[i][k]+dp[i][j−k])
for (int i = 0; i <= a; i++)
  for (int j = 0; j <= b; j++) {
    if (i == j) { dp[i][j] = 0; continue; }
    ll ans = INF;
    for (int k = 1; k < i; k++)
      ans = min(ans, 1 + dp[k][j] + dp[i-k][j]);
    for (int k = 1; k < j; k++)
      ans = min(ans, 1 + dp[i][k] + dp[i][j-k]);
    dp[i][j] = ans;
  }
Gotchaboth i and j ascend together (each cell needs only strictly smaller i and strictly smaller j) — a matrix-chain-style interval-partition DP, try every split point on both axes.
Recognize"split into two integer pieces, minimize a cost over the split" → interval-partition DP trying every split point.

6 · Exponential-state & scheduling DP

Two very different ways constraints push a DP off the "polynomial table" shape: n small enough for 2ⁿ states, or n large enough that even O(n) per transition needs to shrink to O(log n).

Elevator Rides

O(2ⁿ·n)

n people (n≤20), each with a weight, elevator capped at x — minimum number of rides to move everyone.

state
dp[mask] = (min rides, weight of last ride) for people in mask
recurrence
for i∈mask: extend dp[mask^(1<<i)]'s last ride, or start a fresh one
base
dp[0] = (1 ride, 0 weight)
vector<pll> dp(1<<n, {n+1, 0});
dp[0] = {1, 0};
for (int mask = 1; mask < (1<<n); mask++) {
  pll best = {n+1, 0};
  for (int i = 0; i < n; i++) if (mask & (1<<i)) {
    auto [rides, wt] = dp[mask ^ (1<<i)];
    pll cand = (wt + w[i] <= x)
      ? make_pair(rides, wt + w[i])
      : make_pair(rides + 1, w[i]);
    if (cand < best) best = cand;   // rides asc, then weight asc
  }
  dp[mask] = best;
}
cout << dp[(1<<n)-1].first;
Gotchadp[0]=(1,0) is a "phantom" first ride so the very first person added never needs special-casing. Candidates compare (rides, leftover weight) lexicographically — packing the current ride as light as possible is what makes greedy-by-leftover-weight correct, since it leaves the most room for whoever's added next.
Recognize"n ≤ ~20, partition into groups minimizing something" → bitmask DP over 2ⁿ states. See rule 06.

Projects

O(n log n)

n projects, each with a start day, end day and reward, at most one project active per day — maximize total reward.

state
dp[i] = max reward from projects[i..n−1] (sorted by start)
recurrence
dp[i] = max(dp[i+1], pi+dp[next[i]])
next[i]
binary search: first project starting after project i ends
sort(p.begin(), p.end());  // by start day
for (int i = n-1; i >= 0; i--)
  next[i] = firstIndexWithStart_gt(p[i].end);  // binary search
vector<ll> dp(n+1, 0);
for (int i = n-1; i >= 0; i--)
  dp[i] = max(dp[i+1], p[i].reward + dp[next[i]]);
cout << dp[0];
Gotchanot interval DP over [l,r] like family 5 — it's a 1D DP indexed by sorted project order, with binary search standing in for "find the next valid state" instead of a linear scan. Same shape as LIS's O(n log n) upgrade — rule 05.
Recognize"weighted interval scheduling, maximize non-overlapping reward" → sort by start, 1D dp with a binary-searched next-compatible index.

7 · Divide & conquer + segment tree

Kept here for practice continuity, but flagged honestly: this is not overlapping-subproblem DP. No memo table, because every recursive call operates on a disjoint sub-range — there's nothing to reuse.

Mountain Range

O(n log n)

From any mountain, glide to a farther, strictly shorter mountain that dominates everything between the two — maximize mountains visited on one route.

not a dp table
rec(l,r): recurse on disjoint sub-ranges, no memo
powered by
segment tree: range-max height + its index, O(log n) per query
ll rec(int l, int r) {
  if (l > r) return 0;
  auto [maxH, idx] = query(l, r);      // segment tree
  ll lm = query(l, idx-1).first, rm = query(idx+1, r).first;
  ll ans = 1;
  ans = max(ans, (lm==maxH ? 0 : 1) + rec(l, idx-1));
  ans = max(ans, (rm==maxH ? 0 : 1) + rec(idx+1, r));
  return ans;
}
Gotchathe segment tree exists purely to make each "find the max in this range" step O(log n) instead of O(n) — that's what keeps the whole divide-and-conquer at O(n log n) instead of degrading to O(n²) on an already-sorted (worst-case) input.
Recognize"repeatedly split a range at its max/min and recurse on both sides" → segment-tree-accelerated divide & conquer — don't reach for a dp[l][r] table here, there's no overlap to exploit.
