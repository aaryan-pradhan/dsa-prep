Recognition rules

The judgment calls that separate these problems from each other.

1

Order matters (2+3 ≠ 3+2) → sum outside, choices inside. Order doesn't → items outside. Coin Combinations I vs II are the same recurrence with the loops swapped.

2

Unlimited reuse → the take branch stays on the same item (Coin Combinations II) or the item index disappears entirely (Minimizing Coins, Coin Combinations I). Each item once → both branches advance (Book Shop, Money Sums, Two Sets II).

3

Counting problems seed the empty solution with 1 (Dice Combinations, Coin Combinations I/II); min-count problems seed it with 0 and every other state with INF (Minimizing Coins, Removing Digits).

4

If row i only reads row i±1, keep two rows indexed by i & 1 (Coin Combinations II, Book Shop, Array Description). For Book Shop it is the difference between 1.6 MB and 800 MB.

5

A constraint on neighbours (grid traps, |a[i]−a[i−1]| ≤ 1) becomes a 0 or a filtered candidate list, never a special case: Grid Paths I, Array Description.

1 · Last move over a sum

The state is the total so far. Split on the final step; the menu of steps is fixed (dice, coins) or derived from the state (digits). No item index.

Dice Combinations

O(6n)
The ask
Count ordered sequences of die rolls (each 1..6) that sum to n, mod 10⁹+7.
dp[i] = #sequences summing to i dp[0] = 1, dp[i] = Σ dp[i−k], 1 ≤ k ≤ min(6, i)
Key observations
  1. Order matters, so split on the last roll k: what precedes it is any sequence summing to i−k.
  2. dp[0] = 1 — the empty sequence. It makes dp[k] count the lone roll k with no special case.
  3. Each state reads at most 6 earlier states → one forward pass.
Brute force → why it dies
naiveEnumerate every roll sequence recursively.
costO(6ⁿ/…) — exponential
dies atn ≤ 10⁶ → the count itself is ~2n; enumeration never finishes.
thereforeSequences sharing a sum are interchangeable prefixes → one number per sum, O(6n).
Diagram
Implementation

Plain forward loop, i - k >= 0 guards the short prefixes. madd reduces both operands, so it is safe even though every term is already below MOD.

dp/Dice_Combinations.cppverbatim
// Problem: Dice Combinations
// Link: https://cses.fi/problemset/task/1633
// Pattern: 1D bottom-up DP
// Time: O(n)  Space: O(n)
//
// Count the number of ways to construct sum `n` by throwing a dice one or
// more times, each throw producing an outcome between 1 and 6. Order
// matters (1+2 and 2+1 are distinct). Answer modulo 10^9+7.
//
// Constraints: 1 <= n <= 10^6

#include <iostream>
#include <vector>
using namespace std;

typedef long long ll;
const ll MOD = 1000000007;

ll madd(ll a, ll b) { ll s = a % MOD + b % MOD; return s % MOD; }

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n;
    cin >> n;

    vector<ll> dp(n + 1, 0);
    dp[0] = 1;
    for (int i = 1; i <= n; i++) {
        for (int k = 1; k <= 6; k++) {
            if (i - k >= 0) dp[i] = madd(dp[i], dp[i - k]);
        }
    }

    cout << dp[n] << '\n';
    return 0;
}
Gotchadp[0] = 0 zeroes the whole table. The base is the empty sequence, which is one way.
Recognize"number of ordered ways to reach a total with a fixed menu of step sizes" → dp[sum] = ∑ dp[sum − step].

Coin Combinations I

O(n·x)
The ask
Count ordered sequences of reusable coins summing to x, mod 10⁹+7.
dp[0] = 1, dp[s] = Σ over c ≤ s of dp[s−c]
Key observations
  1. Ordered ⇒ it is Dice Combinations with an arbitrary face set: split on the last coin.
  2. Sum loop outside, coin loop inside. Every coin is legal as the last step of every sum, so 2+3 and 3+2 both land.
  3. Base dp[0] = 1, not 0.
Brute force → why it dies
naiveEnumerate sequences recursively.
costexponential
dies atx ≤ 10⁶, n ≤ 100 → answer overflows long before enumeration ends.
thereforeOne count per sum, O(n·x) ≈ 10⁸ simple adds — passes.
Diagram
Implementation

Identical skeleton to Minimizing Coins: min(...)+1 becomes madd. madd uses a conditional subtract since both inputs are already reduced.

// Problem: Coin Combinations I
// Link: https://cses.fi/problemset/task/1635
// Pattern: 1D bottom-up DP, order-matters counting over unbounded coin set
// Time: O(n*x)  Space: O(x)
//
// Count the distinct ordered ways to produce sum `x` from `n` reusable coin
// values (order matters - 2+2+5, 2+5+2, 5+2+2 count separately). Answer
// modulo 10^9+7.
//
// Constraints: 1 <= n <= 100, 1 <= x <= 10^6, 1 <= c_i <= 10^6

#include <iostream>
#include <vector>
using namespace std;

typedef long long ll;
const ll MOD = 1000000007;

ll madd(ll a, ll b) { ll s = a + b; return s >= MOD ? s - MOD : s; }

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n, x;
    cin >> n >> x;

    vector<int> coins(n);
    for (int i = 0; i < n; i++) cin >> coins[i];

    vector<ll> dp(x + 1, 0);
    dp[0] = 1;
    for (int sum = 1; sum <= x; sum++) {
        for (int c : coins) {
            if (sum - c >= 0) dp[sum] = madd(dp[sum], dp[sum - c]);
        }
    }

    cout << dp[x] << '\n';
    return 0;
}
GotchaSwap the loops (coins outside) and you silently get Coin Combinations II — the unordered count. Loop order is the specification.
Recognize"distinct ordered ways" / "2+3 and 3+2 are different" → sums outside, choices inside.

Minimizing Coins

O(n·x)
The ask
Coins of n values, each reusable. Fewest coins summing to x, or −1.
dp[s] = min #coins for sum s dp[0] = 0, dp[s] = min over c ≤ s of dp[s−c] + 1
Key observations
  1. Unbounded reuse ⇒ no coin is ever "used up", so the coin index carries no information. Drop it: state is just the sum.
  2. The last coin is some c; the rest is an optimal solution for s−c.
  3. Unreachable sums must stay unreachable — INF + 1 must never win a min.
Brute force → why it dies
naiveMemoised rec(i, left): take coin i (stay) or skip it (advance).
costO(n·x) states, recursion depth x
dies atx ≤ 10⁶ → 10⁶-deep recursion overflows the stack; the i dimension is 10⁸ states of pure waste.
thereforeCollapse to dp[s], loop all coins per sum, bottom-up: O(n·x) time, O(x) space.
Diagram
Implementation

dp[left - c] != INF is the sentinel guard; without it INF + 1 just becomes a bigger INF here, but the explicit check keeps the intent unambiguous. Output maps INF back to −1.

dp/Minimizing_Coins.cppverbatim
// Problem: Minimizing Coins
// Link: https://cses.fi/problemset/task/1634
// Pattern: 1D bottom-up DP, unbounded reuse (min over all coin values per sum)
// Time: O(n*x)  Space: O(x)
//
// Produce sum `x` from `n` coins (positive integer values, each reusable any
// number of times) using the minimum number of coins. Print -1 if
// impossible.
//
// Constraints: 1 <= n <= 100, 1 <= x <= 10^6, 1 <= c_i <= 10^6

#include <iostream>
#include <vector>
using namespace std;

const int INF = 1000000000;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n, x;
    cin >> n >> x;

    vector<int> coins(n);
    for (int i = 0; i < n; i++) cin >> coins[i];

    vector<int> dp(x + 1, INF);
    dp[0] = 0;
    for (int left = 1; left <= x; left++) {
        for (int c : coins) {
            if (c <= left && dp[left - c] != INF) {
                dp[left] = min(dp[left], dp[left - c] + 1);
            }
        }
    }

    cout << (dp[x] == INF ? -1 : dp[x]) << '\n';
    return 0;
}
GotchaBase is dp[0] = 0, not 1 — this is a min-count, not a way-count. Same loop shape as Coin Combinations I, opposite identity.
Recognize"fewest items, any number of each, to hit an exact total" → 1-D dp[sum], min over item sizes, INF sentinel.

Removing Digits

O(n log n)
The ask
From n, repeatedly subtract one of its nonzero digits. Fewest steps to reach 0.
dp[0] = 0, dp[i] = 1 + min over nonzero digits d of i of dp[i−d]
Key observations
  1. It is Minimizing Coins where the coin set depends on the current sum: the digits of i.
  2. Every move strictly decreases i ⇒ bottom-up from 0 is a valid order.
  3. A nonzero digit d ≤ i always, so dp[i−d] is in range.
Brute force → why it dies
naiveBFS/recursion over all digit choices from n.
costexponential without memo
dies atn ≤ 10⁶ → the same value is reached along huge numbers of paths.
thereforeMemoise on the value: O(n · digits), ≤ 7 digits per state.
Diagram
Implementation

temp peels digits with % 10; zero digits are skipped since subtracting 0 is not progress. dp starts at INF so the first digit always wins.

GotchaThe move set comes from i, not n: temp = i. Precomputing the digits of n once gives a different (wrong) problem.
Recognize"min operations to reduce a number, allowed moves derived from the number itself" → dp[value] over moves.

2 · Take / skip items

The state is (item index, budget). Each item is taken or skipped; whether "take" stays on the row or advances decides unbounded vs 0/1.

Coin Combinations II

O(n·x)
The ask
Count unordered multisets of reusable coins summing to x, mod 10⁹+7.
dp[i][s] = #multisets from coins i..n−1 summing to s dp[i][0] = 1, dp[n][s>0] = 0
Key observations
  1. Unordered ⇒ fix a canonical order: decide coin i fully, then move on. Each multiset is built exactly once.
  2. Take coin i → stay on row i (it may be taken again). Skip → row i+1.
  3. Row i reads only rows i and i+1 ⇒ two rows suffice.
Brute force → why it dies
naiveSum-outside loop as in Coin Combinations I.
costO(n·x) — wrong answer
dies atCounts 2+3 and 3+2 separately: sample gives 8, not 3.
thereforeItem index as the outer dimension, rolling parity rows: O(n·x) time, O(x) memory.
Diagram
Implementation

dp[i&1] is the row being written, dp[(i+1)&1] the row below. The take term reads dp[i&1][left - coins[i]] — the current row, already filled because left ascends. That same-row read is what "reusable" means.

Book Shop

O(n·x)
The ask
Each book has price h and pages s; buy each at most once. Max pages with total price ≤ x.
maximise Σ sᵢ over subsets with Σ hᵢ ≤ x
Key observations
  1. Each item once ⇒ both branches go to row i+1.
  2. Budget "≤ x" instead of "= x" ⇒ base row is 0 for every leftover budget, not just for 0.
  3. Only rows i and i+1 are live ⇒ two rows by parity.
Brute force → why it dies
naiveTry all 2ⁿ subsets.
costO(2ⁿ · n)
dies atn ≤ 1000 → 2¹⁰⁰⁰ subsets.
thereforeState = (next book, budget left): 10³ · 10⁵ = 10⁸ cells, rolling rows keep memory at O(x).
Diagram
Implementation

Outer loop runs i from n down, so dp[0][x] is the answer. Inside i == n the left >= 0 test is always true — the -INF branch is dead code, the affordability check lives in the else branch.

Money Sums

O(n·Σx)
The ask
List every distinct positive sum formed by a subset of n coins.
{ Σ S : ∅ ≠ S ⊆ coins }
Key observations
  1. Knapsack with a boolean value: "is sum s reachable from coins i..n−1".
  2. The sum can never exceed n · max x = 100 · 1000, so a fixed 10⁵ column bound is exact.
  3. Duplicate coin values need no special handling: the set of reachable sums absorbs repeats.
Brute force → why it dies
naiveEnumerate all subsets, insert sums into a set.
costO(2ⁿ)
dies atn ≤ 100 → 2¹⁰⁰.
thereforeDistinct sums ≤ 10⁵ → (n+1) × 10⁵ booleans, 10⁷ work.
Diagram
Implementation

vector<bool> keeps the 10⁷ cells at ~1.2 MB. Column 0 is true in every row (the empty subset), and the output loop starts at s = 1 to exclude it.

Two Sets II

O(n³)
The ask
Count ways to split {1..n} into two sets of equal sum, mod 10⁹+7.
T = n(n+1)/2; count unordered {A, B} with ΣA = ΣB = T/2
Key observations
  1. Odd T ⇒ 0 immediately.
  2. A split is fixed by choosing A: count subsets with sum T/2.
  3. Each split is counted twice (A and its complement) ⇒ divide by 2, which mod p means multiply by 2⁻¹.
Brute force → why it dies
naiveEnumerate subsets of 1..n.
costO(2ⁿ)
dies atn ≤ 500 → 2⁵⁰⁰.
thereforeSubset-sum count over T/2 ≤ 62 625: n · T/2 ≈ 3·10⁷.
Diagram
Implementation

Forward table: row i uses numbers 1..i and reads row i−1. The inner loop variable sum shadows the outer total, harmlessly since the total is no longer used.

3 · Neighbour-constrained fill

Count fillings of a line or grid where each cell only depends on an adjacent cell. The state is the position plus whatever the neighbour pins down.

Grid Paths I

O(n²)
The ask
Count right/down paths from the top-left to the bottom-right of an n × n grid avoiding traps, mod 10⁹+7.
Key observations
  1. A path from (i,j) starts with either down or right — disjoint cases, so counts add.
  2. A trap has 0 paths; that single rule also covers trapped start and end cells.
  3. Filling bottom-up, right-to-left guarantees both neighbours are ready.
Brute force → why it dies
naiveDFS every monotone path.
costO(C(2n, n))
dies atn ≤ 1000 → C(2000, 1000) ≈ 10⁶⁰⁰.
thereforeOne count per cell: O(n²) = 10⁶.
Diagram
Implementation

The '*' test comes before the destination test, so a trapped destination correctly yields 0 everywhere. down/right default to 0 at the borders.

        string x ;
        cin >> x ;
        res[i] = x ;
    }
    vector<vector<ll>> dp(n , vector<ll>(n ,  0)) ;
    for(ll i = n-1 ; i >= 0 ; i--)
    {
        for(ll j = n-1 ; j >= 0 ; j--)
        {
            if ( res[i][j] == '*' ) dp[i][j] = 0 ;
            else if ( i == n-1 && j == n-1 ) dp[i][j] = 1 ;
            else
            {
                ll down = 0 , right = 0 ;
                if ( i+1 < n ) down = dp[i+1][j] ;
                if ( j+1 < n ) right = dp[i][j + 1] ;
                dp[i][j] = madd(down , right) ;
            }
        }
    }
    cout << dp[0][0] << endl ;
}

GotchaSwap the first two branches and a trap on (n−1, n−1) would still report 1.
Recognize"count monotone lattice paths with blocked cells" → dp[cell] = dp[down] + dp[right], trap = 0.

Array Description

O(n·m)
The ask
Fill the zeros of a with values in 1..m so adjacent values differ by at most 1. Count fillings, mod 10⁹+7.
dp[i][p] = #ways to fill i..n−1 given a[i−1] = p
Key observations
  1. The only thing position i needs from the past is the previous value — m ≤ 100 options.
  2. A fixed a[i] is a zero-work case: one candidate, valid or not.
  3. A free a[i] tries p−1, p, p+1 inside [1, m].
Brute force → why it dies
naiveTry every value for every zero.
costO(mᵏ) for k zeros
dies atn ≤ 10⁵, m ≤ 100 → 100¹⁰⁰⁰⁰⁰.
thereforeState (position, previous value): 3 · n · m ≈ 3·10⁷, two rolling rows.
Diagram
Implementation

Rows are indexed by i & 1, filled from i = n down. The final answer reads dp[1][j] when a[0] is free — that 1 is the parity slot holding row i = 1, not "value 1".

// Problem: Array Description
// Link: https://cses.fi/problemset/task/1746
#include <bits/stdc++.h>

#define ll long long
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353
#define INF 1e18
#define mp make_pair
#define PI acos(-1)
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;

ll madd(ll a , ll b)
{
    return (a + b) % MOD ;
}
ll mmul(ll a , ll b)
{
    return (a * b) % MOD ;
}
ll msub(ll a , ll b)
{
    return (a - b + MOD) % MOD ;
}
ll mpow(ll a , ll b)
{
    ll res = 1 ;
    while (b > 0)
    {
        if (b & 1) res = mmul(res , a) ;
        a = mmul(a , a) ;
        b >>= 1 ;
    }
    return res ;
}
ll minv(ll a)
{
    return mpow(a , MOD - 2) ;
}
ll mdiv(ll a , ll b)
{
    return mmul(a , minv(b)) ;
}
ll mcorr(ll a)
{
    return (a % MOD + MOD) % MOD ;
}

void solve()
{
    ll n , m ;
    cin >> n >> m ;
    ll arr[n] ;
    for(ll i = 0 ; i < n ; i++) cin >> arr[i] ;
    ll dp[2][m + 1] ;
    for( ll i = n ; i >= 0 ; i--)
    {
        for(ll prev = 1 ; prev <= m ; prev++)
        {
            if ( i == n )
            {
                dp[(i & 1)][prev] = 1 ;
                continue ;
            }
            ll ans = 0 ;
            if ( arr[i] != 0 )
            {
                if ( abs(arr[i] - prev) <= 1 ) ans = dp[(i + 1) & 1][arr[i]] ;
                else ans = 0 ;
            }
            else
            {
                for(ll j = prev - 1 ; j <= prev + 1 ; j++)
                {
                    if ( j >= 1 && j <= m ) ans = madd(ans , dp[(i + 1) & 1][j]) ;
                }
            }
            dp[(i & 1)][prev] = ans ;
        }
    }
    if ( arr[0] != 0 )
    {
        cout << dp[0][arr[0]] << endl ;
    }
    else
    {
        ll ans = 0 ;
        for(ll j = 1 ; j <= m ; j++)
        {
            ans = madd(ans , dp[1][j]) ;
        }
        cout << ans << endl ;
    }
}
signed main()
{
    ios_base::sync_with_stdio(false);
    cin.tie(0);
    cout.tie(0);

    solve() ;
}
GotchaPosition 0 has no real predecessor, so dp[0][*] is meaningless when a[0] = 0; the code sidesteps it by summing row 1 directly. When a[0] is fixed, dp[0][a[0]] works because a value is always within 1 of itself.
Recognize"fill unknowns, adjacent elements constrained, small value range" → dp[i][previous value].
