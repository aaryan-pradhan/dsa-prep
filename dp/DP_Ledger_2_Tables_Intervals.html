Recognition rules

The judgment calls that separate these problems from each other.

1

Two sequences or a right/down grid → dp[i][j] over prefixes, three neighbours at most: Edit Distance, Longest Common Subsequence, Minimal Grid Path.

2

An action removes or cuts a contiguous piece and leaves smaller contiguous pieces → state is the range or the shape, smaller first: Removal Game, Rectangle Cutting, Mountain Range.

3

n ≤ 2·10⁵ rules out comparing every pair of earlier states; sort and binary-search the one transition that matters: Increasing Subsequence, Projects.

4

When one number is not enough to rank partial answers, store the ranking key itself and compare lexicographically: the pair (rides, weight) in Elevator Rides, the prefix string in Minimal Grid Path.

1 · Two-prefix table

State is a prefix of each of two sequences (or the two coordinates of a monotone grid path). Decide by looking at the last element on each side.

Edit Distance

O(n·m)
The ask
Fewest single-character inserts, deletes and replaces turning s into t.
dp[i][j] = edit distance between s[0..i) and t[0..j) dp[i][0] = i, dp[0][j] = j
Key observations
  1. Look at the last characters. Equal ⇒ they cost nothing, drop both.
  2. Unequal ⇒ the last operation was add (j−1), remove (i−1) or replace (both). Take the cheapest + 1.
  3. Row i reads only rows i and i−1.
Brute force → why it dies
naiveRecurse on the three operations without memo.
costO(3n+m)
dies at|s|, |t| ≤ 5000 → hopeless; even a full table is 25·10⁶ ll = 200 MB.
thereforePrefix pair state, two rolling rows: O(n·m) time, O(m) memory.
Diagram
Implementation

dp[(i&1)] is the current row, dp[(i-1)&1] the previous one. The add term reads the current row at j-1, already written this pass. Answer sits in parity slot n & 1.

Longest Common Subsequence

O(n·m)
The ask
Length of the longest common subsequence of arrays a, b, and one such subsequence.
dp[i][j] = LCS of a[0..i) and b[0..j)
Key observations
  1. Equal last elements can always be matched to each other — take them.
  2. Unequal ⇒ at least one of them is unused: drop a's or b's.
  3. Reconstruction retraces the same decision from (n, m), so the full table must be kept.
Brute force → why it dies
naiveEnumerate subsequences of a, test each against b.
costO(2ⁿ · m)
dies atn, m ≤ 1000 → 2¹⁰⁰⁰.
thereforePrefix pair table, 10⁶ cells, walk back for the witness.
Diagram
Implementation

print recurses back from (n, m): on a match it recurses first and prints after, so output comes out in forward order. On a mismatch it follows the larger neighbour.

Minimal Grid Path

O(n³)
The ask
Right/down path through an n × n letter grid; output the lexicographically smallest string it spells.
Key observations
  1. Every path to (i,j) has the same length ⇒ lexicographic comparison of prefixes is fair.
  2. The best string to (i,j) extends the smaller of the two best strings into it.
  3. Storing whole strings makes each cell cost O(n).
Brute force → why it dies
naiveEnumerate every path string.
costO(C(2n, n) · n)
dies atn ≤ 1000 → astronomically many paths.
thereforeBest prefix per cell (this code): O(n³). The known upgrade keeps only the set of cells on the current anti-diagonal that achieve the minimum prefix: O(n²).
Diagram
Implementation

lexi treats "" as "no candidate" so the border branches can reuse it. For interior cells both neighbours exist and the smaller string is extended by grid[i][j].

2 · Split into sub-ranges

Every move leaves one or two smaller contiguous pieces. Solve by range length or by recursive split.

Rectangle Cutting

O(a·b·(a+b))
The ask
Cut an a × b rectangle along grid lines into squares. Fewest cuts.
dp[i][i] = 0 dp[i][j] = min over every horizontal and vertical cut of 1 + both halves
Key observations
  1. A cut splits one rectangle into two independent rectangles.
  2. Squares are the only base case; there is no greedy rule for where to cut.
  3. Both pieces are strictly smaller ⇒ fill by increasing i, then j.
Brute force → why it dies
naivePlain recursion over every cut.
costexponential
dies ata, b ≤ 500 → the same sub-rectangle appears exponentially often.
thereforeMemo on shape: 2.5·10⁵ shapes × ≤ 1000 cuts = 2.5·10⁸ simple ops.
Diagram
Implementation

Two inner loops try every horizontal and every vertical cut. dp is indexed by exact dimensions, so no swap is needed; row i = 0 stays INF but is never read.

Removal Game

O(n²)
The ask
Players alternately take the first or last element. Both optimal. Max score of the first player.
turn = (n − (r−l+1)) mod 2 dp[l][r] = first player's final score from the remaining range [l, r]
Key observations
  1. What is left is always a contiguous range [l, r].
  2. Whose turn it is follows from how many elements are gone: n − len.
  3. P2 playing optimally = P2 minimising P1's score, since the total is fixed.
Brute force → why it dies
naiveGame tree over both choices each move.
costO(2ⁿ)
dies atn ≤ 5000 → 2⁵⁰⁰⁰.
thereforeRange state, shorter ranges first: n²/2 ≈ 1.25·10⁷ states.
Diagram
Implementation

l descends and r ascends, so dp[l+1][r] and dp[l][r-1] are ready. On P2's turn the table still stores P1's score, which is why the P2 branch adds nothing.

Mountain Range

O(n log n)
The ask
Glide from a mountain to a strictly lower one, only over strictly lower mountains. Max mountains visited.
Key observations
  1. From anywhere in [l, r] you can never cross its tallest mountain m.
  2. Starting at m, you can reach the tallest of either side — everything between is lower.
  3. If that side's max equals h[m] you cannot glide to it; the side is solved on its own, without the +1.
Brute force → why it dies
naiveDP over every start with a scan of reachable targets.
costO(n²)
dies atn ≤ 2·10⁵ → 4·10¹⁰.
thereforeRecursive split at the range max, located by a max segment tree: O(n log n).
Diagram
Implementation

The segment tree node carries mx and its index. merge prefers the right index on ties. Empty queries return node() with mx = 0, safe because heights ≥ 1.

#include <bits/stdc++.h>

#define ll long long 
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353
#define INF 1e18
#define mp make_pair
#define PI acos(-1) 
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;

const ll N = 2e5 + 5 ;
struct node{
    ll mx ; 
    node()
    {
        mx = 0 ;
    }
    ll idx ; 
};

node t[4 * N] ;
ll h[N] ;
ll n ; 
node merge(node a , node b)
{
    node res ;
    res.mx = max(a.mx , b.mx ) ;
    if(a.mx > b.mx)
    {
        res.idx = a.idx ;
    }
    else
    {
        res.idx = b.idx ;
    }
    return res ;
}
void build(ll id , ll l , ll r)
{
    // this builds the segment tree for maximum height in the range l to r both inclusive and stores it in t[id]
    if(l == r)
    {
        t[id].mx = h[l] ;
        t[id].idx = l ;
        return ; 
    }
    ll mid = l + (r - l) / 2 ;
    build(2 * id , l , mid ) ;
    build(2 * id + 1 , mid + 1 , r ) ; 
    t[id] = merge(t[2 * id] , t[2 * id + 1] ) ;
}
node query( ll id , ll l , ll r , ll lq , ll rq)
{
    // this returns the maximum height in the range lq to rq both inclusive from the segment tree
    if( rq < l || r < lq ) return node() ; // this means the range is completely outside the query range
    if( lq <= l && r <= rq ) return t[id] ; // this means the range is completely inside the query range
    ll mid = l + (r - l) / 2 ;
    node left = query(2 * id , l , mid , lq , rq ) ;
    node right = query(2 * id + 1 , mid + 1 , r , lq , rq ) ;
    return merge(left , right ) ;
}
ll rec(ll l , ll r )
{
    // this returns the maximum number of mountains that can be visited in the range l to r both inclusive
    if(l > r) return 0 ;
    node mx = query(1 , 0 , n - 1 , l , r ) ;
    ll idx = mx.idx ;
    ll maxi = mx.mx ;
    node left = query(1 , 0 , n - 1 , l , idx - 1 ) ;
    node right = query(1 , 0 , n - 1 , idx + 1 , r ) ;
    ll lm = left.mx ;
    ll rm = right.mx ;
    ll ans = 1 ; 
    if(lm == maxi)
    {
        ans = max(ans , rec(l , idx -1)) ; 
    }
    else 
    {
        ans = max(ans , 1 + rec(l , idx - 1 ) ) ;
    }
    if(rm == maxi)
    {
        ans = max(ans , rec(idx + 1 , r ) ) ;
    }
    else
    {
        ans = max(ans , 1 + rec(idx + 1 , r ) ) ;
    }
    return ans ;

}

3 · Sorted order + binary search

A one-dimensional DP whose transition would scan all earlier elements; sorting makes the relevant predecessor findable in O(log n).

Increasing Subsequence

O(n log n)
The ask
Length of the longest strictly increasing subsequence.
Key observations
  1. For each length, only the smallest possible ending value matters.
  2. tails is strictly increasing ⇒ binary search where a[i] fits.
  3. lower_bound (≥) keeps it strict: an equal value replaces, never extends.
Brute force → why it dies
naivedp[i] = 1 + max dp[j] over j < i, a[j] < a[i].
costO(n²)
dies atn ≤ 2·10⁵ → 4·10¹⁰.
thereforePatience tails + binary search: O(n log n).
Diagram
Implementation

it == dp.end() means a[i] beats every tail and extends the longest run; otherwise it lowers an existing tail. dp is not an actual subsequence — only its size is meaningful.

Projects

O(n log n)
The ask
Projects [s, e] with reward m; days inclusive, at most one project per day. Max total reward.
sorted by start; dp[i] = best from projects i..n−1
Key observations
  1. Sort by start: taking project i jumps to the first project starting after ei; everything in between overlaps it or is skipped.
  2. Starts are sorted ⇒ that jump target is a binary search.
  3. Days are inclusive: the next start must be > e, not ≥ e.
Brute force → why it dies
naiveFor each project, scan all later ones for compatibility.
costO(n²)
dies atn ≤ 2·10⁵ → 4·10¹⁰; days up to 10⁹ rule out a day-indexed table.
thereforeSort + next[i] by binary search + 1-D DP: O(n log n).
Diagram
Implementation

next[i] is computed by a hand-rolled binary search over [i+1, n−1] with default n. The DP then runs right to left; dp[n] = 0 absorbs "no next project".

Elevator Rides

O(2ⁿ·n)
The ask
n people with weights, elevator capacity x. Fewest rides to carry everyone.
dp[mask] = lexicographic min (rides, weight in the open ride)
Key observations
  1. n ≤ 20 ⇒ 2²⁰ ≈ 10⁶ subsets; the state is "who has already ridden".
  2. For a fixed ride count, a lighter open ride is never worse ⇒ compare pairs lexicographically.
  3. Add person i last: fits → same rides, heavier; else → one more ride holding just wi.
Brute force → why it dies
naiveTry every order of people, fill rides greedily.
costO(n! · n)
dies atn = 20 → 20! ≈ 2.4·10¹⁸.
thereforeOrder only matters through the set used so far: 2ⁿ · n ≈ 2·10⁷.
Diagram
Implementation

Base dp[0] = {1, 0}: one empty open ride. Masks ascend, and mask ^ (1 << i) is always smaller, so it is ready. The tie-break cand.sc < ans.sc is the whole trick.
