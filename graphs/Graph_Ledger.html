Recognition rules

The cross-cutting judgment calls that separate one family from another — these are the actual bugs the problems above were built to catch.

01

Unweighted "fewest steps" wants BFS layer order, not DFS — DFS finds a path, BFS guarantees the shortest. Message Route and Labyrinth both need BFS for that reason; Round Trip and Round Trip II deliberately use DFS instead, because they need ancestor-coloring for cycle detection, not shortest distance.

02

Lazy-deletion Dijkstra (push duplicates, skip stale entries via a vis[] check on pop, not on push) generalizes cleanly: to k-times-per-node (Flight Routes), and to a per-node state key wider than just the node id (Flight Discount's (node,couponUsed) encoding, Investigation's tie-branch aggregates).

03

Any per-node "extra dimension" — coupon used, k-th visit, previous move — belongs in the state key itself, not bolted onto the relax step afterward. Flight Discount doubles every node into encode(node, coupon); Flight Routes swaps a boolean visited-flag for a counter capped at k. Same underlying move: widen the state, keep Dijkstra unchanged.

04

Topological-DP direction follows the dependency arrow: reverse topo order when dp[node] depends on dp[child] (Game Routes sums over children, Longest Flight Route maxes over children) — forward topo order is for problems where the ordering itself is the answer (Course Schedule), not for DP.

05

3-state DFS coloring (unvisited / on-stack / fully done) is required whenever "already visited" must be split into "still an ancestor" vs. "finished, irrelevant." Round Trip and Round Trip II both need it — a 2-state visited array would false-positive a cycle on any DAG-shaped diamond where two paths reconverge on an already-finished node.

06

DSU beats BFS/DFS specifically when connectivity must be queried or updated incrementally as edges are added over time (Road Construction, Road Reparation). BFS/DFS recomputes a component from scratch each time and is the right tool only for a static, one-shot graph (Counting Rooms, Building Roads).

07

Bellman-Ford's dist[] seeding controls the question being asked: all-INF-except-source finds shortest paths from that source; all-zero everywhere (Cycle Finding) finds a negative cycle anywhere in the graph, by treating every node as its own free source simultaneously.

08

n ≤ ~500 with dense edges is the Floyd-Warshall signal (Shortest Routes II) — O(n³) preprocessing beats running Dijkstra from every node when m is large relative to n. Anything with n in the thousands needs single-source Dijkstra/Bellman-Ford per query instead; O(n³) stops being affordable well before n reaches four digits.

find(x)path-compressed root lookup — parent[x] = find(parent[x]) on the way back up flattens the tree for every future call
merge(x, y)union by rank/size — always attach the smaller root under the larger to keep tree height low; no-op if already connected
connected(x, y)find(x) == find(y) — the cycle-free check Kruskal relies on, with no explicit cycle detection code anywhere
size(x)rank[find(x)] — current size of x's component, valid immediately after any merge touching it
sets()running count of disjoint components — decremented once per real merge, untouched by no-op merges

1 · Flood-fill & unweighted BFS/DFS

Grids and plain graphs where every edge costs exactly 1. DFS is enough for pure connectivity (Counting Rooms, Building Roads); the moment you need an actual shortest distance or path, it has to be BFS (Labyrinth, Message Route, Monsters).

Counting Rooms

O(nm)

Grid of floor/wall cells — count the number of 4-directionally connected floor regions.

state
vis[i][j] = room id (0 = unvisited)
algorithm
for each unvisited floor cell: c++; DFS-stamp the whole region with c
void dfs(ll x, ll y, ll n, ll m) {
  vis[x][y] = c;
  for (ll i = 0; i < 4; i++) {
    ll nx = x+dx[i], ny = y+dy[i];
    if (nx>=0 && nx<n && ny>=0 && ny<m
        && !vis[nx][ny] && v[nx][ny]=='.')
      dfs(nx, ny, n, m);
  }
}
// main: if (!vis[i][j] && v[i][j]=='.') { c++; dfs(i,j,n,m); }
Gotcharecursive DFS on a grid up to 1000×1000 = 10⁶ cells risks stack overflow on an adversarial snake-shaped room — an iterative stack or a BFS queue is the safer version to have ready under a strict limit.
Recognize"count connected floor regions in a grid, 4-directional" → grid flood-fill DFS/BFS, one traversal per unvisited cell.

Building Roads

O(n+m)

n cities, some already connected by roads — find the minimum extra roads to make the whole graph one component, and print which ones.

state
vis[node] = component id via DFS
algorithm
answer = col−1 edges, linking comp[i][0]↔comp[i+1][0]
for (ll i = 1; i <= n; i++)
  if (!vis[i]) { col++; dfs(i); }
cout << col - 1 << endl;
for (ll i = 1; i < col; i++)
  cout << comp[i][0] << " " << comp[i+1][0] << endl;
Gotchaany representative node from each component works as the linking endpoint — it doesn't need to be a DSU root, since the full membership of each component is already known from the DFS coloring; a simple linear chain of representatives is enough, no star topology needed.
Recognize"minimum edges to make the whole graph connected, print which ones" → enumerate components once, then chain one representative from each pair together.

Labyrinth

O(nm)

Grid maze with a start (A) and end (B) — find the shortest path length and print it as a direction string.

state
dist[i][j], par[i][j] via single BFS from A
reconstruct
walk par[] back from B to A, diff coords → L/R/U/D
while (a[cx][cy] != 'A') {
  auto [px, py] = par[cx][cy];
  if (px == cx) ans += (py < cy) ? 'R' : 'L';
  else          ans += (px < cx) ? 'D' : 'U';
  cx = px; cy = py;
}
reverse(ans.begin(), ans.end());
Gotchathe direction letter encodes the move from parent to current cell, so get the comparison backward (e.g. compare current-to-parent instead) and the whole printed string comes out reversed in meaning, not just in order. dist is sentinel-filled with -INF, not -1 — check against that exact sentinel.
Recognize"shortest path with the actual path printed" → BFS + parent-pointer array, backtrack from target and translate coordinate deltas to direction characters.

Message Route

O(n+m)

Unweighted graph — find the fewest computers on a route from 1 to n, and print the route.

state
vis[], par[] via plain BFS from node 1
reconstruct
walk par[] from n back to 1 (sentinel par[1]=−1), reverse
vector<ll> ans;
ll node = n;
while (node != -1) { ans.push_back(node); node = par[node]; }
reverse(ans.begin(), ans.end());
cout << ans.size() << endl;
Gotchapar[1] = -1 doubles as both "node 1's parent" and the loop's own termination sentinel — the same one-array-does-double-duty pattern is worth reusing for any "reconstruct path via parent array" BFS.
Recognize"fewest edges plus the actual path" on an unweighted graph → plain BFS with a parent array, backtrack from the target.

Monsters

O(nm)

Escape a grid to any boundary cell strictly before any monster could reach that same cell, moving simultaneously each step.

state
distM[][] = multi-source BFS from every 'M'
distA[][] = single-source BFS from 'A'
answer
any boundary cell with distA < distM (or distM unreachable)
for (auto& [i,j] : monsterCells) { distM[i][j]=0; qm.push({i,j}); }
// one BFS drains qm — all monsters expand in lockstep
while (!qm.empty()) { /* standard 4-dir BFS on distM */ }
Gotchacorrectness requires seeding every monster cell into the queue before the BFS starts draining it — that's what makes each BFS layer represent one real simultaneous time step across all monsters at once; seeding them one at a time would compute the wrong "nearest monster" distance field entirely.
Recognize"you and adversaries move simultaneously, can you reach safety first" → multi-source BFS for the adversary arrival-time field, compare cell-by-cell against your own single-source BFS.

2 · Bipartiteness & reachability checks

Whole-graph structural yes/no questions answered with one or two cheap traversals instead of anything combinatorial.

Building Teams

O(n+m)

Split pupils into two teams so no two friends land on the same team — a bipartiteness check.

state
vis[node] ∈ {0=unvisited, 1, 2}
algorithm
DFS, color child 3−col; same-color neighbor → IMPOSSIBLE
void dfs(ll node, ll col) {
  vis[node] = col;
  for (auto child : g[node]) {
    if (!vis[child]) dfs(child, 3 - col);
    else if (vis[child] == col) { pn; exit(0); }
  }
}
Gotchathe conflict check must compare vis[child]==col (same color), never just "already visited" — a visited neighbor with the opposite color is exactly the expected, valid alternation, not a contradiction.
Recognize"split into two groups with no same-group edge" → BFS/DFS 2-coloring; a contradiction means an odd cycle exists, so no split is possible.

Flight Routes Check

O(n+m)

Directed graph of flights — check whether every city can reach every other city (strong connectivity); if not, print a failing pair.

state
vis[] = BFS(1) on g; rvis[] = BFS(1) on reverse(g)
claim
strongly connected ⇔ R={1..n} && B={1..n}
bfs(1, g, vis);           // R: everything reachable from 1
bfs(1, rg, rvis);         // B: everything that can reach 1
for (i = 1..n) if (!vis[i])  print "NO", 1, i;
for (i = 1..n) if (!rvis[i]) print "NO", i, 1;
Gotchanode 1 isn't structurally special — any fixed hub node works as the pivot, since the proof only needs a path u→hub→v to exist for every pair. That's what collapses an apparent O(n(n+m)) all-pairs check down to exactly 2 BFS passes.
Recognize"check a whole directed graph is strongly connected, in O(n+m) not O(n²)" → forward BFS + reverse-graph BFS from one arbitrary hub node.

3 · Cycle detection via 3-color DFS

"Find any cycle and print it" for a directed and an undirected graph — nearly identical DFS scaffolding, differing in exactly one guard clause.

Round Trip

O(n+m)

Directed graph — find any cycle (2+ distinct cities) and print it, or IMPOSSIBLE.

state
vis[node] ∈ {0=white, 1=gray/on-stack, 2=black/done}
algorithm
back edge to a gray node → walk par[] to reconstruct the cycle
if (!vis[child]) dfs(child, node);
else if (vis[child] == 1) {          // back edge onto the stack
  vector<ll> ans = {child};
  for (ll t = node; t != child; t = par[t]) ans.push_back(t);
  ans.push_back(child); reverse(ans.begin(), ans.end());
}
// ... vis[node] = 2;   set AFTER exploring all children
Gotchathe third state (black/fully-done) is what distinguishes a genuine back-edge (→ real cycle) from a cross-edge into an already-finished branch — a 2-state visited array alone would falsely report a cycle on any DAG where two paths reconverge on the same node.
Recognize"directed graph, find any cycle and print it" → 3-color DFS (white/gray/black), back-edge onto a gray node reconstructs the cycle via parent pointers.

Round Trip II

O(n+m)

Undirected graph — find any cycle of length ≥3 and print it, or IMPOSSIBLE.

state
same 3-color scheme, plus explicit parent-edge skip
algorithm
skip child==parent; else identical to Round Trip
void dfs(ll node, ll parent) {
  vis[node] = 1; par[node] = parent;
  for (auto child : g[node]) {
    if (child == parent) continue;      // the one extra guard
    if (!vis[child]) dfs(child, node);
    else if (vis[child] == 1) { /* reconstruct cycle */ }
  }
  vis[node] = 2;
}
Gotchaundirected edges are stored both directions (a→b and b→a) — without the child==parent skip, walking straight back over the edge you just arrived on gets misreported as a 2-node cycle. That guard is the single line separating this from the directed version above.
Recognize"undirected graph, find any cycle" → same 3-color ancestor-check DFS as the directed case, plus one guard against re-walking the arrival edge.

4 · Topological sort & DAG DP

A DAG's topological order is either the answer itself (Course Schedule) or the safe processing order for a DP whose transitions run along edges (Game Routes, Longest Flight Route).

Course Schedule

O(n+m)

n courses with "a before b" prerequisites — print a valid completion order, or IMPOSSIBLE.

state
indeg[node]; Kahn's BFS queue of zero-indegree nodes
check
topo.size() != n ⇒ a cycle exists
queue<ll> q;
for (i=1..n) if (!indeg[i]) q.push(i);
while (!q.empty()) {
  ll v = q.front(); q.pop(); topo.push_back(v);
  for (auto u : g[v]) if (--indeg[u] == 0) q.push(u);
}
if (topo.size() != n) cout << "IMPOSSIBLE";
Gotchathe only check needed for "no valid order" is topo.size() != n — a cycle simply means some nodes never reach indegree 0 and never get enqueued, so no separate cycle-detection pass is needed on top of Kahn's algorithm itself.
Recognize"valid ordering respecting before-constraints" → Kahn's BFS topological sort; an incomplete topo order is itself the proof of a cycle.

Game Routes

O(n+m)

DAG of teleporters — count the number of distinct paths from level 1 to level n, mod 10⁹+7.

state
dp[node] = # ways from node to n
recurrence
dp[node] = ∑child dp[child], processed in reverse topo order
reverse(topo.begin(), topo.end());
for (auto node : topo) {
  if (node == n) { dp[node] = 1; continue; }
  ll ans = 0;
  for (auto child : g[node]) ans = madd(ans, dp[child]);
  dp[node] = ans;
}
Gotchaprocessing must go sink-to-source (reverse topo) since dp[node] depends on dp[child] — running it forward would sum uncomputed (zero-initialized) child values, silently zeroing out every count.
Recognize"count paths in a DAG" → topo sort, then DP in reverse topological order summing over out-edges.

Longest Flight Route

O(n+m)

DAG of flights — find the route from 1 to n visiting the maximum number of cities, and print it.

state
dp[node] = max cities to n (0 if unreachable)
recurrence
dp[node] = max over child with dp[child]≠0 of dp[child]+1
for (auto node : topo /* reversed */) {
  if (node == n) { dp[node] = 1; continue; }
  ll ans = 0;
  for (auto child : g[node])
    if (dp[child] != 0) ans = max(ans, dp[child] + 1);
  dp[node] = ans;
}
Gotchadp[node]==0 must mean "cannot reach n at all," not "reaches n in 0 more steps" — the explicit dp[child]!=0 guard before taking the max is what keeps an unreachable child from being silently treated as a valid, free transition.
Recognize"longest path / most nodes visited in a DAG" → same reverse-topo DP shape as counting paths, swap the sum for a max, and explicitly exclude dp=0 (unreachable) transitions.

5 · Dijkstra family

One min-heap relaxation loop, reused four ways: plain shortest paths, an augmented state key, augmented per-node aggregates, and a relaxed "visit more than once" rule.

Shortest Routes I

O((n+m) log n)

Directed weighted graph — print the shortest distance from city 1 to every other city.

state
dist[], vis[] (finalized flag)
algorithm
lazy-deletion Dijkstra: skip a popped node if already vis
pq.push({0, 1}); dist[1] = 0;
while (!pq.empty()) {
  auto [d, node] = pq.top(); pq.pop();
  if (vis[node]) continue;
  vis[node] = 1;
  for (auto [w, child] : g[node])
    if (dist[child] > d + w) { dist[child] = d+w; pq.push({dist[child], child}); }
}
Gotchacorrectness of lazy-deletion Dijkstra hinges on checking vis[node] right after popping, not before pushing — the same node can sit in the heap multiple times with different, increasingly stale distances.
Recognize"single-source shortest paths, all weights ≥ 0" → textbook Dijkstra with a min-heap.

Flight Discount

O((n+m) log n)

Cheapest route from 1 to n, with one optional coupon that halves the price of exactly one flight along the way.

state
encode(node, couponUsed) = node*2 + couponUsed — doubled graph
edges
(a,0)→(b,0) full; (a,0)→(b,1) half; (a,1)→(b,1) full
g[encode(a,0)].push_back({c,     encode(b,0)});
g[encode(a,0)].push_back({c / 2, encode(b,1)});  // spend the coupon here
g[encode(a,1)].push_back({c,     encode(b,1)});
// answer: dist[encode(n, 1)]
Gotchathe answer is always read from the "coupon used" layer, even when the discount doesn't help — since discounting can never raise the price, the shortest path in the doubled graph will always end up at least as good in layer 1 as staying in layer 0 forever, so the layer-1 read is safe unconditionally.
Recognize"shortest path plus a single-use power-up along the way" → double/layer the graph by the extra state dimension, run one Dijkstra over the product graph.

Investigation

O((n+m) log n)

Shortest price from 1 to n, plus: how many minimum-price routes, and their minimum and maximum flight counts.

state
dist[], ways[] (mod), min_flights[], max_flights[]
relax
strictly better → overwrite all four; tie → merge into all four
if (d + wt == dist[child]) {
  ways[child] = madd(ways[child], ways[node]);
  min_flights[child] = min(min_flights[child], min_flights[node]+1);
  max_flights[child] = max(max_flights[child], max_flights[node]+1);
} else if (d + wt < dist[child]) {
  dist[child]=d+wt; ways[child]=ways[node];
  min_flights[child]=min_flights[node]+1; max_flights[child]=max_flights[node]+1;
  q.push({dist[child], child});
}
Gotchathe tie branch never re-pushes onto the heap — child's distance hasn't changed, so its existing heap entry is still valid — but it must still merge into ways/min_flights/max_flights, or every tied route silently vanishes from the aggregates.
Recognize"shortest path plus count/min-hops/max-hops among all shortest paths" → augment Dijkstra's relax step with per-node aggregates, branching on strictly-less vs. equal-to-current-best.

Flight Routes

O(km log(kn))

Find the k cheapest routes from 1 to n; routes may revisit cities, and equal-price routes all count separately.

state
vis[node] = times node has been finalized so far, capped at k
algorithm
let each node pop up to k times instead of once
if (vis[node] == k) continue;
vis[node]++;
if (node == n) { ans.push_back(d); if (ans.size()==k) break; }
for (auto& [wt, child] : g[node])
  if (vis[child] < k) pq.push({d + wt, child});
Gotchathis only works because it explicitly permits revisiting a node — a plain visited-once Dijkstra structurally cannot enumerate k distinct routes to the same node, since standard Dijkstra intentionally discards everything except the single best distance per node.
Recognize"k best/shortest paths, revisits allowed" → let each node expand up to k times instead of once inside the Dijkstra loop.

6 · Bellman-Ford & negative cycles

Once edge weights can be negative, Dijkstra's greedy finalize-and-forget breaks; both problems here repurpose Bellman-Ford's relax-n-times structure toward a cycle question rather than a plain shortest-path one.

Cycle Finding

O(nm)

Directed graph, arbitrary weights — detect whether a negative cycle exists anywhere, and print one if so.

state
dist[node] = 0 for every node (not INF!), par[]
algorithm
n full relax rounds; nth round still relaxing ⇒ negative cycle at x
vector<ll> dist(n+1, 0);   // every node is its own free source
ll x = 0;
for (ll round = 1; round <= n; round++) {
  x = 0;
  for (auto& [wt, from, to] : edges)
    if (dist[from] + wt < dist[to]) { dist[to]=dist[from]+wt; par[to]=from; x=to; }
}
for (ll i = 1; i <= n && x; i++) x = par[x];   // walk n times to land inside the cycle
Gotchaseeding dist[] at 0 everywhere (instead of INF-except-source) is the whole trick — it detects a negative cycle anywhere in the graph in one Bellman-Ford run, not only ones reachable from a fixed source. Walking par[] exactly n times before recording the start is required to guarantee landing inside the cycle, not merely upstream of it.
Recognize"detect any negative cycle in the whole graph, not from one source" → seed Bellman-Ford's dist array at 0 for every node, run n rounds instead of n−1.

High Score

O(nm)

Maximize total score walking from room 1 to room n (edge weights can be negative); print -1 if the score is unbounded.

state
negate weights → min-cost; vis[] = reverse-BFS(n): "can reach n"
algorithm
n-round relax, gated by vis[child]; extra round still relaxing a reach-n node ⇒ -1
bfs(n, reverseGraph, vis);           // who can even reach n
for (ll round = 1; round <= n; round++)
  for (ll node = 1; node <= n; node++)
    for (auto& [negW, child] : g[node])
      if (dist[node]+negW < dist[child] && vis[child])
        dist[child] = dist[node] + negW;   // round n relaxing here ⇒ unbounded
Gotchaa negative-cost cycle (a positive-score cycle in the real graph) only breaks the answer if it actually lies on some route from 1 to n — the vis[] reachable-to-n gate on every relaxation is what stops an irrelevant off-path cycle from wrongly forcing a "-1" answer.
Recognize"maximize a walk's score / detect if it's unbounded" → negate weights to reuse min-cost machinery, but gate any relaxation by "is this actually on a path to the target."

7 · Floyd-Warshall APSP

Kept as its own single-problem family — the only place in this set where n is small enough (≤500) that precomputing every pair at once beats running single-source Dijkstra per query.

Shortest Routes II

O(n³)

n≤500 cities, weighted undirected roads, up to 10⁵ distance queries — answer every (a,b) pair.

state
g[i][j] = direct edge weight (min over duplicates), g[i][i]=0
recurrence
g[i][j] = min(g[i][j], g[i][k] + g[k][j])
for (ll k = 1; k <= n; k++)          // k MUST be outermost
  for (ll i = 1; i <= n; i++)
    for (ll j = 1; j <= n; j++)
      g[i][j] = min(g[i][j], g[i][k] + g[k][j]);
Gotchaloop order is non-negotiable — k (the intermediate node) has to be the outermost loop, since the algorithm's invariant is "after processing intermediate k, g[i][j] is optimal using only intermediates ≤k." Swapping k inward silently breaks that invariant and produces wrong distances.
Recognize"n is small (≤~500) and you need many all-pairs queries" → Floyd-Warshall O(n³) preprocessing beats a Dijkstra per source when the graph is dense.

8 · DSU — MST & dynamic connectivity

Both problems share the near-identical union-by-rank/path-compression DSU class (see the toolkit above); what differs is what gets read off it — a running MST cost vs. a running (component count, largest size) pair.

Road Reparation

O(m log m)

n cities, m candidate roads each with a repair cost — minimum total cost to make every city reachable from every other (MST).

state
DSU + edges sorted ascending by cost
algorithm
Kruskal: union if not already connected, add cost
sort(edges.begin(), edges.end(), byCostAscending);
for (auto& [a, b, c] : edges)
  if (!uf.connected(a, b)) { uf.merge(a, b); ans += c; }
if (uf.sets() > 1) cout << "IMPOSSIBLE";
Gotchathe greedy is only correct because edges are pre-sorted ascending — the connected() check before each union is what enforces the "no cycles" MST property, entirely implicitly, without any explicit cycle-detection code.
Recognize"minimum cost to connect everything" / "minimum spanning tree" → sort edges by weight, DSU-guarded greedy union — Kruskal's.

Road Construction

O(mα(n))

Roads are added one at a time — after each, report the current number of components and the size of the largest one.

state
DSU with side-counters setsz (live count) and maxsz (running max)
algorithm
merge(a,b); print(sets(), max_size()) — every single day
void merge(ll x, ll y) {
  x = find(x); y = find(y);
  if (x == y) return;                       // no-op, stats unchanged
  if (rank[x] < rank[y]) swap(x, y);
  parent[y] = x; rank[x] += rank[y];
  maxsz = max(maxsz, rank[x]); setsz--;
}
Gotchamaxsz is a monotonic running maximum, updated only inside a successful merge and never decreased — correct only because components can merely grow here (edges are never removed), which avoids ever having to rescan every set's size after a query.
Recognize"components merge one edge at a time, query live stats after each step" → DSU with incremental side-counters updated inside merge, no full rescan.

9 · Functional-graph binary lifting

Kept as its own single-problem family: every node here has exactly one outgoing edge (a "functional graph"), which is what makes precomputing powers of the successor function pay off for huge-k queries.

Planets Queries I

O((n+q) log k)

Each planet has exactly one outgoing teleporter — answer q queries of "start at x, take k teleports, where do you land," with k up to 10⁵.

state
up[j][node] = the 2^j-th successor of node
query
walk k in binary, high bit to low, jumping by up[j] on each set bit
for (ll k = 1; k < LOG; k++)
  for (ll node = 1; node <= n; node++)
    up[k][node] = up[k-1][up[k-1][node]];
for (ll j = LOG - 1; j >= 0; j--)      // NOT "j = LOG" — see gotcha
  if ((k >> j) & 1) node = up[j][node];
Gotchaas committed, the query loop actually starts at j = LOG (30) while up only has rows 0..LOG-1 (29) — reading up[30][...] is one row past the vector's allocated bound, undefined behavior. It happened to still produce the correct sample output here, but the loop bound belongs at LOG−1, not LOG — don't reproduce the off-by-one live.
Recognize"each node has exactly one outgoing edge, answer huge-k reachability queries" → binary lifting / sparse ancestor table, walk k bit-by-bit from the high bit down.

10 · Monotonic-reach sweep

A genuine BFS-shaped problem (minimum jumps = minimum edges in an implicit graph) solved without ever building a graph or running a queue, because reachable ranges here only ever extend to the right.

Frog Minimum Jumps

O(N+Q)

N stones, each with a jump power p[i] allowing a jump to any stone in [i+1, i+p[i]] — answer Q queries for the minimum jumps from stone 1 to a target.

state
curEnd = edge of current jump count; farthest = edge being built for the next
algorithm
i > curEnd ⇒ jumps++; curEnd = farthest (one more jump was needed)
int jumps = 0, curEnd = 1, farthest = 1;
for (int i = 1; i <= n; i++) {
  if (i > curEnd) { jumps++; curEnd = farthest; }
  dp[i] = jumps;
  farthest = max(farthest, i + power[i]);
}
Gotchadp[i] is not built from stone i's own power looking backward — what actually lets you reach i is some earlier stone j's power (j+power[j]≥i), so the lookback set isn't fixed by i itself; the boundary-sweep sidesteps needing that lookback at all.
Recognize"reachable ranges only ever extend forward, every edge costs 1, need min-jumps to every target" → collapse BFS-by-queue into a single left-to-right boundary sweep (curEnd / farthest), same shape as LeetCode "Jump Game II".
