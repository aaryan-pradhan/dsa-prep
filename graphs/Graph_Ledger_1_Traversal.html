Traversal

Plain BFS and DFS over explicit or implicit graphs. BFS when the question is distance in edges; DFS when it is structure (components, colours, cycles). Most of the work is in what is stored per vertex.

Recognition rules

The judgment calls that separate these problems from each other.

1

Question asks for a count of regions or pieces → count flood-fill launches: Counting Rooms, Building Roads.

2

Unweighted "fewest steps" → BFS; "print the route" → parent array + reverse: Message Route, Labyrinth, Monsters.

3

Several simultaneous starts → one BFS seeded with all of them: Monsters (all M); Frog Minimum Jumps replaces the queue entirely because layers are intervals.

4

Undirected cycle → skip the parent; directed cycle → gray/black states, and do not skip the parent: Round Trip vs Round Trip II.

5

Constraint between endpoints of every edge → propagate a label along DFS and fail on contradiction: Building Teams (colours), Round Trip (open/closed).

1 · Flood fill

Label connected components; the answer is a count or a function of the count.

Counting Rooms

O(n·m)
The ask
Count 4-connected components of . cells in an n × m grid.
Key observations
  1. A room is a connected component of the implicit grid graph.
  2. Each DFS launched from an unvisited floor cell marks exactly one whole room.
  3. Every cell is visited once ⇒ linear in the grid size.
Brute force → why it dies
naiveFor every pair of floor cells, test connectivity.
costO((nm)²)
dies atn, m ≤ 1000 → 10⁶ cells, 10¹² pairs.
thereforeOne flood fill per component, marking as you go: O(n·m).
Diagram
Implementation

vis[x][y] stores the room id c, and the answer is read back as the maximum id — equivalent to just printing c. Neighbours are pruned on bounds, visited and wall before recursing.

Building Roads

O(n+m)
The ask
Add the fewest roads to make an undirected graph connected, and list them.
Key observations
  1. Each new road can merge at most two components ⇒ at least k − 1 roads.
  2. k − 1 suffice: chain one representative of each component to the next.
  3. Any vertex is a valid representative.
Brute force → why it dies
naiveTry adding edges between arbitrary pairs until connected.
costO(n²) checks
dies atn ≤ 10⁵ → 10¹⁰ candidate pairs.
thereforeLabel components once, chain representatives: O(n + m).
Diagram
Implementation

DFS labels every vertex with component id col. comp[c][0] is the smallest vertex of component c, and consecutive components are linked.

2 · BFS + parent

Shortest path in edges, with a parent pointer per vertex to rebuild the route.

Message Route

O(n+m)
The ask
Fewest computers on a path from 1 to n in an unweighted undirected graph, and the path itself.
Key observations
  1. Unweighted ⇒ BFS layers are distances.
  2. The first time a vertex is discovered is via a shortest path; record that parent.
  3. Walk par back from n and reverse.
Brute force → why it dies
naiveDFS all simple paths, keep the shortest.
costexponential
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeBFS: O(n + m).
Diagram
Implementation

vis is set on push, not pop, so each vertex enters the queue once. par[1] = -1 terminates the reconstruction loop.

Labyrinth

O(n·m)
The ask
Shortest path from A to B in a grid with walls; print length and moves.
Key observations
  1. Grid BFS: cells are vertices, 4 neighbours are edges.
  2. Store each cell's parent; the move letter is the difference between cell and parent.
  3. Reconstruction runs from B to A, so the string must be reversed.
Brute force → why it dies
naiveDFS over all paths.
costexponential
dies atn, m ≤ 1000.
thereforeBFS with parents: O(n·m).
Diagram
Implementation

dist = -INF doubles as the unvisited marker. The letter is chosen by comparing parent to child: parent left of the cell ⇒ the move was R.

Monsters

O(n·m)
The ask
You and monsters move simultaneously. Reach a border cell before any monster can; print the moves.
Key observations
  1. Monsters move optimally toward you ⇒ a cell is safe iff you arrive strictly before the nearest monster could.
  2. All monsters at once = one multi-source BFS.
  3. If the final border cell is safe, every earlier cell on your shortest path is too.
Brute force → why it dies
naiveSimulate every step with every monster.
costO((nm)² ) or worse
dies atn, m ≤ 1000.
thereforeTwo BFS (monsters multi-source, you single-source), then scan the border: O(n·m).
Diagram
Implementation

Monster BFS is seeded with every M at distance 0. The border check requires distA < distM strictly (or no monster reaches it). Path letters come from the parent offset.

Frog Minimum Jumps

O(n+q)
The ask
From stone 1, stone i reaches any of i+1..i+pi. Answer many queries: min jumps to stone x.
Key observations
  1. BFS layers here are contiguous index ranges, because reach only grows rightwards.
  2. curEnd closes the current layer; farthest builds the next one.
  3. Precompute every stone once; each query is a lookup.
Brute force → why it dies
naiveBFS enqueuing each of i+1..i+pi.
costO(n²) edges
dies atevery pi = n → n² edge scans.
thereforeBoundary sweep instead of a queue: O(n + q).
Diagram
Implementation

curEnd = farthest = 1 and jumps = 0 make stone 1 come out as 0 with no special case. farthest is updated after recording dp[i], so stone i only extends the next layer.

graphs/Frog_Minimum_Jumps.cppverbatim
// Problem: Frog Minimum Jumps (multi-query)
// Pattern: monotonic-reach BFS collapsed into a single sweep — "Jump Game II"
//          boundary/farthest technique
// Time: O(N + Q)  Space: O(N)
//
// N stones, 1-indexed. Frog starts at stone 1. Stone i has a Jump Power
// p[i] — from stone i the frog can jump forward to any stone in
// [i+1, i+p[i]]. Given Q queries, each a target stone, output the minimum
// number of jumps from stone 1 to reach it (0 if the target is stone 1).
//
// Example:
//     N=5, power=[1,2,4,5,3]
//         query 3 -> 2   (1 -> 2 -> 3)
//         query 1 -> 0
//         query 5 -> 3   (1 -> 2 -> 4 -> 5)

#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(0); cout.tie(0);

    int n; cin >> n;
    vector<int> power(n + 1);
    for (int i = 1; i <= n; i++) cin >> power[i];

    // dp[i] = min jumps from stone 1 to stone i
    vector<int> dp(n + 1, 0);
    int jumps = 0, curEnd = 1, farthest = 1;

    for (int i = 1; i <= n; i++) {
        if (i > curEnd) {
            jumps++;
            curEnd = farthest;
        }
        dp[i] = jumps;
        farthest = max(farthest, i + power[i]);
    }

    int q; cin >> q;
    while (q--) {
        int x; cin >> x;
        cout << dp[x] << "\n";
    }

    return 0;
}
GotchaLooking back with stone i's own power is wrong: what reaches i is an earlier stone's power.
Recognize"min jumps, each position reaches a forward range" → Jump Game II boundary sweep.

3 · DFS colouring / cycles

DFS that carries a per-vertex state (colour, on-stack) and stops at the first contradiction.

Building Teams

O(n+m)
The ask
Split pupils into two teams so no two friends share a team.
2-colour an undirected graph
Key observations
  1. Bipartite check: every edge must join different colours.
  2. In a component, colouring the first vertex forces everything else.
  3. An edge between equal colours is an odd cycle ⇒ impossible.
Brute force → why it dies
naiveTry all 2ⁿ assignments.
costO(2ⁿ · m)
dies atn ≤ 10⁵.
thereforePropagate colours by DFS: O(n + m).
Diagram
Implementation

Round Trip

O(n+m)
The ask
Find any cycle of length ≥ 3 in an undirected graph and print it.
Key observations
  1. In undirected DFS, any edge to an already-open vertex other than the parent closes a cycle.
  2. Skipping the parent is what excludes the trivial a–b–a.
  3. Walk par from the current vertex back to the open one.
Brute force → why it dies
naiveSearch from every vertex for a path back.
costO(n·(n+m))
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeOne DFS with states 0/1/2 and parents: O(n + m).
Diagram
Implementation

vis is 0 unseen, 1 on the stack, 2 finished. On a back edge to child, walk temp up from node, then append node again to close the loop.

Round Trip II

O(n+m)
The ask
Find any directed cycle and print it.
Key observations
  1. A directed cycle exists iff DFS finds an edge into a vertex still on the recursion stack (gray).
  2. Edges into finished (black) vertices are not cycles — that is why three states are needed.
  3. The cycle is the stack segment from that vertex to the current one.
Brute force → why it dies
naiveFrom every vertex, search for a path back to itself.
costO(n·(n+m))
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeWhite/gray/black DFS: O(n + m).
