Recognition rules

The judgment calls that separate these problems from each other.

1

Counting or optimising over paths in a DAG → DP in reverse topological order: Game Routes (sum), Longest Flight Route (max); Course Schedule is the order itself.

2

Mutual reachability → reversed graph: Flight Routes Check (two BFS), Planets and Kingdoms (Kosaraju).

3

Boolean choices with pairwise "at least one" constraints → implication graph + the same SCC routine: Giant Pizza reuses Planets and Kingdoms' two-pass DFS.

4

Connectivity under edge insertions only → DSU: Road Construction (online stats), Road Reparation (edges in cost order).

1 · Topological order

DAGs: order vertices so edges point forward, then process in that order.

Course Schedule

O(n+m)
The ask
Order n courses so every prerequisite comes first, or report IMPOSSIBLE.
Key observations
  1. A valid order exists iff the prerequisite graph is a DAG.
  2. A vertex with in-degree 0 can always go next.
  3. If the queue empties early, the remaining vertices all sit on or behind a cycle.
Brute force → why it dies
naiveTry permutations.
costO(n! · m)
dies atn ≤ 10⁵.
thereforeKahn's algorithm: O(n + m).
Diagram
Implementation

In-degrees are counted while reading edges. The size check topo.size() != n is the cycle test.

Game Routes

O(n+m)
The ask
Count paths from level 1 to level n in a DAG, mod 10⁹+7.
Key observations
  1. Paths from v = sum over first edge of paths from the child.
  2. Children must be finished first ⇒ process vertices in reverse topological order.
  3. Vertices that cannot reach n naturally get 0.
Brute force → why it dies
naiveDFS enumerating paths.
costexponential
dies atn ≤ 10⁵, m ≤ 2·10⁵; path count is exponential.
thereforeDP over topological order: O(n + m).
Diagram
Implementation

Kahn produces topo, which is reversed so children come first. The commented rec is the same recurrence top-down.

Longest Flight Route

O(n+m)
The ask
Longest path (most cities) from 1 to n in a DAG, with the route; or IMPOSSIBLE.
Key observations
  1. Longest path is easy on a DAG: same shape as path counting with max.
  2. dp = 0 must mean "cannot reach n", so dead ends are skipped, not counted as length 1.
  3. Rebuild by following any child with dp[child] = dp[v] − 1.
Brute force → why it dies
naiveDFS all paths.
costexponential
dies atn ≤ 10⁵, m ≤ 2·10⁵; longest path is NP-hard in general graphs.
thereforeDAG ⇒ DP over reverse topo: O(n + m).
Diagram
Implementation

if (r != 0) filters children that cannot reach n. The walk from 1 always finds a child with dp[node] − 1 because dp[1] > 0.

2 · Strong connectivity

Reachability in both directions, via the reversed graph.

Flight Routes Check

O(n+m)
The ask
Can every city reach every other? If not, print a pair a b with no route a → b.
Key observations
  1. All pairs reachable ⇔ 1 reaches everyone and everyone reaches 1.
  2. "Everyone reaches 1" is BFS from 1 on the reversed graph.
  3. An unreached i gives the witness directly: 1 i or i 1.
Brute force → why it dies
naiveBFS from every vertex.
costO(n·(n+m))
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeTwo BFS: O(n + m).
Diagram
Implementation

Forward BFS from 1 on g, then on rg. The first unvisited vertex in each pass is the witness.

Planets and Kingdoms

O(n+m)
The ask
Label strongly connected components.
Key observations
  1. The vertex that finishes last in DFS on G lies in a source component of the condensation.
  2. In reverse(G), that component is a sink: DFS from it cannot leak out.
  3. Repeat in decreasing finish order; each launch is one SCC.
Brute force → why it dies
naiveReachability both ways for every pair.
costO(n·(n+m))
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeKosaraju: two DFS passes, O(n + m).
Diagram
Implementation

order collects vertices on DFS exit; popping from the back gives decreasing finish time. vis is reused as the component id in the second pass.

Giant Pizza

O(n+m)
The ask
Each member wants at least one of two topping choices. Pick toppings to satisfy everyone, or IMPOSSIBLE.
2-SAT: ∧ (ℓ₁ ∨ ℓ₂)
Key observations
  1. a ∨ b is two implications: ¬a ⇒ b and ¬b ⇒ a.
  2. x and ¬x in one SCC ⇒ each implies the other ⇒ unsatisfiable.
  3. Otherwise set each literal whose component comes later in topological order — implications never lead from true to false.
Brute force → why it dies
naiveTry all 2ᵐ topping sets.
costO(2ᵐ · n)
dies atm ≤ 10⁵.
thereforeImplication graph on 2m literals + Kosaraju: O(n + m).

3 · Union-find

Merge-only connectivity.

Road Construction

O(m α(n))
The ask
Roads are added one by one; after each, print the number of components and the largest component size.
Key observations
  1. Components only merge, never split ⇒ union-find.
  2. A successful merge lowers the count by one.
  3. The max size can only change at a merge, to the new merged size.
Brute force → why it dies
naiveBFS/DFS after every addition.
costO(m·(n+m))
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeDSU with path compression + union by size: ≈ O(m).
Diagram
Implementation

rank actually holds set sizes. merge returns early on the same root, so setsz and maxsz only move on real merges.

#define ll long long 
#define endl "\n"

#define sc second

#define PI acos(-1)

#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
struct UnionFind{
    ll n , *parent , *rank , setsz , maxsz; 
    UnionFind()
    {
        n = setsz = 0 ;
        parent = nullptr ; 
        rank = nullptr ; 
        maxsz = 0 ;
    }
    UnionFind(ll a)
    {
        n = setsz = a ; 
        parent = new ll[a+1] ;
        rank = new ll[a+1] ; 
        for(ll i = 1 ; i <= a ; i++)
        {
            parent[i] = i ; 
            rank[i] = 1 ; 
        }
        maxsz = 1 ;
    }
    ll find(ll x)
    {
        if(parent[x] == x)
        {
            return x ; 
        }
        return parent[x] = find(parent[x]) ; 
    }
    void merge(ll x , ll y)
    {
        x = find(x) ; 
        y = find(y) ; 
        if(x == y)
        {
            return ; 
        }
        if(rank[x] < rank[y])
        {
            swap(x , y) ; 
        }
        // this ensures that the larger set is always the parent of the smaller set, which helps to keep the tree flat and improves the efficiency of the union-find operations.
        parent[y] = x ; 
        rank[x] += rank[y] ; 
        maxsz = max(maxsz , rank[x]) ; 
        setsz-- ; 
    }
    bool connected(ll x , ll y)
    {
        return find(x) == find(y) ; 
    }
    ll size(ll x)
    {
        return rank[find(x)] ; 
    }

    ll sets()
    {
        return setsz ; 
    }
    ll max_size()
    {
        return maxsz ; 
    }
};

{

    cin >> n >> m ; 
    UnionFind uf(n) ; 
    for(ll i = 0 ; i < m ; i++)
    {
        ll a , b ; 
        cin >> a >> b ; 
        uf.merge(a , b) ; 
        cout << uf.sets() << " " << uf.max_size() << endl ;

Road Reparation

O(m log m)
The ask

Key observations
  1. Cheapest edge crossing any cut is safe to take (cut property).
  2. Processing edges by cost, an edge joining two different components is such an edge.
  3. If more than one component remains, no spanning tree exists.
Brute force → why it dies
naiveTry all subsets of n−1 edges.
costexponential
dies atn ≤ 10⁵, m ≤ 2·10⁵.
thereforeKruskal with DSU: O(m log m).

4 · Binary lifting

Functional graphs with huge step counts.

Planets Queries I

O((n+q) log k)
The ask
Every planet has one teleporter. Answer queries: where do you end after k teleports from x?
f(v) given; answer f^k(x), k ≤ 10⁹
Key observations
  1. Out-degree exactly 1 ⇒ the k-th successor is well defined.
  2. 2ʲ steps = two 2ʲ⁻¹ step jumps ⇒ a doubling table.
  3. Any k is a sum of powers of two: jump once per set bit.
Brute force → why it dies
naiveSimulate k steps per query.
costO(q·k)
dies atq ≤ 2·10⁵, k ≤ 10⁹ → 2·10¹⁴.
thereforeBinary lifting with 30 levels: O(30·(n + q)).
Diagram
Implementation

LOG = 30 covers k < 2³⁰. up is LOG × (n+1) of long long, ~48 MB. The query loop applies bit j in any order since jumps commute.

// orz
#include <bits/stdc++.h>
#define LOG 30
#define ll long long 
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353
#define INF 1e18
#define mp make_pair
#define PI acos(-1) 
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
void solve() 
{
    ll n , qu ;
    cin >> n >> qu ;

    vector< vector < ll > > up(LOG , vector<ll>(n+1 , 0)) ;
    
    for(ll i = 1 ; i <= n ; i++)
    {
        ll a ; 
        cin >> a ; 
        up[0][i] = a ;
        // up [ j ] [ node ] = the 2^j th ancestor of node
    }
    for(ll k = 1 ; k < LOG ; k++)
    {
        // for each node, we will find the 2^k th ancestor of that node
        // 2^k th ancestor of node = 2^(k-1) th ancestor of 2^(k-1) th ancestor of node
        for(ll node = 1 ; node <= n ; node++)
        {
            // 2 raise to k-1th ancestor of all nodes is already calculated in the previous iteration, so we can use that to calculate the 2^k th ancestor of all nodes
            up[k][node] = up[k-1][up[k-1][node]] ;
        }
    }
    while(qu--)
    {
        ll node , k ; 
        cin >> node >> k ;
        for(ll j = 0 ; j < LOG ; j++)
        {
            // if the jth bit of k is set, we will move to the 2^j th ancestor of node
            ll bit = (k >> j) & 1 ;
            if(bit)
            {
                node = up[j][node] ;
            }
        }
        cout << node << endl ;
    }
    




    



   






}
