Recognition rules

The judgment calls that separate these problems from each other.

1

Pick by weights and query shape: non-negative, one source → Dijkstra (Shortest Routes I); negative edges or cycles → Bellman-Ford (High Score, Cycle Finding); all pairs with n ≤ 500 → Floyd (Shortest Routes II).

2

Extend the vertex, not the algorithm: Flight Discount doubles vertices by coupon state; Flight Routes lets each vertex be finalised k times.

3

Aggregates over shortest paths ride along Dijkstra: reset on strictly shorter, merge on equal. Investigation; the same reset rule is what Shortest Routes I does with dist alone.

4

A negative cycle only matters where the question looks: High Score filters to 1→n walks, Cycle Finding seeds all distances at 0 to see every cycle.

1 · Dijkstra and variants

Min-heap over tentative distances. The variants change the state (Flight Discount), the pop limit (Flight Routes) or what is carried (Investigation).

Shortest Routes I

O((n+m) log m)
The ask
Shortest distance from city 1 to every city; directed, non-negative weights.
Key observations
  1. Non-negative weights ⇒ the smallest tentative distance is final when popped.
  2. Lazy deletion: push duplicates, skip a vertex already finalised.
  3. Each edge relaxes at most once per finalised vertex ⇒ ≤ m pushes.
Brute force → why it dies
naiveBellman-Ford: relax all edges n times.
costO(n·m)
dies atn ≤ 10⁵, m ≤ 2·10⁵ → 2·10¹⁰.
thereforeBinary-heap Dijkstra: O((n+m) log m).
Diagram
Implementation

vis[node] guards against stale heap entries. The relaxation uses dist[node], which equals the popped d for the first (valid) pop.

Flight Discount

O((n+m) log m)
The ask
Cheapest route 1 → n when exactly one flight may be halved (rounded down).
Key observations
  1. "Used the coupon yet?" is one extra bit of state.
  2. Double every city; the coupon edge moves from layer 0 to layer 1.
  3. Plain Dijkstra on the layered graph; answer is (n, 1) — halving never hurts.
Brute force → why it dies
naiveFor each edge, halve it and rerun Dijkstra.
costO(m · (n+m) log m)
dies atm ≤ 2·10⁵ → ~10¹¹.
thereforeOne Dijkstra on 2n vertices and 3m edges.
Diagram
Implementation

encode(a, b) = 2a + b packs the layer into the vertex id; the array is sized 2n + 2. Only layer-0 vertices get the c / 2 edge.

Flight Routes

O(k·(n+m) log(km))
The ask
The k cheapest routes (not necessarily simple) from 1 to n.
Key observations
  1. The j-th pop of a vertex from a min-heap is its j-th shortest walk.
  2. The k-th shortest route to n only extends routes that are among the k shortest at each vertex.
  3. Cap pops per vertex at k; stop after k pops of n.
Brute force → why it dies
naiveEnumerate walks by cost.
costunbounded
dies atn ≤ 10⁵, m ≤ 2·10⁵, k ≤ 10.
thereforeDijkstra with a per-vertex pop counter: O(k·m log(km)).
Diagram
Implementation

vis[node] is a pop counter, not a flag. Pushes to a child already popped k times are pruned since they can never be used.

Investigation

O((n+m) log m)
The ask
For shortest routes 1 → n: the length, how many there are, and the min and max number of flights among them.
Key observations
  1. Restrict to shortest-path edges: those with dist[u] + w = dist[v].
  2. Dijkstra finalises in distance order, which is a topological order of that sub-DAG.
  3. Strictly better arrival resets the aggregates; an equal arrival merges them.
Brute force → why it dies
naiveEnumerate all shortest paths.
costexponential
dies atcounts reach 10⁹+7-sized values; m ≤ 2·10⁵.
thereforeCarry (ways, minF, maxF) through Dijkstra: O((n+m) log m).
Diagram
Implementation

The equality branch does not push: the child is already in the heap with this distance. All three aggregates are updated in both branches, reading from the popped node.

2 · Bellman-Ford

Relax every edge n−1 times; anything still relaxable afterwards is on or behind a negative cycle.

High Score

O(n·m)
The ask
Maximum score path 1 → n; print −1 if the score can be made arbitrarily large.
Key observations
  1. Max-sum path = shortest path with negated weights.
  2. Unbounded ⇔ a negative cycle reachable from 1 and able to reach n.
  3. Reverse BFS from n marks which vertices can reach n.
Brute force → why it dies
naiveDijkstra on negated weights.
costwrong
dies atnegative edges break Dijkstra's finality.
thereforeBellman-Ford n rounds + one detection round: O(n·m) ≈ 5·10⁵ at n ≤ 2500, m ≤ 5000.
Diagram
Implementation

vis comes from BFS on the reversed graph from n. Relaxations only happen into vis vertices and from finite dist, so cycles that are unreachable from 1 or cannot reach n are ignored.

Cycle Finding

O(n·m)
The ask
Does the directed graph have a negative cycle? If so, print one.
Key observations
  1. Starting all distances at 0 is a virtual source with 0-edges to every vertex ⇒ every cycle is reachable.
  2. If round n still relaxes something, a negative cycle exists.
  3. Following par n times from that vertex guarantees landing on the cycle.
Brute force → why it dies
naiveEnumerate cycles.
costexponential
dies atn ≤ 2500, m ≤ 5000.
thereforeBellman-Ford with parents: O(n·m).
Diagram
Implementation

x is reset each round, so after the loop it is the last vertex relaxed in round n. The collection loop starts at x and stops when it returns, then reverses to get edge direction.

3 · Floyd–Warshall

All-pairs by allowing intermediates one at a time.

Shortest Routes II

O(n³ + q)
The ask
Answer q shortest-distance queries between arbitrary pairs; undirected, n ≤ 500.
Key observations
  1. After phase k, g[i][j] is the best path using only intermediates 1..k.
  2. n ≤ 500 ⇒ n³ = 1.25·10⁸, tiny inner loop.
  3. Parallel edges: keep the minimum when reading.
Brute force → why it dies
naiveDijkstra per query.
costO(q · m log m)
dies atq ≤ 10⁵, m ≤ n²/2 → ~10¹⁰.
thereforePrecompute all pairs once: O(n³), each query O(1).
Diagram
Implementation

INF is 1e18, so INF + INF = 2·10¹⁸ still fits in long long and no guard is needed. Diagonal set to 0 after reading edges.
