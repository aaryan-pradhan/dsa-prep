Recognition rules

The judgment calls that separate these problems from each other.

1

If a node's answer depends only on its subtree, one post-order DFS does it: children first, then combine. See Subordinates and Tree Matching. Counting Paths uses the same idea for its final pass.

2

If the answer for every node depends on the whole tree, don't run n DFS passes. Run an in-DP (downward) and then an out-DP pushed from parent to child. See Tree Distances I and II.

3

A child often needs the parent's total without its own share. For a sum, subtract it (Tree Distances II, other_children_matching in Tree Matching). For a max, keep the top two values (Tree Distances I).

4

"k levels up" or "lowest common" with q ≤ 2·10⁵ queries means a binary lifting table: up[v][j] = up[up[v][j−1]][j−1], with node 0 standing for "above the root". See Company Queries I and II, Distance Queries and Counting Paths.

5

Reduce path questions to the LCA. Distance is d[a]+d[b]−2d[lca] (Distance Queries). To count paths through each node, add +1 at both ends, −1 at the lca and −1 at its parent, then sum over subtrees (Counting Paths).

1 · Subtree DP

One DFS. A node's value is computed from its children's finished values on the way back up. The state is the node, plus one flag when the node itself can be used or left free.

Subordinates

O(n)
The ask
Tree rooted at 1, with each node's parent given. For every node, count the nodes strictly below it.
ans[v] = sts[v] − 1, sts[v] = 1 + ∑ sts[c] over children c
Key observations
  1. Subordinates of v = the subtree of v, minus v itself.
  2. Subtree size is 1 plus the sizes of the child subtrees.
  3. In post-order, every child is finished before its parent reads it.
Brute force → why it dies
naiveDFS each node's subtree separately.
costO(n²) on a chain.
dies atn ≤ 2·10⁵ → 4·10¹⁰.
thereforeOne post-order DFS summing child sizes: O(n).
Diagram
Implementation

Edges are stored only from parent to child (g[x].push_back(i)), so child != par never fails. It is harmless. depth and p are unused.

Tree Matching

O(n)
The ask
Choose the most edges such that no two chosen edges share a node.
dp[v][0] = ∑ max(dp[c][0], dp[c][1]) dp[v][1] = max over c of dp[v][0] − max(dp[c][0], dp[c][1]) + 1 + dp[c][0]
Key observations
  1. In its subtree, v is either unmatched (state 0) or matched to exactly one child (state 1).
  2. If v is unmatched, every child takes its better state.
  3. If v is matched to c, then c must be in state 0 and every other child is unchanged. So swap c's term in the sum.
  4. The swap is a subtraction from dp[v][0], so there is no inner loop: O(deg) per node.
Brute force → why it dies
naiveTry every subset of edges.
costO(2ⁿ⁻¹ · n)
dies atn ≤ 2·10⁵. It is dead by n = 40.
thereforeTwo-state tree DP: O(n).
Diagram
Implementation

There are two loops over the children. The first loop must finish dp[node][0] before the second one uses it. other_children_matching is the whole sum minus this child's best, and that subtraction is the swap.

#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
vector < vector < ll > > g ;
vector < vector < ll > > dp ;

void dfs(ll node, ll par)
{
    // dp[node][0] = maximum matching in the subtree rooted at node when node is not matched
    // dp[node][1] = maximum matching in the subtree rooted at node when node is matched with one of its children
    dp[node][0] = 0 ;
    dp[node][1] = 0 ;
    
    for(auto child : g[node])
    {
        if(child != par)
        {
            dfs(child , node) ;
            // this should fill up node's children's dp values first, then we can calculate node's dp values based on its children's dp values
            dp[node][0] += max(dp[child][0] , dp[child][1]) ;
        }
    }
    // now we have dp[node][0] filled, we can calculate dp[node][1] by considering matching node with one of its children

    for(auto child : g[node])
    {
        if(child != par)
        {
            // if we match node with child, then we cannot take dp[child][1] (because child is matched), but we can take dp[child][0] (because child is not matched)
            // and for all other children, we can take the maximum of dp[other_child][0] and dp[other_child][1]
            ll matched_with_child = 1 + dp[child][0] ; // 1 for the edge between node and child
            // now add the maximum matching from all other children
            ll other_children_matching = dp[node][0] - max(dp[child][0] , dp[child][1]) ; // subtract the contribution of this child from dp[node][0]
            dp[node][1] = max(dp[node][1] , matched_with_child + other_children_matching) ;
        }
    }
}

Tree Diameter

O(n)
The ask
Find the longest path in the tree, counted in edges.
max over u, v of dist(u, v)
Key observations
  1. The farthest node from any start is one end of a diameter.
  2. The farthest distance from that end is the diameter.
  3. So run two depth DFS passes, with no DP.
Brute force → why it dies
naiveBFS from every node and take the global max.
costO(n²)
dies atn ≤ 2·10⁵ → 4·10¹⁰.
thereforeDouble DFS: O(n).
Diagram
Implementation

The same dfs and d[] are reused. The second call overwrites every depth because the tree is connected. The first scan keeps the first strict maximum. The second scan only needs the value.

2 · Rerooting

An answer for every node. in[v] covers v's subtree. out[v] covers everything else and is pushed from parent to child. The answer is in combined with out. The whole trick is how the parent excludes the child it is pushing into.

Tree Distances I

O(n)
The ask
For every node, find the distance to the node farthest from it.
ans[v] = max(in[v], out[v]) in[v] = max over c of (in[c] + 1) out[c] = max(out[v] + 1, best in[] of c's siblings + 2)
Key observations
  1. The farthest node from v either lies in v's subtree or is reached through v's parent.
  2. Going up from child c, the path either continues above v (out[v]+1) or turns down into a sibling (in[s]+2).
  3. The best sibling excluding c is the top in[] value, or the second one when c holds the top. So keep two maxima.
  4. Starting mx2 = −1 makes an only child get −1 + 2 = 1, which is the distance to v itself.
Brute force → why it dies
naiveBFS from each node.
costO(n²)
dies atn ≤ 2·10⁵ → 4·10¹⁰.
thereforeIn-DP, then out-DP with the top two child values: O(n).
Diagram
Implementation

dfsout finds mx1 and mx2 over the children first, then recurses with max(outval + 1, use + 2). The child is excluded by value (indp[child] == mx1), not by identity.

ll n ; 
vector < vector < ll > > g ;
vector < ll > indp ; 
vector < ll > outdp ;
void dfsin(ll node, ll par)
{
    indp[node] = 0 ;
    // indp[node] = maximum distance from node to any of its descendants
    for(auto child : g[node])
    {
        if(child != par)
        {
            dfsin(child , node) ;
            indp[node] = max(indp[node] , indp[child] + 1) ;
        }
    } 
}
void dfsout(ll node, ll par, ll outval)
{
    // outdp[node] = maximum distance from node to any of its ancestors
    outdp[node] = outval ;
    // here outval is the maximum distance from node to any of its ancestors
    ll mx1 = -1 , mx2 = -1 ;
    for(auto child : g[node])
    {
        if(child != par)
        {
            if(indp[child] >= mx1)
            {
                mx2 = mx1 ;
                mx1 = indp[child] ;
            }
            else if(indp[child] > mx2)
            {
                mx2 = indp[child] ;
            }
        }
    }
    // now we have the maximum and second maximum distances from node's children to its descendants
    
    for(auto child : g[node])
    {
        if(child != par)
        {
            ll use = mx1 ;
            if(indp[child] == mx1)
            {
                use = mx2 ;
            }
            dfsout(child , node , max(outval + 1 , use + 2)) ;
            
        }
    }

}

Tree Distances II

O(n)
The ask
For every node, sum the distances to all other nodes.
in[v] = ∑ (in[c] + sts[c]) out[c] = out[v] + (n − sts[v]) + (in[v] − in[c] − sts[c]) + (sts[v] − sts[c]) ans[v] = in[v] + out[v]
Key observations
  1. Every node under c is one step farther from v than from c, which is why + sts[c].
  2. From c, the n − sts[v] nodes outside v's subtree are one step farther than from v.
  3. v's other branches contribute their in[] total, plus one step for each of their sts[v] − sts[c] nodes. That count includes v.
  4. For a sum, excluding a child is subtraction, so there is no top-2 trick.
Brute force → why it dies
naiveBFS from each node and sum.
costO(n²)
dies atn ≤ 2·10⁵ → 4·10¹⁰.
thereforeSubtree sizes plus rerooting: O(n).
Diagram
Implementation

dfsin fills sizes and in[] together. use is built in two lines: first the part above v, then v's other branches. Those are exactly the four terms of the formula.

3 · Binary lifting & LCA

Table up[v][j] holds the 2j-th ancestor of v, and 0 is the sink above the root. Any jump of k steps uses the set bits of k. The LCA step: bring both nodes to equal depth, then jump from high j to low while the ancestors still differ.

Company Queries I

O((n+q) log n)
The ask
For each query, find x's ancestor k levels up, or −1 if it doesn't exist.
up[v][0] = parent(v), up[v][j] = up[ up[v][j−1] ][j−1]
Key observations
  1. k is a sum of powers of two, so make one table jump per set bit.
  2. A 2j jump is two 2j−1 jumps.
  3. up[0][*] = 0, so overshooting the root stays at 0. That means −1.
Brute force → why it dies
naiveFollow the parent pointer k times.
costO(k) per query.
dies atA chain with n, q = 2·10⁵ → 4·10¹⁰.
thereforeBinary lifting: O(n log n) to build, O(log n) per query.
Diagram
Implementation

Parents come straight from input, so no DFS is needed. The level loop i is outermost, so level i−1 is complete for every node before level i reads it. The query stops early once x reaches 0.

Company Queries II

O((n+q) log n)
The ask
For each query (a, b), find their lowest common ancestor.
lca(a, b) = the deepest v that is an ancestor of both
Key observations
  1. Lift the deeper node by d[a] − d[b]. If the two nodes are now equal, that node is the LCA.
  2. From j = 19 down to 0, jump both while up[a][j] ≠ up[b][j]. That can never cross the LCA.
  3. Afterwards, a and b are children of the LCA, so the answer is up[a][0].
Brute force → why it dies
naiveWalk both nodes up one parent at a time.
costO(n) per query.
dies atA chain with n, q = 2·10⁵ → 4·10¹⁰.
thereforeLift to equal depth, then descend the jumps: O(log n).
Diagram
Implementation

The DFS only computes depth, because up[i][0] comes straight from input. After the descent, the code checks a == b first (b was an ancestor of a) and otherwise takes the shared parent. The final else is unreachable.

// orz
#include <bits/stdc++.h>

#define ll long long 
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353
#define INF 1e18
#define mp make_pair
#define PI acos(-1) 
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
vector < vector < ll > > g; 
vector < ll > d ; 
vector < vector < ll > > up ;
void dfs(ll node , ll parent, ll depth)
{
    d[node] = depth ; 
    for (auto child : g[node])
    {
        if (child != parent)
        {
            dfs(child , node , depth + 1) ; 
        }
    }
}
void solve() 
{
    ll n , q ; 
    cin >> n >> q ;
    g.resize(n+1) ;
    d.resize(n+1) ;
    up.resize(n+1 , vector < ll > (20 , 0)) ;

    for (ll i = 2 ; i <= n ; i++)
    {
        ll x ;
        cin >> x ;
        g[x].push_back(i) ;
        g[i].push_back(x) ;
        up[i][0] = x ;
    }
    dfs(1 , 0 , 0) ;

    // binary lifting
    for(ll sa = 1 ; sa < 20 ; sa++)
    {
        for(ll node = 1 ; node <= n ; node++)
        {
            up[node][sa] = up[up[node][sa-1]][sa-1] ;
        }
    }

    while(q--)
    {
        ll a , b ; 
        cin >> a >> b ; 
        if (d[a] < d[b]) swap(a , b) ; 
        // a is deeper than b
        // lift a to the same depth as b
        ll diff = d[a] - d[b] ;
        for(ll sa = 0 ; sa < 20 ; sa++)
        {
            if (diff & (1 << sa))
            {
                a = up[a][sa] ;
            }
        }
        for(ll sa = 19 ; sa >= 0 ; sa--)
        {
            // if the ancestor 2^sa edges away towards root for a and 2^sa edges away towards root for b are different, then we can lift both a and b to their respective ancestors
            if (up[a][sa] != up[b][sa])
            {
                a = up[a][sa] ;
                b = up[b][sa] ;
            }
            // if the ancestore 2^sa edges away from a and 2^sa edges away from b are the same, then we cannot lift both a and b to their respective ancestors, because they will be the same, so we continue to the next sa which is smaller that is we have overshot our target 
            else
            {
                continue ; 
            }
        }
        // now a and b are at the same depth and their ancestors 2^sa edges away towards root are the same, so we can lift both a and b to their respective ancestors which are the same, so we can return either a or b as the answer
        if(a == b)
        {
            cout << a << endl ; 
        }
        // if a and b are not the same, then we can return their parent as the answer
        // why is the parent of a and b the lowest common boss of a and b? because we have lifted both a and b to their respective ancestors which are the same, so their parent is the lowest common boss of a and b
        else if(up[a][0] == up[b][0])
        {
            a = up[a][0] ;
            cout << a << endl ;
        }
        else

             cout << "Pranjal is Gay" << endl ;

GotchaCheck a == b before taking the parent. When b is an ancestor of a, equal depth already lands on b. The descent doesn't move either node because every ancestor matches, and returning up[a][0] would be one level too high.

Distance Queries

O((n+q) log n)
The ask
For each query (a, b), find the number of edges between a and b.
dist(a, b) = d[a] + d[b] − 2·d[lca(a, b)]
Key observations
  1. The a–b path goes up to the LCA and back down.
  2. Root depths measure both halves once the LCA's depth is subtracted twice.
  3. The LCA is found exactly as in Company Queries II.
Brute force → why it dies
naiveBFS from a for each query.
costO(n) per query.
dies atn, q = 2·10⁵ → 4·10¹⁰.
thereforeDepths plus LCA: O(log n) per query.
Diagram
Implementation

This table is indexed up[level][node], the reverse of Company Queries II, with the same recurrence. The parent is recorded in the DFS because the input is an edge list. node_a and node_b save the originals before lifting overwrites a and b.

Counting Paths

O((n+m) log n)
The ask
Given m paths, count for each node how many paths pass through it.
diff[a] += 1, diff[b] += 1, diff[lca] −= 1, diff[par(lca)] −= 1 ans[v] = ∑ diff[u] over u in subtree(v)
Key observations
  1. After subtree sums, +1 at a marks every node from a up to the root.
  2. The two marks overlap from the LCA upward. −1 at the lca leaves it counted once, and −1 at par(lca) clears everything above.
  3. This is a 1D difference array, with "prefix" replaced by "subtree".
  4. Subtree sums are post-order accumulation: add each child into its parent after the child is final.
Brute force → why it dies
naiveWalk each path and increment every node on it.
costO(n) per path.
dies atn, m = 2·10⁵ on a chain → 4·10¹⁰.
thereforeFour marks per path using the LCA, then one accumulation pass: O((n+m) log n).
Diagram
Implementation

topo records nodes in post-order, since each node is pushed after its children. Iterating it adds every node into its parent only after the node itself is final. The root adds into cnt[0], which is a harmless sink.
