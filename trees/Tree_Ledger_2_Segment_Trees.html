Segment Trees & Flattening

Range structures filed under trees/: a segment tree over an Euler tour, descending a segment tree to find a position, lazy range updates, and the static 2D case where prefix sums are enough. Reach for this page when there are q ≤ 2·10⁵ queries over an array or a flattened tree.

Master table

The 60-second scan. Each name jumps to its entry.

ProblemFamilyInvariant / recurrenceTime

Recognition rules

The judgment calls that separate these problems from each other.

1

No updates means precompute, not a segment tree (Forest Queries). If updates are mixed with queries, use a segment tree (Subtree Queries, Hotel Queries, List Removals, Range Update Queries).

2

Point update with a range read needs no lazy tags (Subtree Queries, Hotel Queries). Range update with a point read needs lazy tags (Range Update Queries).

3

"First position where …" or "k-th remaining" means descend the tree and pick the left child whenever the left aggregate is enough. Hotel Queries checks max ≥ r. List Removals checks count ≥ k and passes k − left to the right.

4

Never shift the array. A removed element becomes a 0 leaf (List Removals), and a shrinking capacity overwrites its leaf (Hotel Queries). Original indices stay valid.

5

A tree question becomes an array question once the subtree is a contiguous range [tin, tout] (Subtree Queries). After that, the same build/update/query/merge skeleton as Hotel Queries applies unchanged.

1 · Euler tour + segment tree

A DFS visits a subtree as one contiguous stretch of time. Relabel nodes by entry time and every subtree becomes an array range.

Subtree Queries

O((n+q) log n)
The ask
A rooted tree has node values. Queries are either set vs = x, or sum the values in the subtree of s.
subtree(s) ↔ positions [tin[s], tout[s]] in DFS order query = ∑ arr[tin[s] .. tout[s]]
Key observations
  1. A DFS enters s, visits the whole subtree, then leaves, so the subtree occupies consecutive entry times.
  2. tin = the entry time. tout = the largest entry time inside the subtree.
  3. An update is a point write at tin[s], and a query is a range sum. That is a plain segment tree.
Brute force → why it dies
naiveDFS the subtree for each query.
costO(n) per query.
dies atn, q = 2·10⁵ → 4·10¹⁰.
thereforeFlatten, then use a sum segment tree: O(log n) per operation.
Diagram
Implementation

s[timer] = val[node] lays the values out in tin order, and build reads s. update sets the leaf rather than adding to it, which matches the problem's "change the value". encode and encode_tree just name the tin and [tin, tout] mappings.

2 · Segment tree descent

The query is a position, not an aggregate. At each node, check whether the left child's aggregate is enough and go left or right. That is one root-to-leaf walk, O(log n), with no outer binary search.

Hotel Queries

O((n+m) log n)
The ask
For each group of size r, find the first hotel with at least r free rooms, print its index and subtract r. If there is none, print 0.
i* = min { i : h[i] ≥ r }, h[i*] −= r
Key observations
  1. If max(left half) ≥ r, the first fit is in the left half. Otherwise it is in the right half.
  2. So a max segment tree answers "first fit" with one descent.
  3. Subtracting is a point update of the leaf's new value.
Brute force → why it dies
naiveScan from hotel 1 for each group.
costO(n) per group.
dies atn, m = 2·10⁵ → 4·10¹⁰.
thereforeMax segment tree plus descent: O(log n) per group.
Diagram
Implementation

query tries left and then right, but it returns −1 at once when st[id].mx < val. So a failed branch costs O(1), and the walk stays O(log n). The empty node's mx = -INF never matters because every leaf is built.

        build(2 * id , l , mid) ; 
        build(2 * id + 1 , mid + 1 , r) ;
        st[id] = merge(st[2 * id] , st[2 * id + 1]) ;
    }
}
void update(ll id, ll l, ll r, ll pos, ll val)
{
    if (pos < l )
    {
        return ; 
    }
    else if(pos > r)
    {
        return ; 
    }
    else if(l == r && l == pos)
    {
        st[id].mx = val ; 
        return ; 
    }
    else
    {
        ll mid = l + (r - l) / 2 ;
        update(2 * id , l , mid , pos , val) ;

        st[id] = merge(st[2 * id] , st[2 * id + 1]) ;

ll query(ll id , ll l , ll r , ll val)
{
    if(st[id].mx < val)
    {
        // if the maximum value in this segment is less than val, then there is no hotel in this segment that can accommodate the group, so we return 0
        return -1 ;
    }
    else if(l == r)
    {
        // we are at a leaf node, so we return the index of the hotel
        if(st[id].mx >= val)
        {
            return l ; 
        }
        else
        {
            return -1 ; 
        }
        
    }
    else
    {
        ll mid = l + (r - l) / 2 ;
        // we first check the left child, because we want to find the first hotel that can accommodate the group
        ll left = query(2 * id , l , mid , val) ; 
        if(left != -1)
        {
            return left ; 
        }
        else
        {
            return query(2 * id + 1 , mid + 1 , r , val) ;
        }
    }

}

List Removals

O(n log n)
The ask
Repeatedly remove the element at current position p and print it.
alive[i] ∈ {0,1}; remove min { j : ∑i≤j alive[i] = p }
Key observations
  1. Keep the original indices and mark a removal by setting its leaf to 0.
  2. Current position p = the p-th leaf that is still 1.
  3. Descend: if the left count is ≥ k, go left. Otherwise go right with k − left count.
Brute force → why it dies
naivevector::erase at p.
costO(n) per removal.
dies atn = 2·10⁵ → ~2·10¹⁰ shifts.
thereforeCount segment tree plus k-th-one descent: O(log n) per removal.
Diagram
Implementation

Every leaf is built as 1, and update writes 0. In query, the l == r && k != 1 branch can't be reached once the top-level k > st[id].sum guard holds.

3 · Lazy propagation

A range update stops at the O(log n) nodes that fully cover the range and leaves a tag. Every later visit pushes the tag down first, so no node is read stale.

Range Update Queries

O((n+q) log n)
The ask
Queries either add u to every xi in [a, b], or print xk.
push: sum += (r−l+1)·lazy; children.lazy += lazy; lazy = 0
Key observations
  1. [a, b] splits into O(log n) fully covered nodes, so tag those and stop.
  2. A tag on a node applies to its whole range, which is why len·lazy goes into the sum.
  3. Push on entry to both update and query, so anything read is current.
Brute force → why it dies
naiveLoop from a to b on every update.
costO(n) per update.
dies atn, q = 2·10⁵ → 4·10¹⁰.
thereforeLazy segment tree: O(log n) per operation. A difference array under a plain sum tree also works, with no tags.
Diagram
Implementation

In the full-cover branch, update adds to lazy and pushes straight away, so this node's sum is already correct when the parent merges. query prints at the leaf instead of returning a value.

#define ll long long 
#define endl "\n"
#define fr first
#define sc second
#define MOD 1000000007
#define MOD1 998244353

#define mp make_pair
#define PI acos(-1) 
#define py cout << "YES" << endl
#define pn cout << "NO" << endl
#define pll pair<ll,ll>

using namespace std;
ll n , q ; 
vector < ll > arr ;

struct stnode{
    ll sum ; 
    ll lazy ;
    stnode()
    {
        sum = 0 ; 
        lazy = 0 ; 
    }
};
vector < stnode > st ;
stnode merge(stnode a , stnode b)
{
    stnode res ;
    res.sum = a.sum + b.sum ;
    return res ;
}
void push(ll id , ll l , ll r)
{
    if(st[id].lazy != 0)
    {
        st[id].sum += (r - l + 1) * st[id].lazy ;
        if(l != r)
        {
            st[2 * id].lazy += st[id].lazy ;
            st[2 * id + 1].lazy += st[id].lazy ;
        }
        st[id].lazy = 0 ;
    }
}
void build(ll id , ll l , ll r)
{
    if(l == r)
    {
        st[id].sum = arr[l] ; 
        return ; 
    }
    else
    {
        ll mid = l + (r - l) / 2 ;
        build(2 * id , l , mid) ; 
        build(2 * id + 1 , mid + 1 , r) ;
        st[id] = merge(st[2 * id] , st[2 * id + 1]) ;
    }
    
}
void update(ll id, ll l , ll r , ll lq , ll rq, ll val)
{
    push(id , l , r) ;
    if(rq < l || lq > r)
    {
        return ; 
    }
    else if(lq <= l && r <= rq)
    {
        st[id].lazy += val ;
        // why do we need to push here? because we need to update the current node's sum value as well, since we are adding a lazy value to it. If we don't push here, the sum value will not be updated and will be incorrect when we query it later.
        push(id , l , r) ;
    }
    else
    {
        ll mid = l + (r - l) / 2 ;
        update(2 * id , l , mid , lq , rq, val) ; 
        update(2 * id + 1 , mid + 1 , r , lq , rq, val) ;
        st[id] = merge(st[2 * id] , st[2 * id + 1]) ;
    }
}
void query(ll id , ll l , ll r , ll pos)
{
    push(id , l , r) ;
    if(pos < l || pos > r)
    {
        return ; 
    }
    else if(l == r && l == pos)
    {
        cout << st[id].sum << endl ;
        return ; 
    }
    else
    {
        ll mid = l + (r - l) / 2 ;
        query(2 * id , l , mid , pos) ; 
        query(2 * id + 1 , mid + 1 , r , pos) ;
    }
}

4 · 2D prefix sums

A static grid needs no tree. Precompute once, and each rectangle is four corners with inclusion–exclusion.

Forest Queries

O(n² + q)
The ask
For each query, count the trees (*) inside a rectangle of a fixed n×n grid.
ps[i][j] = f[i][j] + ps[i−1][j] + ps[i][j−1] − ps[i−1][j−1] ans = ps[y2][x2] − ps[y1−1][x2] − ps[y2][x1−1] + ps[y1−1][x1−1]
Key observations
  1. There are no updates, so the counts can be precomputed.
  2. A rectangle is the big prefix minus the strip above and the strip to the left, plus the corner that was subtracted twice.
  3. 1-indexing with a zero row and column removes every bounds check.
Brute force → why it dies
naiveCount the cells for each query.
costO(n²) per query.
dies atn = 1000, q = 2·10⁵ → 2·10¹¹.
therefore2D prefix sums: O(n²) build, O(1) per query.
Diagram
Implementation

cin >> c reads one non-space character at a time, so the row strings need no parsing. f and ps are both (n+1)², and row and column 0 stay zero.
