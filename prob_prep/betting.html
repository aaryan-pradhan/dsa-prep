1 · Plain expected value

Fair price \(= \mathbb{E}[\text{payout}]\). Write the payout as a random variable, then use linearity and indicators.

Known urn (10B, 10W), $10 for the right colour

An urn holds 10 black and 10 white balls. You call a colour, then one ball is drawn at random; you win $10 if it has the colour you called.

Question: what is the fair price to play this game?

Key idea

\(P(\text{win}) = \tfrac12\) whichever colour you call.

Picture

Half the balls match whatever you call. So you win $10 half the time: the game is worth \(10 \times \tfrac12 = \$5\).

Solution

Setup. 10 black and 10 white balls; you call a colour and win $10 if the drawn ball has that colour.

  1. Whichever colour you call, \(P(\text{win}) = \tfrac{10}{20} = \tfrac12\).Why: 10 of the 20 equally likely balls match.
  2. \(\mathbb{E}[\text{payout}] = 10\cdot\tfrac12 = \) $5.Why: fair price = expected payout.

Conclusion. The fair price is $5. ∎

Secret urn, unknown mix

A friend fills an urn with 20 balls, black and white, in a mix you are not told (and the friend may try to trick you). You call a colour, then one ball is drawn at random; you win $10 if it matches.

Question: how should you play, and what fee is fair?

Key idea

Call your colour with a fair coin flip. Then \(P(\text{win}) = \tfrac12\) whatever the mix is.

Picture

If you always call black, the friend can simply put in no black balls. Any fixed call can be beaten.

Flip a coin to choose your call. Then you win half the time whatever the friend put in, because your call is a surprise to the friend too.

Solution

Setup. A friend fills the urn with an unknown fraction \(p\) of black balls. You call a colour and win $10 if the drawn ball matches.

  1. Call black or white by flipping a fair coin, independently of everything.Why: this is the strategy.
  2. \(P(\text{win}) = \tfrac12p + \tfrac12(1 - p) = \tfrac12\), for every \(p\).Why: call black (probability \(\tfrac12\)) and draw black (probability \(p\)), or call white and draw white.
  3. The fair fee is \(10\cdot\tfrac12 = \) $5, guaranteed whatever the friend chose.Why: step 2 doesn't depend on \(p\).

Conclusion. Randomising the call guarantees a $5 value. ∎

⚠ Course assumes \(p \sim U[0,1]\). Nothing justifies that: an adversarial friend could pick \(p = 0\) against a fixed call of “black”. Randomising the call (step 1) gives \(\tfrac12\) with no assumption.

$10 per red card before the first spade

A shuffled 52-card deck is turned over one card at a time until the first spade appears. You win $10 for every red card that appears before that first spade.

Question: what is the fair price of this game?

Picture

Clubs don't matter; throw them away. That leaves 26 reds and 13 spades in random order.

Look at one red card together with the 13 spades. It comes before all of them exactly when it is first among those 14 cards: probability \(\tfrac1{14}\).

Add over all 26 reds: \(26 \times \tfrac1{14} = \tfrac{13}{7}\) reds on average, worth \$10 each.

Solution

Form 1 (i → end) · Turn = the next card that is a red or a spade (clubs change nothing). Spade → ends. Red → +1, next turn with one red fewer.

  1. LEVEL. rec(r, s) = the expected number of red cards still to come before the first spade, given r reds and s spades left and no spade yet. The answer is rec(26, 13).Why: a club neither counts nor ends the game, and removing the clubs from a uniformly shuffled deck leaves the reds and spades in uniformly random order; so only the reds and spades matter.
  2. CHOICE. The next red-or-spade card is red with probability \(\tfrac{r}{r+s}\), a spade with \(\tfrac{s}{r+s}\).Why: uniform order of the remaining reds and spades.
  3. CHECK. Spade: ends, 0 more. Red: +1, continue at (r−1, s). Base case: r = 0 → 0.Why: the rules.
  4. MOVE. \(\text{rec}(r, s) = \tfrac{r}{r+s}\big(1 + \text{rec}(r{-}1, s)\big) + \tfrac{s}{r+s}\cdot 0\).Why: law of total expectation over the next card.
  5. SOLVE. Claim rec(r, s) = \(\tfrac{r}{s+1}\). r = 0: 0 ✓. If it holds for r−1: \(\tfrac{r}{r+s}\big(1 + \tfrac{r-1}{s+1}\big) = \tfrac{r}{r+s}\cdot\tfrac{s+1+r-1}{s+1} = \tfrac{r}{s+1}\) ✓. So rec(26, 13) = \(\tfrac{26}{14} = \tfrac{13}{7}\), and the fair fee is \(10\cdot\tfrac{13}{7} = \tfrac{130}{7} \approx\) $18.57.Why: induction on r; r only goes down, so there are no loops.
  6. CHECK THE ANSWER. Each of the 26 reds comes before all 13 spades with probability \(\tfrac1{14}\) (it is first among those 14 cards), and \(26\cdot\tfrac1{14} = \tfrac{13}{7}\) ✓.Why: linearity over indicators.

Answer. The fair fee is \(\tfrac{130}{7} \approx\) $18.57. ∎

2 · Present vs future

  1. At each decision: stop if (value now) \(\ge \mathbb{E}[\text{value of continuing optimally}]\); otherwise continue.
  2. With a fixed number of steps, work backwards from the last step.
  3. One-step look-ahead ("stop as soon as stopping beats exactly one more step") is optimal when the problem is monotone: once stopping is better, it stays better.

Dice game: up to 2 rolls, then up to 3

You roll a die. You may either keep the number (you are paid that many dollars and the game ends) or throw it away and roll again. The last roll you are allowed must be kept.

Question: what is the game worth with the best strategy (a) if you may roll at most 2 times; (b) if you may roll at most 3 times?

Picture

Work backwards from the last roll. With 1 roll left you must keep it: worth 3.5 on average.

With 2 rolls: keep the first roll only if it beats 3.5 (a 4, 5 or 6); otherwise reroll and expect 3.5. That game is worth 4.25.

With 3 rolls: keep only what beats 4.25 (a 5 or 6). Each extra roll raises the bar you keep at.

Solution

Form 1 (i → end) · Level = rolls left k. Keep → ends. Reroll → level k−1. One roll left → must keep (base case).

  1. LEVEL. rec(k) = the expected payout with k rolls left, playing optimally. The answers are rec(2) and rec(3).Why: only the number of rolls left matters.
  2. CHOICE. After seeing roll x: keep x, or throw it away and reroll.Why: the rules.
  3. CHECK. Keep: ends with x. k = 1: the roll must be kept, so rec(1) = 3.5 (base case).Why: the mean of one roll is \(\tfrac{1+2+3+4+5+6}{6} = 3.5\).
  4. MOVE. \(\text{rec}(k) = \tfrac16\sum_{x=1}^{6}\max\big(x,\ \text{rec}(k-1)\big)\).Why: for each x take the better option; then average over the 6 equally likely rolls.
  5. CODE. 
    double dp[4];                                   // all -1
double rec(ll k) {
    if (k == 1) return 3.5;                     // base case
    if (dp[k] != -1) return dp[k];              // cache check
    double ans = 0;
    for (ll x = 1; x <= 6; x++) ans += max((double)x, rec(k - 1)) / 6;
    return dp[k] = ans;                         // save and return
}   // rec(2), rec(3)
    Why: his fixed order.
  6. SOLVE.
    k = 2: keep x ≥ 4 (4 > 3.5), otherwise reroll. \(\text{rec}(2) = \tfrac16(3.5 + 3.5 + 3.5 + 4 + 5 + 6) = \tfrac{25.5}{6} = \) 4.25.
    k = 3: keep x ≥ 5 (5 > 4.25 > 4). \(\text{rec}(3) = \tfrac16(4\cdot4.25 + 5 + 6) = \tfrac{28}{6} = \) \(\tfrac{14}{3} \approx 4.67\).Why: the max replaces each low roll by the value of rerolling.

Answer. With 2 rolls the game is worth 4.25; with 3 rolls, \(\tfrac{14}{3}\). ∎

Push your luck with a d10

You roll a 10-sided die (faces 1–10) as often as you like. A roll of 1–9 adds that many dollars to your total. A roll of 10 wipes out your total and ends the game. After any roll you may stop and keep your total.

Question: at what total should you stop, to make your expected winnings as large as possible?

Picture

Compare stopping now with rolling exactly once more. From a total x, one more roll gives \(\tfrac9{10}(x + 5)\) on average: 9 times in 10 you add 5 on average, and 1 time in 10 you lose everything.

That beats x only while x < 45. The total only grows, so once past 45 it stays past 45: stop at 45.

Solution

Form 1 (i → end) · Level = your current total x. Stop → ends with x. Roll 10 → ends with 0. Roll 1–9 → level x + k.

  1. LEVEL. rec(x) = the best expected final amount when your total is x and you are deciding whether to roll. The question asks for which x you should stop.Why: only the current total matters.
  2. CHOICE. Stop, or roll once more.Why: the rules.
  3. CHECK. Stop: ends with x. Roll 10 (\(\tfrac1{10}\)): ends with 0. Roll k ∈ {1, …, 9} (\(\tfrac1{10}\) each): continue at x + k.Why: the rules.
  4. MOVE. \(\text{rec}(x) = \max\Big(x,\ \tfrac1{10}\cdot 0 + \sum_{k=1}^{9}\tfrac1{10}\,\text{rec}(x + k)\Big)\).Why: law of total expectation over the roll; then take the better option.
  5. BASE CASE (why rec(x) = x for x ≥ 45).
    Rolling exactly once more from x gives \(\tfrac9{10}(x + 5)\) on average.
    That is ≤ x exactly when \(0.9x + 4.5 \le x\), i.e. x ≥ 45.
    The total only goes up, so once x ≥ 45 it stays ≥ 45, and one more roll stays worse.
    For such monotone problems stopping is then optimal: rec(x) = x for x ≥ 45.Why: the one-step look-ahead rule is optimal for monotone problems (idea box of §2). The levels never end on their own, so this is the base case the recursion stands on.
  6. CODE. 
    double dp[45];                                  // all -1
double rec(ll x) {
    if (x >= 45) return x;                      // base case (see above)
    if (dp[x] != -1) return dp[x];              // cache check
    double roll = 0;                            // a 10 adds 0
    for (ll k = 1; k <= 9; k++) roll += rec(x + k) / 10;
    return dp[x] = max((double)x, roll);        // save and return
}   // rec(0) = 17.68...    cost: 45 states x 9 transitions
    Why: his fixed order.
  7. SOLVE. For x < 45 the max picks 'roll' (one more roll beats x there, and rec(x+k) ≥ x + k only helps). So: keep rolling while the total is below $45, stop at the first total ≥ 45 (at exactly 45 you are indifferent). Played this way, the game is worth rec(0) ≈ $17.68.Why: x < 45 means \(\tfrac9{10}(x+5) > x\), and rec(x + k) ≥ x + k.

Answer. Stop at the first total of $45 or more. ∎

⚠ Course compares with just one more roll but never says why that is enough. The BASE CASE step is the reason.

3 · Optimal parameters

Describe a family of strategies with a parameter \(\theta\) (a threshold, a fraction), compute \(\mathbb{E}(\theta)\) or \(P(\theta)\), then maximise. First argue that the optimum lies in that family.

Secretary problem, \(n = 6\)

6 candidates are interviewed one at a time, in random order. After each interview you must immediately hire or reject that candidate; a rejected candidate cannot be called back. You can rank everyone you have seen so far.

Question: which strategy gives the highest probability of hiring the best of the 6, and what is that probability?

Picture

Only a candidate who is the best so far can be the best overall.

Early on, a best-so-far is probably beaten later. Late on, you are running out of candidates. So skip the first few just to learn the level, then hire the first one who beats them all.

For 6 candidates, skipping 2 is best: success \(\tfrac{77}{180} \approx 0.43\).

Solution

Form 1 (i → end) · Level = the candidate i being deliberated on (1, …, i−1 already rejected). Candidate i best-so-far → hire (ends) or reject. Not best-so-far → reject (hiring can't win).

  1. LEVEL. rec(i) = the best probability of hiring the overall best, given candidates 1, …, i−1 were all rejected and we are now deliberating on candidate i. The answer is rec(1).Why: what matters for the future is only how many candidates are gone; see MOVE for why the past order doesn't matter.
  2. CHOICE. If candidate i is the best so far (better than all of 1, …, i−1): hire or reject. If not: reject.Why: a candidate who is not best so far cannot be the overall best.
  3. CHECK. Hiring a best-so-far candidate i ends the game and wins with probability \(\tfrac{i}{6}\). Rejecting moves on to candidate i+1. Base case: rec(7) = 0 (all 6 rejected, nobody left).Why: she is the overall best exactly when the best of all 6 is among the first i, which has probability \(\tfrac i6\).
  4. MOVE. \(\text{rec}(i) = \tfrac{1}{i}\max\Big(\tfrac{i}{6},\ \text{rec}(i{+}1)\Big) + \tfrac{i-1}{i}\,\text{rec}(i{+}1)\).
    Reading the max. Split on what candidate i turns out to be.
      Case 1: best so far (probability \(\tfrac1i\)). You have two options and you take the better one:
        hire now → you win if she is the overall best: \(\tfrac i6\);
        reject → you are now deliberating on candidate i+1: \(\text{rec}(i{+}1)\).
        Taking the better of the two is exactly \(\max\big(\tfrac i6,\ \text{rec}(i{+}1)\big)\).
      Case 2: not best so far (probability \(\tfrac{i-1}{i}\)). Hiring her can never win, so there is no choice: reject, and the value is \(\text{rec}(i{+}1)\).
    So the max is a decision (hire or wait), and it appears only in the case where a decision exists.
    ihire now: i/6wait: rec(i+1)max picks
    11/6 ≈ .16777/180 ≈ .428wait
    22/6 ≈ .33377/180 ≈ .428wait
    33/6 = .50047/120 ≈ .392hire
    44/6 ≈ .6673/10 = .300hire
    55/6 ≈ .8331/6 ≈ .167hire
    66/6 = 1rec(7) = 0hire
    Hiring gets better as i grows (i/6 goes up) while waiting gets worse (fewer candidates left). The two cross between i = 2 and i = 3, and that crossing is the "skip 2" rule.Why: candidate i is best so far with probability \(\tfrac1{i}\) (each of the first i is equally likely to be the best among them), and this is independent of the relative order of the earlier ones and of the later arrivals, so the future after rejecting is rec(i+1) either way.
  5. CODE. 
    double dp[8];                                   // all -1
double rec(ll i) {
    if (i == 7) return 0;                       // base case: nobody left
    if (dp[i] != -1) return dp[i];              // cache check
    double hire = i / 6.0, go_on = rec(i + 1);
    double ans = max(hire, go_on) / i + go_on * (i - 1) / i;
    return dp[i] = ans;                         // save and return
}   // rec(1)
    Why: his fixed order.
  6. SOLVE. From i = 7 down:
    rec(7) = 0.
    rec(6) = \(\tfrac16\max(1, 0) + \tfrac56\cdot0 = \tfrac16\).
    rec(5) = \(\tfrac15\max(\tfrac56, \tfrac16) + \tfrac45\cdot\tfrac16 = \tfrac16 + \tfrac{2}{15} = \tfrac3{10}\).
    rec(4) = \(\tfrac14\max(\tfrac46, \tfrac3{10}) + \tfrac34\cdot\tfrac3{10} = \tfrac16 + \tfrac{9}{40} = \tfrac{47}{120}\).
    rec(3) = \(\tfrac13\max(\tfrac36, \tfrac{47}{120}) + \tfrac23\cdot\tfrac{47}{120} = \tfrac16 + \tfrac{47}{180} = \tfrac{77}{180}\).
    rec(2) = \(\tfrac12\max(\tfrac26, \tfrac{77}{180}) + \tfrac12\cdot\tfrac{77}{180} = \tfrac{77}{180}\) (here \(\tfrac26 = \tfrac{60}{180} < \tfrac{77}{180}\), so reject).
    rec(1) = \(\tfrac11\max(\tfrac16, \tfrac{77}{180}) + 0 = \) \(\tfrac{77}{180} \approx 0.428\) (reject candidate 1).Why: the max picks 'hire' exactly when i/6 ≥ rec(i+1): true for i ≥ 3 (\(\tfrac36 \ge \tfrac{47}{120}\)), false for i ≤ 2. So: skip the first 2, then hire the first best-so-far.

Answer. Skip 2 candidates, then take the first best-so-far: success probability \(\tfrac{77}{180}\). (For large n: skip n/e, giving ≈ 1/e.) ∎

⚠ Course asserts the threshold form without justifying it; the max in MOVE is the justification. It also has a typo: “\(P(5) = \tfrac16 + \tfrac16 = \tfrac16\)”.

Paid redraws from 1..100

Each draw costs $1 and gives a random whole number from 1 to 100 (all equally likely, draws independent). After each draw you may stop and receive the last number drawn in dollars, or pay $1 to draw again.

Question: with the best strategy, what is your expected net gain (payout minus total cost)?

Picture

Every draw is a fresh start at the same price, so the game has one value V, the same before every draw.

Keep a draw exactly when it beats V. That gives one equation: \(V = -1 + \text{average of } \max(x, V)\). Its solution is V ≈ 86.36, so keep 87 or more.

Solution

Form 1 (i → end) · Turn = one paid draw. Stop → ends with the number drawn. Continue → next turn. MEMORYLESS turns it into one equation.

  1. LEVEL. rec(i) = the expected net gain from draw i onward (paying for draw i included), playing optimally. The answer is rec(1).Why: net = last number kept − number of draws paid for.
  2. CHOICE. Pay $1 and draw X (uniform on 1–100); then stop and keep X, or continue.Why: the rules.
  3. CHECK. Stop: ends with X. Continue: go to draw i+1.Why: the rules.
  4. MOVE. \(\text{rec}(i) = -1 + \tfrac1{100}\sum_{x=1}^{100}\max\big(x,\ \text{rec}(i{+}1)\big)\).Why: pay 1, then for each x take the better option; average over x.
  5. MEMORYLESS. Every draw is a fresh uniform number at the same cost, so rec(i+1) = rec(i) = V, and \(V = -1 + \tfrac1{100}\sum_{x=1}^{100}\max(x, V)\).Why: each turn is independent of earlier turns, has the same probabilities and the same rules, and nothing from earlier turns is carried forward.
  6. SOLVE.
    Guess V ∈ (86, 87]. Then max(x, V) = V for x ≤ 86 and = x for x ≥ 87, and \(\sum_{x=87}^{100}x = \tfrac{14\cdot187}{2} = 1309\).
    Solve: \[V = -1 + \tfrac{86V + 1309}{100} \;\Rightarrow\; 100V = -100 + 86V + 1309 \;\Rightarrow\; 14V = 1209 \;\Rightarrow\; V = \tfrac{1209}{14}\]so V ≈ $86.36.
    Check: 86.36 ∈ (86, 87] ✓.
    Rule: stop iff X ≥ V, i.e. X ≥ 87.Why: the right side minus V decreases as V grows (slope \(\tfrac{\#\{x \le V\}}{100} - 1 < 0\)), so the equation has only one solution, and the guessed interval checks out.

Answer. Stop at the first draw of 87 or more; the game is worth \(\tfrac{1209}{14} \approx\) $86.36. ∎

4 · Dynamic programming

State = everything that decides the future. \(V(\text{state}) = \max_{\text{action}} \mathbb{E}[\text{reward} + V(\text{next state})]\). Fill the table from the terminal states.

Guess the colour of each draw (3W, 3B)

A deck of 3 white and 3 black cards is shuffled. Before each card is turned over you guess its colour, and you win $1 for each correct guess. You see every card after guessing it.

Question: with the best strategy, what is your expected total?

Picture

Your guess doesn't change which card comes next. So each time, just guess the colour with more cards left.

Build a table of values from small decks up: each cell = (chance the majority guess is right) + the average of the two cells for the deck after this card.

Solution

Form 1 (i → end) · Level = cards left (w whites, b blacks). Guess, then the card is revealed: level (w−1, b) or (w, b−1).

  1. LEVEL. rec(w, b) = the expected number of correct guesses from here, with w whites and b blacks still in the deck. The answer is rec(3, 3).Why: only the remaining counts matter.
  2. CHOICE. Guess W or B. The next state doesn't depend on the guess (the card is drawn anyway), so guess the majority colour, right with probability \(\tfrac{\max(w,b)}{w+b}\).Why: your guess changes only this card's reward.
  3. CHECK. Base case: w = 0 or b = 0 → every remaining guess is right: w + b.Why: you know every remaining colour.
  4. MOVE. \(\text{rec}(w,b) = \dfrac{\max(w,b)}{w+b} + \dfrac{w}{w+b}\text{rec}(w{-}1,b) + \dfrac{b}{w+b}\text{rec}(w,b{-}1)\).Why: reward now, plus the expected future over which colour is drawn.
  5. CODE. 
    double dp[4][4];                                // all -1
double rec(ll w, ll b) {
    if (w == 0 || b == 0) return w + b;         // base case
    if (dp[w][b] != -1) return dp[w][b];        // cache check
    double n = w + b;
    double ans = max(w, b) / n + w / n * rec(w - 1, b) + b / n * rec(w, b - 1);
    return dp[w][b] = ans;                      // save and return
}   // rec(3, 3)    cost: 16 states x 2 transitions
    Why: his fixed order.
  6. SOLVE. Filled exactly (rows w, columns b):
    w \ b0123
    00123
    113/27/313/4
    227/317/618/5
    3313/418/541/10
    rec(3, 3) = \(\tfrac{41}{10} = 4.1\).Why: e.g. rec(1, 1) = ½ + ½·rec(0, 1) + ½·rec(1, 0) = ½ + ½ + ½ = \(\tfrac32\).

Answer. 4.1 correct guesses on average. ∎

+1 red, −1 black, quit any time (4R, 4B)

A deck of 4 red and 4 black cards is shuffled and turned over one card at a time. Each red card gives you \(+\$1\) and each black card \(-\$1\). You may stop at any moment and keep your current total.

Question: with the best strategy, what is your expected total?

Picture

At each moment compare two numbers: quit now and keep your total, or draw and get the average of the two next states.

Fill the table from the edges (only reds left, or only blacks left) inwards. The orange cells are where quitting is best.

Solution

Form 1 (i → end) · Level = cards left (b blacks, r reds); the total so far is b − r. Quit → ends. Draw → level (b−1, r) or (b, r−1).

  1. LEVEL. rec(b, r) = the best expected final total with b blacks and r reds left. The total so far is (4 − r) − (4 − b) = b − r. The answer is rec(4, 4).Why: the state fixes the total, so it is all the future needs.
  2. CHOICE. Quit (keep b − r) or draw.Why: the rules.
  3. CHECK. Base cases: b = 0 → only reds left; drawing them all ends at 0 > −r, so rec = 0. r = 0 → only blacks left; drawing only loses, so quit: rec = b.Why: compare the options directly.
  4. MOVE. \(\text{rec}(b,r) = \max\Big\{b - r,\ \dfrac{b}{b+r}\text{rec}(b{-}1,r) + \dfrac{r}{b+r}\text{rec}(b,r{-}1)\Big\}\).Why: a black comes with probability \(\tfrac{b}{b+r}\), a red with \(\tfrac{r}{b+r}\); take the better of quitting and drawing.
  5. CODE. 
    double dp[5][5];                                // all -1
double rec(ll b, ll r) {
    if (b == 0) return 0;                       // base case: only reds left
    if (r == 0) return b;                       // base case: only blacks left
    if (dp[b][r] != -1) return dp[b][r];        // cache check
    double n = b + r;
    double ans = max((double)(b - r), b / n * rec(b - 1, r) + r / n * rec(b, r - 1));
    return dp[b][r] = ans;                      // save and return
}   // rec(4, 4)    cost: 25 states x 2 transitions
    Why: his fixed order.
  6. SOLVE. Filled exactly (rows b, columns r):
    b \ r01234
    000000
    111/21/31/41/5
    2212/31/22/5
    3326/517/2023/35
    443247/351
    rec(4, 4) = 1.Why: e.g. rec(1, 1) = max(0, ½·rec(0, 1) + ½·rec(1, 0)) = max(0, ½·0 + ½·1) = ½.

Answer. With the best strategy the expected total is $1. ∎

5 · Lessons from the past

Symmetry, small cases and induction still work. For guessing games, choose the best answer separately for each observation: that maximises the total probability of being right.

Is \(X_1\) the min, the median or the max?

Three numbers are drawn independently and uniformly from \([0, 1]\). You are shown only the first one, \(X_1 = x\), and must guess whether it is the smallest, the middle or the largest of the three.

Question: with the best strategy, what is the probability that your guess is correct?

Key idea

Given \(x\): \(P(\text{min}) = (1-x)^2,\ P(\text{median}) = 2x(1-x),\ P(\text{max}) = x^2\). Pick the largest.

Picture

Seeing x, each other number is above x with probability 1 − x.

So P(min) = (1 − x)², P(max) = x², and P(median) = 2x(1 − x) (one above, one below, 2 orders).

Guess whichever is largest: min below ⅓, median in the middle, max above ⅔.

Solution

Setup. \(X_1, X_2, X_3\) are independent uniforms on \([0, 1]\). You see only \(X_1 = x\) and guess whether it is the min, the median or the max.

  1. Given \(x\): \(P(\text{min}) = (1 - x)^2\), \(P(\text{max}) = x^2\), \(P(\text{median}) = 2x(1 - x)\).Why: min means both others are above \(x\); max means both below; median means one below and one above (2 orders).
  2. \((1 - x)^2 \ge 2x(1 - x) \iff 1 - x \ge 2x \iff x \le \tfrac13\), and \(x^2 \ge 2x(1 - x) \iff x \ge 2(1 - x) \iff x \ge \tfrac23\).Why: divide by \(1 - x > 0\), resp. \(x > 0\).
  3. Rule: guess min if \(x \le \tfrac13\), median if \(\tfrac13 < x < \tfrac23\), max if \(x \ge \tfrac23\). It is optimal because it picks the most likely answer for every single \(x\).Why: total success probability = average over \(x\) of the chosen answer's probability.
  4. \(P = \displaystyle\int_0^{1/3}(1-x)^2dx + \int_{1/3}^{2/3}2x(1-x)\,dx + \int_{2/3}^{1}x^2dx\). The first and last are equal by symmetry, each \(\tfrac{1 - (2/3)^3}{3} = \tfrac{19}{81}\); the middle is \(\big[x^2 - \tfrac{2x^3}{3}\big]_{1/3}^{2/3} = \tfrac{20}{81} - \tfrac{7}{81} = \tfrac{13}{81}\).Why: integrate each piece.
  5. \(P = \tfrac{38}{81} + \tfrac{13}{81} = \tfrac{51}{81} = \) \(\tfrac{17}{27} \approx 0.63\).Why: add.

Conclusion. The best rule is right with probability \(\tfrac{17}{27}\). ∎

Alternate guessing a secret in 1..100

A secret number is chosen uniformly from 1 to 100. You and a friend take turns guessing it, you first. After each wrong guess both of you are told whether the secret is higher or lower. The first person to guess it correctly wins.

Question: with best play by both, what is the probability that you win?

Picture

Count secrets won instead of probabilities. Guess the k-th number of the range. You win that one secret.

If the secret is below, your friend becomes the guesser on the k − 1 numbers below and wins W(k − 1) of them; you get the rest. The same for the n − k numbers above.

So you win n − W(k − 1) − W(n − k) secrets. With W(n) = ⌈n/2⌉ that is n/2 for every k when n is even: going first is exactly fair.

Solution

Form 5 (game) + Form 4 (LR) · Level = the range l … r of secrets still possible (Form 4); only its size n matters. rec is about the player about to guess (Form 5).

  1. LEVEL. rec(n) = Wn = how many of the n still-possible secrets the player about to guess wins, playing best (so their win probability is Wn/n). The answer is W100/100.Why: after each wrong guess the possible secrets are a range l … r, uniformly likely; a range of size n plays the same whatever l is.
  2. CHOICE. Guess the k-th number of the range, k ∈ {1, …, n}.Why: any guess in the range.
  3. CHECK. Secret = k: ends, you win (1 secret). Base case: n = 0 → 0.Why: the rules.
  4. MOVE. Secret below k (k−1 of them): the opponent is now the player to guess on a range of k−1 and wins Wk−1 of those, so you win (k−1) − Wk−1. Above: (n−k) − Wn−k. So \(\text{rec}(n) = \max_k\big[1 + (k-1) - W_{k-1} + (n-k) - W_{n-k}\big] = \max_k\big[n - W_{k-1} - W_{n-k}\big]\).Why: the Form 5 move: what I win = what is left after the player who moves next takes their best.
  5. CODE. 
    ll dp[101];                                     // all -1
ll rec(ll n) {
    if (n == 0) return 0;                       // base case
    if (dp[n] != -1) return dp[n];              // cache check
    ll ans = 0;
    for (ll k = 1; k <= n; k++) ans = max(ans, n - rec(k - 1) - rec(n - k));
    return dp[n] = ans;                         // save and return
}   // rec(100) / 100    cost: 101 states x 100 transitions
    Why: his fixed order.
  6. SOLVE (pattern). Claim: Wn = ⌈n/2⌉.
    Strong induction. Write a = k−1, b = n−k, so a + b = n−1.
    n even: a + b is odd, so exactly one of a, b is odd, and ⌈a/2⌉ + ⌈b/2⌉ = \(\tfrac{a+b+1}{2} = \tfrac n2\) for every k. So Wn = n − \(\tfrac n2 = \tfrac n2\).
    n odd: a + b is even. Both even (e.g. k = 1): ceilings sum to \(\tfrac{n-1}{2}\), value \(\tfrac{n+1}{2}\). Both odd: value \(\tfrac{n-1}{2}\). The max is \(\tfrac{n+1}{2}\).Why: the ceiling adds ½ exactly to the odd ones; n = 0 gives 0 ✓. (DP-checked for n ≤ 100.)
  7. ANSWER. W100 = 50, so going first wins with probability \(\tfrac{50}{100} = \) \(\tfrac12\).Why: the pattern with n = 100.

Answer. Going first wins with probability exactly \(\tfrac12\). ∎

⚠ Course's induction ends with “a similar check yields \(\tfrac12\)”. Counting secrets won (Wn = n·pn) makes every case a one-line parity count.
