The DP template (Form → Level → Choice → Check → Move)

From Vivek Gupta's DP workshop. Every recursion, DP and "repeat until" solution in these ledgers is written in these steps, in this order.

  1. FORM: decide which of the five forms below the problem is. The form gives the picture and the first argument of rec.
  2. LEVEL (state design): rec(level, …) = the question asked, but only for what is left, given what has already happened. Put in the state exactly what the CHECK or the base case needs to know. The choice never goes in the state.
  3. CHOICE: every option at this level (with its probability, in probability problems).
  4. CHECK: is the option legal? Does it end the process, with a known value?
  5. MOVE: go to the smaller state and combine: or (is it possible?), + (count, or probability-weighted), max / min (best), not (games).
  6. MEMORYLESS (probability only, and only now): is the future from turn i+1 exactly the future from turn i? Yes → drop i. A fixed deadline → keep i.
  7. COST (TLE check): #states × (1 + #transitions) must fit the limit.
  8. CODE, always in this order: pruning → base case → cache check → transition → save and return.
T dp[..][..];                        // every entry -1 before the first call
T rec(level, state...) {
    if (state is invalid) return BAD;            // 1. pruning
    if (level == end) return BASE;               // 2. base case (written the form's way)
    if (dp[level][state] != -1) return dp[...];  // 3. cache check
    T ans = identity;                            // 4. transition: CHOICE -> CHECK -> MOVE
    for (each choice c)
        if (check(c)) ans = combine(ans, rec(next level, next state));
    return dp[level][state] = ans;               // 5. save and return
}
